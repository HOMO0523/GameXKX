# 卡牌 pill 与悬停文本：规则分析及样表 V1

状态：待用户审阅。本文只提出文案和显示规则，没有修改 tooltip、pill、字体、颜色或排版代码。样表用于确认表达方式，尚不是173张卡的完整文案表。

用户要求：后续 pill 和 tooltip 必须先列文本表，给用户看过再改。简述尽量短且清楚；攻击倍率允许百分比；能直接算出的护甲等效果显示数字；详述讨论展示百分比、计算系数和补正来源。已确认的卡牌运行时工作继续，本文不重新开放已冻结的卡牌数值。

## 推荐方案

| 方案 | 简述 | 详述 | 判断 |
|---|---|---|---|
| 混合显示（推荐） | 攻击保留倍率，其余显示已计算数值，保留必要条件 | 完整语义、计算来源、本次结果 | 同时方便出牌判断和理解成长 |
| 全部显示结果 | 攻击也只显示预计损血 | 计算式放在详述 | 对目标变化敏感，不容易看出攻击倍率 |
| 全部显示公式 | 护甲、治疗等也写完整换算 | 重复或扩展公式 | 简述容易过长，增加心算负担 |

推荐口径：简述回答“这张牌现在做什么”，详述解释“为什么是这个数”。

## 简述规则

1. 采用“目标＋动作＋结果”的短句。例如“获得344护甲”“全体友方各获得344护甲”。不能省略“各”，避免误读为全队分摊。
2. 攻击显示当前品质下的卡牌倍率，例如“造成120%攻击伤害”。不写“攻击力+120%”，后者表示属性增益。选中目标后的预计损血放在结果预览中。
3. 防御换算护甲、治疗、固定伤害、DOT生成等显示已经计算过的数字。DOT写点数，不写消耗性层数；虚弱、标记等仍用层，格挡/重放等按实际规则用次。
4. 必要的玩法条件不能省掉：无护甲时、低于30%生命、每2点蓄力、每回合最多3次、检索失败等。护甲翻倍、消耗护甲25%返还等若描述的是机制关系，可以保留倍率或百分比。
5. 通常用2—4行效果文字，复杂牌允许多一两行。靠短句和分块压缩，不靠省略号截掉条件、目标或奖励。
6. 卡牌计算出的产出与真正生效的增量不同时，补一个短实际值：如“治疗155（有效100）”“施加36流血（可加入10）”。群体各人的实际值不同，放到逐目标结果中，不把全队写成同一个有效治疗量。
7. 回复和溢出分别命名。满内力时“回复4内力，溢出获得24护甲”不表示当前内力真的增加4。详述列请求回复、实际回复和溢出；简述保留“溢出”关系。
8. 任务阵赏用单独的机制行说明，不并入普通牌面产出。只有本次出牌确实将完成任务、且预览已演算重放顺序时，才显示本次阵赏的确定数值。

## 详述规则

建议顺序：完整效果 → 当前计算 → 实际结果/限制 → 本牌涉及的机制说明。

| 类别 | 应说明的计算项 | 不应误加的项 |
|---|---|---|
| 普通攻击 | 基础攻击倍率、品质后的倍率；选择目标后展示当前攻击、防御、有效状态及等级差补正、护甲吸收 | 不能把百分比攻击等同于实际损血 |
| 防御产甲 | 出牌者当前防御、卡牌的护甲系数、品质；实际存在的额外产甲补正 | 不再额外乘DOT等级倍率；不改用受益者防御 |
| 内力溢出产甲 | 先付费、回复量、剩余容量、实际溢出、转甲倍率、品质和队伍等级倍率 | 不使用防御；不把内力点数叫作防御百分比 |
| 治疗/反转 | 治疗系数、该系数是否已含品质、药效、品质、等级倍率；有效治疗与过量 | 已含稀有品质的25不能再直接乘1.2 |
| DOT生成 | 基础系数、品质、等级倍率、生成量、已有量和上限、实际加入量 | 已经生成的DOT触发不再乘品质/等级，也不因触发扣除储量 |
| 复制/翻倍/返还 | 原有或消耗的确定护甲值、复制或返还比例、取整方式 | 已结算的护甲不再乘品质、等级或防御 |

“补正”必须有具体名字，例如“品质×1.2”“队伍等级倍率×5”“虚弱−20%”。只列本次实际参与的项，通常省去×1、+0。不能为凑完整公式，展示没有接入或没有生效的装备/天赋补正。

当前防御358已经包含角色等级和装备等属性来源时，产甲公式直接使用358；需要解释属性来源可另列“防御358的组成”，不能再把那一套装备/等级补正乘到护甲上。所有装备内力上限加成已被禁止，不能出现在内力计算中。

主护甲的费用档位与明确写出的副护甲系数必须分别解释。例如寒序的40%防御不会因为牌面1气而自动变成80%。

品质和取整沿用已确认的运行时规则。特别是“稀有已含品质”的系数保留其标注品质，到最终结果才取整，不先把25÷1.2取整为普通系数。

## Pill 用法建议

本文用〔名称〕表示 pill 文本，尚不确定视觉尺寸或新配色。

| 用途 | 示例 | 排列规则 |
|---|---|---|
| 机制分段 | 〔冲锋〕〔收招〕〔重箭〕〔编序〕〔阵赏〕〔药方〕 | 单独放在相应机制行前；先基础效果，再条件效果，再完成/回合奖励 |
| 状态或资源 | 〔护甲〕〔内力〕〔流血〕〔中毒〕〔灼烧〕〔蚀伤〕〔虚弱〕〔药效〕 | 只包名字，数值和单位紧邻它；不把整句塞入pill |
| 共享动作 | 〔毒爆〕〔冰爆〕 | 简述用短动作名，详述解释完整规则和本次计算 |
| 规则说明 | 同一状态的定义 | 详述末尾去重，每种只解释一次 |

不强行把每个名称缩成两字。当前工程同时出现“药方/方剂”等称谓，完整文本表需要明确最终用词后再统一；样表先用现有pill“药方”。“净化”也不能默认覆盖所有DOT：清心散清四类，归元术等只清其明确列出的三类，范围必须保留。

## 无法确定数字时

- 有出牌者但没选择敌人：出牌者护甲/治疗系数仍可计算；受不同目标防御、等级或DOT余量影响的结果显示范围，选中后给精确结果。
- 场外有已选角色：采用该角色当前面板和卡牌品质，明确按场外状态；不捏造战斗药效、护甲或任务进度。
- 纯图鉴没有角色上下文：保留系数/关系式，或在明确标注的基准下展示样例。绝不能假设防御0而显示“获得0护甲”。
- 未来的阵赏、重放或反应：无法确定的量保留关系式；只有真实演算本次完成过程后，才显示确定数值。

## 后续完整文本表与审批范围

逐职业/卡组整理，每张卡至少列：稳定ID、名称/品质/费用、目标与分支条件、pill文字及顺序、完整简述、完整详述、计算来源及样例、尚待确认项。复杂分支和不同品质费用另列行，不藏在备注里。

用户审阅具体批次后才应用该批次。批准这份显示规则不自动等于批准尚未列出的173张具体文案；雷走候选倍率也不会因通过文本格式而获批准。任何新pill名称及术语统一必须出现在表内。

实施时，显示值和战斗结算使用同一份数值来源，避免靠替换旧字符串推测结果；静态文案、战斗预览和实际日志必须一致。当前短说明会合并及截断字符串，后续应以语义分块控制长度，保留重要条件；视觉换行和pill对齐在文本批准后做真实PIE验收。
