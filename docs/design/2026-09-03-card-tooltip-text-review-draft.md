# 卡牌 pill 与悬停文本：规则分析及样表 V3

状态：待用户审阅。本文只提出文案和显示规则，没有修改 tooltip、pill、字体、颜色或排版代码。样表用于确认表达方式，尚不是173张卡的完整文案表。

用户要求：后续 pill 和 tooltip 必须先列文本表，给用户看过再改。攻击也必须按实际取值对象显示数字，不能只显示百分比。最新明确分工：卡牌详述写“角色攻击（100 × 120% = 120）”，只解释角色/卡牌自身的计算；目标防御、状态、护甲吸收和最终损血，由随后鼠标移到怪物时的目标tooltip负责。已确认的卡牌运行时工作继续，本文不重新开放已冻结的卡牌数值。

## 修正后的显示层次

V1中“攻击只保留倍率”的建议已撤回；V2把目标结算混入卡牌详述的内容也已撤回。卡牌tooltip与怪物tooltip分别承担自身计算和目标结算。

| 位置 | 显示内容 | 示例 |
|---|---|---|
| 卡面/简述 | 按实际出手对象及卡牌自身规则算出的伤害数字 | 造成120点攻击伤害 |
| 卡牌详述 | 取值对象、当前属性、卡牌系数/品质等自身计算 | 角色攻击（100 × 120% = 120） |
| 鼠标移到怪物后的tooltip | 该怪物的防御、相关状态、护甲吸收、最终损血 | 护甲吸收10，预计损血90 |

简述回答“这张牌现在做什么”，详述解释“取谁的属性、为什么是这个数”。没有选择敌人，不妨碍先计算已有出手对象提供的攻击伤害数字。

## 简述规则

1. 采用“目标＋动作＋结果”的短句。例如“获得344护甲”“全体友方各获得344护甲”。不能省略“各”，避免误读为全队分摊。
2. 攻击也显示伤害数字，例如“造成120点攻击伤害”。卡牌详述采用“角色攻击（100 × 120% = 120）”的短公式。按语义取实际攻击来源，不能一律取主角或牌持有者。对敌人的减防、状态、护甲和损血结算只放在怪物tooltip，不回填成卡牌详述的长计算账单。
3. 防御换算护甲、治疗、固定伤害、DOT生成等显示已经计算过的数字。DOT写点数，不写消耗性层数；虚弱、标记等仍用层，格挡/重放等按实际规则用次。
4. 必要的玩法条件不能省掉：无护甲时、低于30%生命、每2点蓄力、每回合最多3次、检索失败等。护甲翻倍、消耗护甲25%返还等若描述的是机制关系，可以保留倍率或百分比。
5. 通常用2—4行效果文字，复杂牌允许多一两行。靠短句和分块压缩，不靠省略号截掉条件、目标或奖励。
6. 卡牌显示其自身计算出的产出。目标相关的实际增量放到目标结果中：卡牌可写“治疗155”“施加36流血”，目标tooltip再说明有效治疗或实际可加入量。群体各人的实际值分别列出，不混入卡牌自身公式。本条为相同分工在治疗/DOT中的文案建议，具体样表仍需审阅。
7. 回复和溢出分别命名。满内力时“回复4内力，溢出获得24护甲”不表示当前内力真的增加4。详述列请求回复、实际回复和溢出；简述保留“溢出”关系。
8. 任务阵赏用单独的机制行说明，不并入普通牌面产出。只有本次出牌确实将完成任务、且预览已演算重放顺序时，才显示本次阵赏的确定数值。

## 属性取值对象

- 伤害来源与承伤目标分别记录。所选友方可能是实际攻击者，敌人则是承伤者，不能把“选对象”一概理解为选敌人。
- 自身攻击、攻击最高友方出手、指定友方出手等，分别取规则指定对象的实时属性。
- 每名友方各攻击一次时，卡牌逐人使用各自攻击值；群攻后的逐敌结算由怪物tooltip显示。
- 卡牌数值随实际取值对象及其属性变化刷新。鼠标换到不同怪物，不将其防御或护甲结算塞入卡牌详述；由怪物tooltip更新对应结果。

## 详述规则

卡牌详述顺序：完整效果 → 角色/卡牌自身计算 → 本牌涉及的条件及机制说明。具体目标的减免与落地结果不在此展开。

| 类别 | 应说明的计算项 | 不应误加的项 |
|---|---|---|
| 普通攻击 | 角色攻击（当前攻击 × 本牌倍率 = 伤害数字）；需要解释时注明本牌倍率如何包含品质或自身条件 | 不列目标防御、状态、等级差、护甲吸收和最终损血；不默认取主角攻击 |
| 防御产甲 | 出牌者当前防御、卡牌的护甲系数、品质；实际存在的额外产甲补正 | 不再额外乘DOT等级倍率；不改用受益者防御 |
| 内力溢出产甲 | 先付费、回复量、剩余容量、实际溢出、转甲倍率、品质和队伍等级倍率 | 不使用防御；不把内力点数叫作防御百分比 |
| 治疗/反转 | 治疗系数、该系数是否已含品质、药效、品质、等级倍率及算出的治疗量 | 已含稀有品质的25不能再直接乘1.2；具体对象的有效治疗留给目标结果 |
| DOT生成 | 基础系数、品质、等级倍率及生成量；全局上限作为规则说明 | 目标已有储量与本次实际加入量留给目标tooltip；触发不再次乘倍率或扣储量 |
| 复制/翻倍/返还 | 原有或消耗的确定护甲值、复制或返还比例、取整方式 | 已结算的护甲不再乘品质、等级或防御 |

卡牌自身计算的“补正”用具体名字，例如“品质×1.2”“队伍等级倍率×5”。通常省去×1、+0。虚弱/破绽等战斗结算修正、目标防御、等级差和护甲吸收由怪物tooltip解释，不再写入卡牌详述。不能为凑完整公式，展示没有接入或没有生效的补正。

卡牌本身明确的条件仍要写，例如“目标有标记时增强”；保留卡牌规则不等于在卡牌详述列出某只怪物完整的状态结算账单。

当前防御358已经包含角色等级和装备等属性来源时，产甲公式直接使用358；需要解释属性来源可另列“防御358的组成”，不能再把那一套装备/等级补正乘到护甲上。所有装备内力上限加成已被禁止，不能出现在内力计算中。

主护甲的费用档位与明确写出的副护甲系数必须分别解释。例如寒序的40%防御不会因为牌面1气而自动变成80%。

品质和取整沿用已确认的运行时规则。特别是“稀有已含品质”的系数保留其标注品质，到最终结果才取整，不先把25÷1.2取整为普通系数。

## Pill 用法建议

本文用〔名称〕表示 pill 文本，尚不确定视觉尺寸或新配色。

| 用途 | 示例 | 排列规则 |
|---|---|---|
| 机制分段 | 〔冲锋〕〔收招〕〔重箭〕〔编序〕〔阵赏〕〔药方〕 | 单独放在相应机制行前；先基础效果，再条件效果，再完成/回合奖励 |
| 状态或资源 | 〔护甲〕〔内力〕〔流血〕〔中毒〕〔灼烧〕〔蚀伤〕〔虚弱〕〔药效〕 | 只包名字，数值和单位紧邻它；不把整句塞入pill |
| 共享动作 | 〔毒爆〕〔冰爆〕 | 简述用短动作名，详述解释完整规则和本次计算 |
| 规则说明 | 同一状态的定义 | 详述末尾去重，每种只解释一次 |

不强行把每个名称缩成两字。当前工程同时出现“药方/方剂”等称谓，完整文本表需要明确最终用词后再统一；样表先用现有pill“药方”。“净化”也不能默认覆盖所有DOT：清心散清四类，归元术等只清其明确列出的三类，范围必须保留。

## 怪物tooltip负责的内容

鼠标移到具体怪物后，才显示该目标的防御、相关状态、等级差、护甲吸收和最终生命损失。例如卡牌攻击120，对同级防御20、护甲10且无其他补正的怪物：减防后100，护甲吸收10，预计损血90。这段只出现在怪物tooltip，不追加到卡牌详述。

类似地，卡牌“施加36流血”与目标当前90/100而实际只能加入10，建议分别放在卡牌与目标tooltip中；该延伸的具体文案随文本表审阅。

卡牌120与怪物预计损血90对应不同计算阶段，不能用两者直接相等作为验收条件。卡牌数字应匹配自身产出阶段，怪物tooltip应匹配实际对该目标的结算。

## 无法确定数字时

- 有实际出手对象但没选择敌人：攻击伤害也先显示数字，不退回百分比；护甲/治疗等按各自取值对象计算。目标相关的落地结果等鼠标移到怪物后由怪物tooltip显示。
- 场外有已选角色：采用该角色当前面板和卡牌品质，明确按场外状态；不捏造战斗药效、护甲或任务进度。
- 纯图鉴没有角色上下文：采用明确标注的角色/等级基准展示数字，并在详述说明基准及倍率；不能把基准值冒充当前角色数值，也不只留下攻击百分比。无可用基准的特殊取值对象应明确说明缺少对象，不能假设攻击或防御为0。
- 未来的阵赏、重放或反应：无法确定的量保留关系式；只有真实演算本次完成过程后，才显示确定数值。

## 后续完整文本表与审批范围

逐职业/卡组整理，每张卡至少列：稳定ID、名称/品质/费用、属性取值对象、目标规则与分支条件、pill文字及顺序、完整简述、卡牌自身计算详述、独立的目标tooltip结果样例、尚待确认项。两种tooltip分列，复杂分支和不同品质费用另列行，不藏在备注里。

用户审阅具体批次后才应用该批次。批准这份显示规则不自动等于批准尚未列出的173张具体文案；雷走候选倍率也不会因通过文本格式而获批准。任何新pill名称及术语统一必须出现在表内。

实施时，显示值和战斗结算使用同一份数值来源，避免靠替换旧字符串推测结果；静态文案、战斗预览和实际日志必须一致。当前短说明会合并及截断字符串，后续应以语义分块控制长度，保留重要条件；视觉换行和pill对齐在文本批准后做真实PIE验收。
