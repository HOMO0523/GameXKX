# 专题七：UI、背包模板、新页面边界与短 Tooltip

## 1. 总原则

当前确认的 UI 布局保持不变。任何玩法实施不得顺带移动主菜单、城镇壳、路线节点、战斗血条、状态图标、手牌、气力、内力、敌方意图、背包分栏或已经校准的角色区域。允许的工作分为三类：

1. 在现有控件内更正数据、短文案、禁用态、目标高亮和错误反馈。
2. 复用现有背包视觉模板构建经用户批准的新页面。
3. 新增页签、独立界面、HUD 面板或交互层前，先提交页面清单、入口、信息结构和线框说明，由用户逐项确认。

天赋系统和称号系统尚未批准具体页面、页签、字段和数值；本规划不替用户决定。两者状态均为“待单独评审”。

## 2. 现有页面与职责

| 页面/区域 | 主要职责 | 可调整范围 | 状态 |
|---|---|---|---|
| 主菜单 | 新游戏、继续、读取/删除存档、设置与退出 | 数据接线、禁用态、错误提示；不改确认布局 | 已实现 |
| 城镇 HUD | 任务提示、NPC 交互、进入路线、打开背包/商店 | 入口接线和短提示；不重排 | 已实现 |
| 路线图 | 三章节点、当前位置、节点可达状态、资源 | 节点数据、提示和状态；不改变现有地图结构 | 已实现 |
| 战斗 HUD | 单位、血条、状态、意图、手牌、资源、结束回合 | 规则同步、短 Tooltip、目标高亮；不移动区域 | 已实现 |
| 背包/角色界面 | 角色、装备六槽、装备仓库、卡牌配置 | 数据模型从旧伙伴解锁迁移到出生六牌；沿用模板 | 部分实现 |
| 商店 | 永久包、路线商品、价格、库存和购买结果 | 更新经济与概率；不静默添加新页面 | 部分实现 |
| 战斗结算 | 胜负、奖励、路线返回 | 同死玩家胜利与奖励事务 | 已实现 |

## 3. 背包模板与队伍配置

背包模板继续作为局外复杂系统的视觉基准：左侧/上层为分类与角色选择，中部为当前对象详情，右侧/下层为库存或候选列表；卡框、边距、滚动、Tooltip 和按钮样式沿用现有语言。

队伍卡牌配置必须清楚分为三个角色，不把 16 张混成一个候选池：

| 角色 | 选择显示 | 候选显示 |
|---|---:|---|
| 主角 | 8 个已选槽 | 36 张中当前已解锁/可用的牌 |
| 永久伙伴 | 5 个已选槽 | 该伙伴出生固定 6 张 |
| 任务 NPC | 3 个已选槽 | 本次路线确定的 4 选 3 结果；未携带第四张不显示为可检索牌 |

普通伙伴升级后不出现新卡解锁。旧模板若存在“12 张伙伴池、等级锁定牌”区域，应保持整体版式，改为显示出生六牌、五个选择槽和出生流派说明；不能保留虚假的锁图标。阵师显示两张出生换场牌和四张出生收益牌，不展示其余四张换场为待解锁。

卡牌详情至少显示当前费用、固定目标模式、来源角色、基础效果、关键词效果、是否消耗和实现所需的状态短 Tooltip。代码签名和内部枚举只出现在开发诊断，不出现在玩家界面。

## 4. 战斗 HUD 边界

### 4.1 不移动的区域

- 我方与敌方角色位置、血条和护甲表现。
- 血条下方状态小图标行。
- 手牌扇形/横排、气力、内力和结束回合按钮。
- 敌方意图图标及其悬停区域。
- 已确认的战斗背景层级与角色前后关系。

新机制首先复用状态小图标、卡牌关键词行、战斗日志和既有高亮。只有这些载体无法表达且用户批准后，才可增加新进度条或任务面板。

### 4.2 目标反馈

手牌应显示随当前预览更新的短目标标签：`指友 / 指敌 / 全友 / 全敌 / 自身 / 任一`。阵师地势分支不能在鼠标按下后才改变目标模式；目标模式在六地势保持固定。合法单位使用既有高亮，非法单位不响应确认。

失败反馈必须区分：

- 气力不足；
- 内力不足；
- 没有合法目标；
- 必须先完成洞察/弃牌等待选择；
- 卡牌条件仅影响增强段，基础效果仍可用。

规则拒绝后牌与资源原样保留。不能用一个“无法使用”掩盖全部原因。

### 4.3 自动效果反馈

重放、毒爆、流血触发、灼烧触发、反击、格挡、法术任务回放和套装触发依序显示简短来源标签。自动效果不弹出新的目标选择；原目标失效时按规则自动改选或跳过。任务进度若要新增常驻 HUD，状态为“待单独评审”；在获得批准前可使用卡牌角标和战斗日志，不新增面板。

## 5. Task11 卡牌与状态 Tooltip：已实现

Task11 已把局内卡牌关键词和血条下状态 Tooltip 改为短而准确的现行文案。修改范围只包含文本构造、玩家可见名称映射、悬停内容和缺失图标映射；既有 slot、anchor、size、排序、血条、手牌、资源、意图与页面区块全部保留，未改变用户已确认的 UI 布局。

状态 Tooltip 的固定结构是 `状态名称\n层数：真实整数\n一句规则`。图标层数超过 99 时只在图标上写 `99+`，Tooltip 仍保留真实整数；文本不再使用 `效果：`、`时机：` 前缀。当前术语统一为“灼烧、药效、灵动、破绽”，反击与格挡分别显示，剑意不创建状态图标。完整精确状态文本见专题二第 8 节。

卡牌关键词精确文本已锁定为：

- 冲锋：本回合第一张主动牌时触发。
- 收招：作为结束回合前最后一张主动牌时触发。
- 重箭：消耗全部蓄力，逐层触发本牌重箭效果。
- 药效：下一次治疗或治疗反转每层＋1；结算时全部消耗。
- 反击：敌方单体攻击牌结算后，造成100%攻击并消耗1次。
- 格挡：敌方单体攻击牌结算后，造成100%攻击＋当前护甲并消耗1次。
- 当前地势收益：按当前地势触发对应效果。
- 法术任务：主角8张装备牌各主动打出一次后，依序重放基础效果并触发首牌奖励。

精确测试证据：`Saved/Automation/Task11_StatusTooltips_GREEN_20260811/index.json` 中 `GameXXK.UI.Battle.StatusTooltips` 为 1/1 Success、0 error、0 warning；`Saved/Automation/Task11_CardText_GREEN_20260811/index.json` 中 `GameXXK.Integration.CardText` 为 1/1 Success、0 error、0 warning。对应实现提交为 `aba2a2e`。因此当前卡牌/状态 Tooltip 状态为“已实现”，不是待评审或待落地；以后若再次改文案，需要同步更新精确断言，但仍不得顺带改布局。

## 6. 天赋系统：讨论边界

天赋系统当前只有“尚未开放、沿用背包视觉模板”的方向，未批准以下内容：

- 是独立页面、背包页签还是角色子页；
- 面向主角、所有角色或全账号；
- 树状、网格、分支或线性解锁结构；
- 使用何种货币、是否可重置、存档作用域；
- 每个天赋的数值、互斥和战斗接入点；
- 是否在战斗 HUD 显示新的触发反馈。

因此本规划不创建具体天赋节点或数值。评审时应一次展示两至三个不改变背包整体布局的入口方案，并附信息层级、返回路径、控制器/鼠标操作和存档字段影响；用户选定后才进入页面和数据规格。状态为“待单独评审”。

## 7. 称号系统：讨论边界

称号系统同样只确定复用背包视觉语言，未批准：

- 称号是纯展示还是带属性/规则效果；
- 单角色装备还是账号级展示；
- 获得条件、稀有度、排序、筛选和隐藏条件；
- 在城镇、战斗、存档选择或角色详情何处展示；
- 是否与成就、任务或路线结算绑定。

评审必须先确定“纯展示 / 轻量加成 / 构筑组件”三种产品定位之一，因为它直接改变存档和战斗平衡。未确认前不创建假页签、不写数值、不占用战斗 HUD。状态为“待单独评审”。

## 8. 页面新增决策门

任何新页面方案至少提交以下信息，用户确认后方可实施：

| 项目 | 必须说明 |
|---|---|
| 页面目的 | 玩家在此完成的单一主任务 |
| 入口/退出 | 从哪个现有按钮进入，返回到哪里 |
| 信息结构 | 页签、列表、详情、确认区的层级 |
| 模板复用 | 复用背包哪些区域、卡框和交互 |
| 数据状态 | 空态、锁定态、错误态、容量态 |
| 操作方式 | 鼠标、键盘、手柄焦点和返回 |
| 存档影响 | 永久/路线/战斗哪个作用域，版本迁移 |
| 战斗影响 | 是否改变数值、生成卡或增加 HUD |
| 验收截图 | 设计分辨率与至少一种缩放分辨率 |

这道决策门适用于天赋、称号、法术任务常驻面板、藏式独立区和任何新增页签。

## 9. 可访问性与一致性

- 颜色不作为状态或地势的唯一编码；同时用名称、图标轮廓和短标签。
- Tooltip 不超出安全区；长 CardId 只在开发模式出现。
- 禁用按钮说明原因，而不是只变灰。
- 关键数字使用统一单位和舍入；百分比写 `%`，层数写整数。
- 状态增减、护甲吸收、治疗和反向治疗使用不同颜色与浮字前缀，但保持低饱和整体美术。
- 控制器焦点顺序与视觉顺序一致；弹出待选择时锁定背后手牌并保留明确返回/取消规则。

## 10. UI 验收清单

1. 现有主菜单、城镇、路线、战斗和背包布局的截图基线无非授权位移。
2. 主角 8、伙伴 5、NPC 3 在 UI 上来源清楚，伙伴只显示出生六牌。
3. 198 张当前卡至少能显示名称、费用、目标和完整短卡文；目标重做后同步更新。
4. 阵师所有地势下预览、目标高亮和结算一致，基础效果不会卡手。
5. Task11 状态短 Tooltip 与卡牌关键词已通过精确自动化；文本不遮挡血条或意图，既有 UI 布局无位移。
6. 天赋与称号在页面方案未确认前保持未开放入口，不出现臆造数值或假可用控件。
7. 新页面若获批准，使用背包模板并通过键鼠/手柄、不同分辨率和存档恢复验证。
