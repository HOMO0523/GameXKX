# 专题九：存档、确定性、迁移与兼容

## 1. 存档产品规则

项目提供 5 个手动存档槽：

- 新游戏始终创建新的游戏状态，不自动读取旧槽。
- 继续/读取必须指向玩家选择的具体槽，不猜测“最近看过”的 UI 项。
- 删除只删除明确选择的槽，先二次确认，不影响其他槽。
- 接任务、进入路线、购买或普通交互不隐式覆盖手动存档；玩家明确保存后才写槽。
- 当前城镇任务路径在 F 接任务后激活叙事跟随者；玩家明确手动保存后恢复任务接受、`bFollowerJoined=true`、玩家位置与任务 NPC 位置。

更早设计中“按 F 接任务即自动保存”的行为被现行手动保存规则取代。路线和战斗可以维护崩溃恢复快照，但它不能伪装成玩家的永久手动存档，也不能覆盖其他槽。

`AcceptTownQuest` 先把 follower 状态设为真；任务 NPC 的交互路径随后执行 `ActivateFollower` 并记录 NPC 当前世界位置。F 接任务本身不自动保存，只有玩家明确保存时才把任务、跟随状态、玩家与 NPC 位置写入选定槽。现行代码、v15迁移与 MVP 验收之间没有遗留规范冲突。

## 2. 数据分层

### 2.1 永久状态

| 范围 | 关键数据 |
|---|---|
| 身份与进度 | 存档版本、玩家/角色稳定 ID、主角等级、章节/任务进度 |
| 城镇/NPC | 任务接受、`bFollowerJoined`、玩家位置、任务 NPC 位置；v15跟随迁移与缺失位置回填 |
| 主角卡 | 36 张目录版本、泛用解锁位、当前主角 8 张配置 |
| 永久伙伴 | 伙伴实例、职业、出生种子、终身固定 6 张、当前 5 张配置 |
| 装备 | 实例、模板、品质、强化、词缀、装备者、材料、容量 |
| 永久经济 | 永久金币、商店已购买项和可重复购买计数 |
| 设置 | 非玩法显示/音频/控制设置，和玩法存档分区 |

### 2.2 路线状态

路线种子、章节、节点图、当前位置、可达节点、敌人等级快照、路线金币、运行牌组与品质、遗物、事件、商店库存/刷新、任务 NPC 4 选 3 结果、战斗前生命与资源。

进入战斗时，任务 NPC 投影由其自身模板按当前玩家等级取得的 NPC 属性构建，不继承玩家装备、词缀或套装。存档保存 NPC 身份与 4 选 3 结果即可；不得把玩家装备快照复制为 NPC 属性来源。

### 2.3 战斗恢复状态

单位属性与稳定 ID、回合/阶段、手牌/抽牌/弃牌/消耗区及牌实例、当前气力和内力、护甲、全部状态、守护链接、反击/格挡来源、Battle Modifiers、药方监听、套装回合次数、法术任务、刀客首牌/末牌/藏式、重放和反应队列、敌方意图与蓄力字段、待选择交互、随机流位置和已经锁定的胜负。

临时牌需要保存来源、到期和不可复制标记；恢复后不能因重新生成实例而绕过到期。自动队列若在安全点存档，应要么完整序列化，要么只允许在队列清空的事务边界保存。

## 3. 稳定 ID 与目录版本

- CardId、EnemyId、EquipmentTemplateId、AffixId、SetBonusId、RelicId、EventId、CharacterId 和节点 ID 均使用稳定标识。
- 显示名、本地化文本和数组索引不得作为存档主键。
- 静态目录各自带版本；存档记录写入时版本和迁移后的规范 ID。
- 读取未知 ID 时跳过该实例并写可定位诊断，不能崩溃，也不能用数组第 0 项替代。
- 迁移必须幂等：同一存档被加载多次只迁移一次，保存后写新版本。

## 4. 已知迁移

### 4.1 主角 36 张

主角从旧泛用池扩展为 36 张后，存档保留已拥有合法 CardId，并按主角等级补齐 8 张初始泛用及 5/10/15/20 的四个解锁位；职业关联 24 张按新规则直接可选。当前迁移和测试状态为“已实现”。

### 4.2 刀客 CardId

新刀客藏锋牌替代四张旧随机池牌：

| 旧 CardId | 新 CardId |
|---|---|
| `Profession.Blade.YiShangHuanShi` | `Profession.Blade.JingHongChuQiao` |
| `Profession.Blade.DaoYiShouShu` | `Profession.Blade.HengYunKaiFeng` |
| `Profession.Blade.XiaoJiaLianJi` | `Profession.Blade.LianXiGuiQiao` |
| `Profession.Blade.CanYueSanDie` | `Profession.Blade.BaoDaoShouYe` |

旧 ID 读取时映射到新 ID；新伙伴生成、奖励和检索只使用新 ID。永久伙伴、待招募候选和相关引用均已覆盖，刀客旧ID迁移专项1/1通过，状态为“已实现”。

### 4.3 药效与旧 Medicine

早期某存档版本的 `Medicine` 表示已废弃的旧药材资源，该版本读取时迁移为 `NextHealingBonus × 6`。新版本重新使用 `Medicine` 枚举表示现行药效：下一次治疗/反向治疗每层 +1并全部耗尽。因此转换必须受存档版本门控；不能把新存档的药效再次转成疗愈增幅。当前版本门控转换状态为“已实现”。

### 4.4 反击与格挡

旧存档只有一个无法区分来源的反应层数时，不能一律迁成反击或格挡。迁移应根据授予卡 CardId、来源职业与旧反应记录恢复：刀客来源为反击，守卫护甲来源为格挡；无法判定的战斗中临时旧记录安全丢弃并写诊断，比产生错误高伤更安全。规范和双枚举已实现；旧战斗快照兼容状态为“部分实现”。

### 4.5 Speed

旧装备和角色存档中的 Speed 保留可读，维持角色排序、敌方意图和结构兼容；追风套已不再使用 Speed。`Affix.Universal.Speed` 已从 `GetUniversalDefinitions()` 新生成/重铸池移除，但仍存在于 `GetAllDefinitions()` 并可由 `FindDefinition()` 解析，使旧实例安全读取。旧 Speed 词缀可以支付固定 1 重铸砂迁出，新候选不会再次生成 Speed；目录、10,000 次生成与旧实例付费替换均已通过，状态“已实现”。

### 4.6 任务跟随契约 v15

v15 将 v14 及更早存档中“`QuestState=Accepted` 但 `bFollowerJoined=false`”规范化为 follower=true。旧档若已有 NPC 位置则原样恢复；若缺少位置，关卡按 Accepted+follower 恢复任务 NPC 后调用 `ActivateFollower`，该入口把 NPC 当前实际位置写回运行状态，供下一次手动保存持久化。迁移本身不伪造坐标，也不自动写玩家手动槽。

## 5. 伙伴出生池 v13 迁移

旧永久伙伴的 6/12 张合法同职业候选池已采用确定性迁移，不再保留三选一未决方案：

1. 用原伙伴职业与不可变 `CardSeed` 运行当前出生算法，重建精确六张出生池。
2. 旧配置中仍位于新出生池的牌按原顺序保留；再按新出生池顺序补足到5张。
3. `PersonalCardIds` 与 `UnlockedPersonalCardIds` 都写为同一六张；等级、星级与身份不改变，升级后不增牌或重抽。
4. 永久 roster 与待招募候选使用同一迁移；写入当前存档版本后再次加载不重复改写。

当前 roster、待招募候选、六职业覆盖共3/3新鲜测试通过，状态为“已实现”。玄甲/山河精确套装规则若未来获批并改变已有描述符，再按批准规则增加独立版本迁移；伙伴包重复处理仍是商店产品规则，不在通用读取器中猜测。

## 6. 随机确定性

至少分离以下随机流，避免一次 UI 预览改变战斗结果：

- 永久伙伴出生；
- 任务 NPC 4 选 3；
- 路线图与节点内容；
- 商店库存与重铸；
- 战斗抽牌/洗牌；
- 随机目标与灵动完美闪避；
- 敌人意图选择。

每个流保存种子和当前位置。预览、Tooltip、排序与 UI 重建不得消费玩法随机数。相同存档、相同输入序列必须得到相同出生六牌、NPC 三牌、路线、战斗随机目标和闪避结果。

## 7. 原子事务

| 事务 | 成功时同时发生 | 失败时 |
|---|---|---|
| 出牌 | 目标/资源验证、扣费、移牌、效果与首打标记 | 不扣费、不移牌、不改变计数 |
| 购买 | 验库存和货币、扣款、发货、售罄/刷新状态 | 全部不变 |
| 强化 | 验实例/等级/材料、扣材料、写等级和历史投入 | 全部不变 |
| 重铸 | 验词缀槽与至少 1 砂、固定扣 1 砂、写新词缀和随机位置；不分品质 | 全部不变 |
| 分解 | 验实例未装备/未锁、删除实例、固定返 1 重铸砂 + 1 强化石 + 10 金币 | 全部不变 |
| 存档 | 写临时文件、校验版本/哈希、原子替换目标槽 | 原槽保持可读 |

磁盘写入中断时优先保留上一份完整槽；临时文件在下次启动可清理，但不能当成玩家可选槽显示。

## 8. 保存和加载验收

1. 五槽分别新建、覆盖、读取和删除，不串槽。
2. 新游戏不读取旧槽；继续准确读取所选槽。
3. 接任务后不保存直接退出不会伪持久；手动保存后任务接受、follower=true、玩家与任务 NPC 位置均恢复。
4. 路线节点、商店库存、NPC 4 选 3、敌人编队与首意图读档不重抽。
5. 战斗中手牌、牌区、状态、护甲、反应来源、任务、药方和随机位置一致。
6. 旧刀客 ID、旧 Medicine、主角 36 扩展按版本迁移且幂等。
7. 新药效不会被旧 Medicine 迁移器误转换。
8. 未知或被删除的目录 ID 安全跳过并留下诊断；其余数据继续加载。
9. 伙伴旧 6/12 张池按稳定种子迁移到六牌；保留仍有效的旧配置并确定性补足5张，往返加载不重复改写。
10. 存档写入故障、磁盘空间不足或校验失败时旧槽仍可读。
11. 任务 NPC 战斗投影只读取 NPC 自身等级属性，不继承玩家装备；独立投影测试 1/1 Success、0 warning、0 error。
12. 新生成/重铸不产出 Speed，旧 Speed 实例仍可解析并可付费迁出；整套装备回归 55/55 Success、0 warning、0 error。
13. v14 Accepted/false follower 迁移到 v15 后 follower=true；缺失 NPC 位置在恢复跟随时回填，专项1/1 Success、0 warning、0 error。
14. 新游戏、进入城镇、接任务和路线结算不自动覆盖手动槽；现代根界面的保存/读取/删除隔离1/1 Success、0 warning、0 error。
