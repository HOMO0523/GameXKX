# 新增桌面界面审美与可读性复核

状态：已依据实机截图定位问题；修正后的截图仍需复核。不能以资源路径相同或编译通过代替视觉验收。

## 统一参照

参照现有背包、编队、工具页，而非局内战斗按钮：宣纸底、细墨线纸框、江湖体短标题、留白、物品/角色立绘。普通页签、选择行及底部操作使用背包的 `004_tab_2` / 普通页签样式。局内大面积青绿墨迹按钮不能直接用于整个桌面菜单体系。

「任务」「教程」仅原位替换原来的「剧情任务」「进入城镇」两个圆钮。两页复用左侧仓库区域；商店使用中央背包区域。

## 逐页结论

| 界面 | 已发现的问题 | 修改标准 |
|---|---|---|
| 商店 | 初稿缺少纸底与关闭；改稿中九宫格切片放大了卡框墨边；标题、价格压在可见边缘；底部贴纸边 | 补齐背包纸面与关闭；卡框整体缩放保留笔触粗细；标题、图、价格分区；卡面内容以可见边缘为准留内边距；底部购买栏上移 |
| 商品卡 | 文字占比过高，后来虽然加入图，文字依然侵占边框 | 短名称、装备/宝石/宝箱图、金币图标与价格；取消反复书写“金币”；代表图不冒充购买结果 |
| 获得物品 | 标题与品质压框；无法悬停查看实际装备；重复名称无法区分不同词缀 | 展示实际生成的每件物品，复用同一安全边距；接入背包的装备详情格式器；保留明确“确定”返回 |
| 教程列表 | 大面积墨迹选中条不符合背包；头像偏小；姓名自动换行，甚至出现“弓”单字被截 | 使用背包纸框选择行；头像独立定宽并保持比例；文字列填充剩余宽度、名称单行；行高统一 |
| 教程详情 | 原来说明、进度和首通奖励挤成一段；奖励不突出 | 角色图＋短课题，进度独立；金币图标＋100000为明确视觉重点；“首通/已领取”分离；底部按钮保留安全边距 |
| 任务页 | 当前无正式任务数据 | 与教程共享纸面和页签样式，显示简洁空状态；不虚构任务或奖励 |
| 战斗教程提示 | 旧稿灰按钮、整块深底与文字拥挤；遮到原有按钮 | 使用项目纸底与字体，增加正文宽度与按钮间距；当前目标独立清晰；复核是否遮挡敌人意图和角色关键区域 |

## 信息层级

- 商店：商品图与名称 → 金币价格 → 数量及总价 → 购买。
- 获得物品：实际物品 → 悬停属性 → 确定。不要把完整属性常驻铺满页面。
- 教程：角色/课程选择 → 当前短目标 → 首通金币 → 开始/继续。
- 金币只保留必要数字和图标；描述不重复解释按钮本身能表达的操作。

## 购买规则同步

每次1～10件，整批生成、验证、保存后提交；失败不能部分扣款或发放。套装包随机一件对应套装装备，宝石包一颗。商店装备按购买时工具等级生成；工具未解锁为1级。商店宝箱使用同样的装备等级快照，普通游历掉落规则不改。

## 验收门槛

1. 100%和50%实机截图均没有压框、出纸面、姓名断行、拉伸立绘。
2. 比较背包与新界面时，页签和底部按钮属于同一套控件样式。
3. 单件及10件展示均保持整齐；数量上限清楚，总价正确。
4. 获得装备悬停显示实际等级、品质、属性与词缀；不只显示商品包描述。
5. 教程开始、退出和返回恢复正确；图形化不能掩盖未实现的机制。

当前验证记录见 `docs/production/2026-09-08-academy-shop-implementation.md`。已通过的规则测试不能视为上述视觉门槛已通过。
