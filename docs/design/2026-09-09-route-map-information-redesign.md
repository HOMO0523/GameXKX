# 路线地图信息与图例重整

## 现状判断

| 旧信息 | 当前运行事实 | 地图上的处理 |
|---|---|---|
| 行旅钱 | 修改前为本局虚拟计数，行商却使用局外金币 | 保留显示，改为背包与仓库的实物余额；所有局内消费只扣此物品 |
| 路线进度 x/17 | 分母是整张图的候选节点，包括不能同时走到的分支 | 改为已完成层级/总层级的“行程”；只看已访问层，不把当前候选节点算完成 |
| 首领卡槽 0/3 | 数据与卡组仍有兼容逻辑，但训练首领战后直接结算，地图没有管理入口 | 从地图移除，不改背包、卡组、奖励或存档规则 |
| 黑灰矩形与系统文字 | 与已经替换的浅纸、淡墨山水和彩墨图标不一致 | 与地图统一浅纸底、墨色文字和明确字号层级 |

修改前代码依据：`GameXXKRouteMerchantRules.cpp` 的预览/购买/刷新均读写 `PlayerGold`；旧结算折算虚拟余额。新规则统一用 `GameXXKTravelMoneyRules` 消耗实物；旧余额仅保留兼容结算，不转换成高价值实物。`GameXXKTrainingRules.cpp` 在起点已访问时就把 `CurrentRouteNodeId` 指向下一候选节点，因此进度不能直接使用当前节点层级。

## 值得常驻的信息

关卡名称与难度确认、实际可消费的行旅钱、路线行程，以及解释节点含义的固定图例。遗物详情与结算收益适合在相应页面按需查看；旧卡槽容量、背包计数、经验、日志不占地图常驻区域。若以后展示队伍气血，需要投影三人的真实续存状态，不能将旧 `PlayerHP` 当作全队资源。

## 本轮实施

1. 左上改成固定墨字信息：现有关卡名、行旅钱、行程层级。保留旧诊断字段供兼容读取，界面移除首领卡槽。
2. 右侧固定图例按实际字体自动行高，复用当前八类节点映射，随地图滚动保持位置。介绍按真实规则编写：篝火给保命护符；宝匣为遗物三选一；行商强化卡牌、购买遗物；奇遇包含属性机缘与主线见闻。附墨圈与淡色状态说明。
3. 路线首次打开时，上方使用 `FGameXXKInRunUiStyle::Font(..., true)` 的项目江湖体显示正式关卡名。现有表的名称如“普通 1-1”。淡入、停留、淡出；刷新、滚动、战斗返回不重播；新路线重新播放。
4. 检查首层 0/N、分支总数不污染分母、金币不误读旧字段、图例内容/固定位置、江湖字体和入场动画生命周期。冷 UBT 后进行默认 `L_DesktopTrainingHUD` 的 PIE 实拍。

## 用户追加

- 行旅钱为可堆叠实物 `Item.TravelMoney`。局内不产出：开局、战斗、精英、首领、事件、篝火、遗物都不发钱。老酒盏退出新掉落池。
- 普通宝箱最终口径：装备50%、宝石30%、材料20%。材料池强化石×1、洗练砂×1、行旅钱×10三种等概率；行旅钱总概率1/15，替代此前10%方案。高级箱保持原池。
- 局外商店行旅钱10个一份、100000金币。分解每个固定2500金币，不吃金币天赋、不奖励工具经验。
- 局内卡牌强化、遗物、刷新均消耗背包＋仓库的实物，背包优先；失败回滚，普通金币不参与支付。
- 图标采用用户选定的前大后小两枚胖铜钱与左下短红绳，参照现有宝石粗墨线和大色块。装备总表07C/07D同步规则与图标，生成器保留这些页。
- 点击节点后只调整已有纵向滚动，使该层居中，不添加横向移动、缩放或其他跟随功能。必要的末端滚动留白不能改变原节点间距与首次打开的位置。
- 可选且待选的图标有轻微间歇抖动；文字、点击区域和已选择节点保持稳定。

路线生成、角色资源和原有选点圈仍保持；商店币种按用户本轮新裁决调整。
