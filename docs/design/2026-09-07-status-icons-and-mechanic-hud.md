# 状态图标与法术／药方机制条设计

状态：用户已确认“固定卡位，点亮后显示实际出牌序号”。2026-09-08 新机制条代码与五图共用材质已接入，冷 UBT 与 7 项定向检查通过；真实 PIE 小尺寸／遮罩／悬停验收仍待完成，不能视为视觉验收完毕。见 [接入进度](../production/2026-09-08-mechanic-hud-progress.md)。

## 设计结论

推荐保留水墨轮廓，用“深色描边＋一个主体色”建立统一图标语言。缩小后优先识别外形；不靠细缝、纹理或多个小装饰区分含义。每枚图标至多两种设计颜色，透明背景不计入；抗锯齿只用于边缘，不增加内部渐变。

“简化”需要保留物体特征。法师火任务用飞行火球／火焰流星，灼烧用直立火苗；冰法任务最终改用重新设计的六向雪花，中央实心区域加大；旧菱形冰块与十字棱线方案已被用户替换。用户已认可单股淡绿气流造型，不再改变其轮廓。

## 当前项目取证

- 当前 27 个护甲／状态显示条目共用 21 张独立纹理，另有第二、第三阶段两个文字标记。21 张状态纹理均已通过 UE MCP 实际加载和导出，证据在 `Saved/Codex/CardEffects-20260907/status-assets/`。
- 现有素材分为 14 张带纸框的 v4 素材和 7 张透明轮廓素材，源尺寸分别为 1254 方图与 512 方图。首次读取资源尺寸可能得到占位值，不能据此认定原图只有 32 像素或缺失。
- 图标绘制统一使用 UV `(0.22, 0.20)–(0.80, 0.80)`，再叠加 overscan。它适配旧纸框素材，对完整透明图形会切掉边缘；必须按素材类型区分，再统一视觉占比。
- 纹理本身已有颜色，显示时还乘了状态 Tint。纸色也参与乘色，导致部分底和主体偏暗、不同来源素材的色重不一致。
- “追击标记／破绽追击／疗愈增幅”共用战术图；五种地势与代挡状态共用另一张图。相近颜色和同一轮廓会加重识别负担。
- 数字角标原字号为 10，部分缩小场景下较弱。应与图形一起检查最终尺寸，而非只看大图是否精细。
- 125 个 UI 路径字面量的初次检查中，120 个完整路径存在，4 个是动态拼接前缀，1 个历史窗纸底路径无效；该无效引用已改用现有 PanelLarge。动态前缀不能误报为缺图。

上述结论区分了运行时截图、UE 导出纹理和源代码配置。原始绿幕素材不等于玩家能看到绿边；具体可见范围仍由 UV、裁剪和实际构建结果决定。

## 优先优化顺序

| 顺序 | 问题 | 建议 |
|---|---|---|
| 1 | 透明图形仍套用旧纸框裁剪 | 透明图使用完整 UV；旧素材按既定有效范围展示，避免切掉叶尖、弓弦等轮廓 |
| 1 | 填充率不一致 | 统一图案包围盒与视觉体量；细长图加粗、缩短尖端，雪花中心加大；不通过非等比拉伸填满 |
| 1 | 法术火／灼烧容易混淆 | 红色飞行火球与橙色直立火苗采用明显不同轮廓；灰度下也要分得开 |
| 2 | 重复底、重复上色 | 最终倾向“透明图案＋共用纸底”；只染图案一次，亮灭由统一显示状态控制 |
| 2 | 多状态共用同一轮廓 | 先拆分战术三项、地势与代挡；同一语义的时限变体可共享主图，用明确时限标记区分 |
| 2 | 角标较小 | 试验 12–14 号江湖体及深描边，按位数收敛；实际完整数值继续在 Tooltip 显示 |
| 3 | 频繁闪烁可能干扰挂机 | 静态图标保持安静，只有新增、触发或完成时做一次短脉冲 |

这些是整套图标后续替换的建议，不表示所有旧图已经重绘或导入。

## 五张新图的分工

| 图标 | 轮廓 | 颜色 | 关键要求 |
|---|---|---|---|
| 雷任务 | 宽而短的闪电 | 黄色＋深赭描边 | 去掉细小副闪电，主体不能细成一根线 |
| 火任务 | 圆形火球头＋短火焰拖尾 | 红色＋深棕红描边 | 与灼烧直立火苗区分，保留火球物体感 |
| 冰任务 | 六向雪花，中心相连且雪花心加大 | 浅蓝＋深蓝描边 | 只借鉴六向雪晶类型，重新设计中心与分叉；无外围碎片 |

## 填充率与缩小验收

以 22、28、32、44 像素的实际显示尺寸比较，并放到项目真实纸底附近；大图只能看制作细节。

- 图案主体包围盒先以图标格约 75%–85% 为起点，按视觉重心微调。不同形状不强求相同像素面积。
- 雷电等细长形要增加主体厚度，不能只把尖端伸长来达到“占满”。雪花保持宽高均衡，中央实心区域约占图案宽度的30%。
- 内部至多一处关键的大留白，避免最终小于约 2 像素的细缝。雪花以连贯的实心中心连接六臂，不增加内部小孔。
- 描边在最低倍率下仍连续，主体色与纸底有足够区别；浅蓝／淡绿尤其需要深色边界。
- 先在灰度下比较火球、火苗、血滴、气流，再检查颜色。颜色不能是唯一识别线索。
- 动态数字放在单独 UI 层；保留可读字重，不让数字遮住图案唯一的识别特征。

这是设计起点，最终以实机小尺寸结果为准，不宣称某组比例自动保证清晰。

## 法术任务：固定槽位与真实牌序

在资源条附近增加独立机制条，避免挤入已有六格状态栏。建议主图约 32，标记约 24–28，格间留 4–6 个逻辑单位；图标实际尺度需用最终 HUD 倍率复核。

主角法术任务 4 格，法师伙伴 5 格，宋金宝／月白任务 3 格。NPC 没有对应元素分支时使用通用图标，不根据卡名猜元素。

用户已确认固定槽位：每格始终对应一张入局携带牌。例：固定牌位 A、B、C、D、E，实际打出 D→B→A，标记显示 **3、2、空、1、空**。图标不会换位，数字表达真实出牌顺序。

- 未出：低亮度墨环，没有牌序数字。
- 已出：成功主动出牌后点亮，并显示首次出牌序号；失败、取消、重复打同一牌、自动重放不重复计数。
- 悬停元素图：任务分支、进度和未出的卡名列表；悬停单格：对应卡名、是否已出及牌序，可复用卡牌 Tooltip。
- 未开启：预留稳定位置，显示灰态提示；不让状态栏在开任务时突然跳位。
- 通用牌先手：先显示淡绿“分支待定”；第二张牌锁定分支后换相应元素。核心／通用对应普通分支时仍用通用图。
- 完成：依序短亮，随后随真实重放过程反馈；保留完成快照直到展示结束，再依据运行时重置，不能在第 5 张落下时瞬间清空。
- 不默认每回合清零；根据真实任务是否完成或失效决定。存档恢复按记录重建，不播放假完成动画。

现有数据可直接提供固定成员和牌序：`LockedHeroCardIds`／`LockedCardIds`、`CompletedHeroCardIds`／`CompletedCardIds`、`FirstPlayOrder`。法师伙伴的锁定牌按 `AcquisitionOrdinal` 与实例 ID 排序，避免从已经洗乱的牌堆直接取槽位。

现有运行时在重放结束后重置任务；UI 需要独立的只读完成快照。只读展示不应新增任务进度、奖励或次数规则。主角与伙伴／NPC 的每回合次数差异仍待设计裁决，本方案不擅自改规则。

## 药方：固定编号与持续效果

每名角色按携带药方卡的稳定顺序编号 1–5。编号是药方身份，不是层数，也不是本回合触发顺序。未开启药方继续由手牌绿光提示；开启后，在角色机制条显示对应编号药纸。

- 使用 `OwnerUnitId + SourceCardId` 区分药方；同一张牌重复打出、复制或检索不会生成第二枚相同图标。
- 悬停显示药方名称、编号、效果、开方时锁定的品质，以及能可靠判定的本回合触发状态。
- 药方的 `SourceQuality` 是开方时品质，不能拿后来升级后的手牌品质覆盖已有药方说明。
- `Progress`、`PhaseProgress`、`LastTriggeredRound` 等字段因药方类型不同而含义不同，不能全部当成同一种倒计时。首版只显示已明确解释的进度。
- 药方触发时只做一次短脉冲；达到本回合次数上限后变弱，但图标保留，不能误导为永久失效。
- 角色倒下时明确药方不生效；离开本局时清理，不把它写成永久被动。

周光祖、琼梅儿等角色有药效或治疗能力并不自动代表具有“药方”。仅为真实存在的 `HealerFormulas` 显示药纸，保持机制与文字一致。

## 接入验收

新机制条至少覆盖：首次任务、通用先手分支锁定、重复卡不重复计数、自动重放、跨回合保留、重放完成、读档恢复、角色倒下、4／5／3 格；药方覆盖同名不同角色、编号稳定、重复开方、品质锁定、次数耗尽及读档。所有测试同时检查运行时状态不被展示层修改。

图标正式替换前确认轮廓与两色风格，再整理完整 alpha 和统一边距。显示层优先复用现有字体、纸底和 Tooltip；不为了新图标改掉原 Pill。
