一、项目概述

《霞客行》是一款基于 Unreal Engine 5.8 开发的卡牌构筑 + 回合制战斗 + 城镇探索的单人演示游戏。 玩家扮演初入青山镇的旅行者，在古镇中与六位江湖人物结交，招募伙伴、配置装备、构筑卡组， 沿路线地图挑战事件与强敌，在一次次战斗中验证并深化自己的构筑，形成完整的 「战斗赚取 → 商店消费 → 装备强化 → 伙伴养成 → 再战更强」成长闭环。

二、游戏流程

游戏的全部内容围绕「城镇 — 路线 — 战斗」三大空间展开，主菜单点击「开始游戏」后直接进入青山镇，无需二次跳转：

主菜单开始游戏 / 读取
→
青山镇任务 · 商店 · 招募
→
路线地图选择事件/商人/战斗
→
卡牌战斗意图预判 · 地形运用
→
结算奖励 · 装备 · 金币
→
返回城镇强化循环
↺ 成长循环：战斗赚取 → 商店消费 → 装备/伙伴强化 → 再战更强

与 NPC 的三种互动

🏮 任务（土司首领）

接受主线任务推进冒险进程，解锁路线地图与后续内容。

💰 商店（宋金宝）

开放商店窗口：装备包（按套装批量开出装备，含武器图标）、伙伴包（招募新伙伴）。购买结果以「背包格子 + 中文说明 + 可悬停查看属性」的窗口呈现，确认按钮关闭。

🤝 招募（其余四位）

与可加入的伙伴对话将其收入队伍，成为卡牌战斗中的可出战单位，进入伙伴养成体系。

四、可玩性分析

演示版以「一条可完整循环的成长链路」为目标：从点击开始游戏到打一场完整的卡牌战斗， 再到回城强化，每一步都有实时的界面与数值反馈，玩家能清晰感知「为什么变强了」。

完整性：全流程可玩

  • 主菜单 → 城镇 → 互动 → 路线 → 战斗 → 结算 → 回城，无断点
  • 所有关键交互都有明确反馈：购买成功弹结果窗、满员置灰、遣散自动卸装
  • 40+ 自动化测试用例守护流程，核心玩法套件全绿

信息密度：贴近设计稿

  • UI 按 Master V1 PSD 页面级坐标还原（页 02/03/07/18）
  • tooltip 纸片、选择墨迹、关闭墨迹等视觉语言全局统一
  • 数值对比用「红升绿降」双色块即时呈现差异

操作手感：一致性与细节

  • 局内局外卡面统一，选中风格一致，学习成本低
  • 伙伴切换、装备跟随、标签页互斥，状态不串扰
  • 手牌放大 1.5× 保证可读性，肖像裁切不越界

数值循环：有深度的构筑空间

  • 18 个装备套装 × 2/4/6 件激活阈值，构成装备构筑目标
  • 六名伙伴各具定位（统御·护阵 / 谋略·情报 / 术法·灼印 / 医术·地志 / 市井·策应 / 山野·灵引）
  • 遣散释放成本 → 鼓励尝试不同伙伴组合

五、局内成长系统（卡牌战斗）

战斗是「把构筑兑现为操作」的舞台。玩家与至多三名出站角色共享一张卡组，围绕四个核心机制展开攻防：

⚡ 资源双轨：共享能量 + 个人法力

  • 卡牌费用分为共享能量与角色法力两类，限制单回合动作数量
  • 「充能」「回蓝」类卡牌与效果形成资源运营层

🎯 意图预判

  • 敌人回合前揭示行动意图，玩家据其分配护甲、嘲讽与击杀优先级
  • 「耳目密报」等卡牌可额外洞悉多回合意图，信息差即收益

🌲 地形加成

  • 战场存在 断崖 / 村落 / 森林 / 洞穴等地形
  • 部分卡牌在特定地形获得额外效果（如「石门守势」在断崖村落额外护甲）
  • 「地志摹图」可把地形优势翻倍，考验卡组与战场匹配度

🔥 状态系统

  • 增益：动量 / 敏捷 / 地形加成翻倍等
  • 减益：灼烧 / 中毒 / 脆弱 / 标记
  • 净化：解毒 / 驱散持续伤害，治疗与护甲构成防御端选择

六、局外成长系统（背包 · 装备 · 经济）

局外成长把战斗收益转化为可持有的资产，是驱动玩家持续游玩的引擎：

💰 经济循环

  • 初始金币 10000，战斗与事件产出金币
  • 商店以装备包 / 伙伴包两种商品回收金币
  • 装备包按套装开出，装备包图标直接使用套装武器图，所见即所得

🎒 背包管理

  • 200 格大仓库，装备/道具混仓，4×5 网格 + 滚动条
  • 选中格高亮 + 墨迹选中样式，纸片 tooltip 悬停即看属性
  • 仓库满时商店对应商品置灰，杜绝「买了放不下」

⚔️ 套装构筑

  • 18 个装备套装，集齐 2 / 4 / 6 件逐级激活更强效果
  • 背包与装备槽均展示套装进度，达成自动标注「（已激活）」
  • 背包装备与已穿戴对比：升红降绿直观呈现收益

🛡️ 装备槽联动

  • 主角与伙伴拥有各自的装备槽，伙伴装备槽随伙伴切换跟随
  • 遣散伙伴时装备自动卸下回背包，资产不流失

七、伙伴养成系统

伙伴养成是局外成长的核心分支：招募 → 定位认知 → 装备武装 → 组队出战 → 遣散换血， 与主角背包共用同一套视觉与交互语言，学习成本为零。

🪪 招募与命名

  • 城内与可加入 NPC 对话即招募入队
  • 新游戏自带 2 名起始伙伴，开局即可体验切换
  • 伙伴拥有确定性生成的中文名与独立定位描述

📋 三页签养成界面

  • 属性：立绘头顶显示姓名，属性页签展示数值
  • 装备：装备槽跟随选中伙伴，与背包 1:1 对照
  • 卡组：查看/管理伙伴初始卡池与构筑

🃏 卡牌联动

  • 伙伴卡牌 tooltip 与主角同款纸片底图 + 完整效果描述
  • 局内卡面与局外统一：同一 CardFrame、同一肖像裁切规范
  • 伙伴初始卡池决定其在战斗中的定位与玩法

⚖️ 解散规则

  • 遣散不设人数上限，随时可遣散
  • 遣散自动卸装，装备回归背包
  • 保留至少 1 名伙伴：最后一个伙伴不可遣散，保证队伍永远可用
  • 满员时商店伙伴包置灰，避免无效消费

八、技术实现亮点

🧩 程序化 UMG

  • 所有主界面（主菜单 / 城镇 HUD / 背包 / 伙伴背包 / 商店 / 战斗面板）均由 C++ 构建程序化布局
  • FrameCanvas 与 RootCanvas 同级定位（0,0）1920×1080，内容使用绝对屏幕坐标直接映射 PSD 设计稿
  • 坐标系与 PSD JSON 页坐标对齐，改布局 = 改坐标常量，可回归测试

🎨 PSD 驱动工作流

  • 从 Master V1 PSD 导出页级 JSON 坐标（页 02/03/07/18）作为唯一布局真相
  • 批准纹理（PanelLarge / tab / ItemSlot 纸片 / CardFrame / SelectionInk 等）统一入库
  • 脚本化导入管线：gamexxk_import_*.py 通过 MCP 在编辑器内执行

🤖 MCP 自动化

  • 编辑器内嵌 MCP 服务（端口 18765），脚本可导入资产、探查运行时、批量修改资产
  • 本轮通过 MCP 完成了主菜单背景、6 张 NPC 第一帧的导入与精灵/动画书重定向

🧪 测试体系

  • 8 个自动化测试套件、40+ 用例：伙伴招募、商店规则、MVP 流程、UI 布局、卡牌战斗
  • 通过 UnrealEditor-Cmd Automation RunTests 无头执行，回归守护
  • 本轮新增：NPC 精灵/动画书链路验证脚本，资产级校验
