# GameXXK 新商店 PSD 设计规格

**日期：** 2026-08-05
**状态：** 已确认，待壳体分层规格复核
**当前阶段：** 仅制作 PSD 与预览，不迁移 UE

## 目标

以用户提供的 1920×1080 商店效果图为目标构图，优先使用现有 GameXXK UI Master V2 组件套件，在可编辑 PSD 中完成新商店页面。用户确认 PSD 成稿后，才统一导出 RuntimeAssets 并迁移至 UE。

本阶段不得修改游戏内商店 UI、导入 UE 资源或提前制作运行时热区。

## 权威参考

- 目标构图：用户提供的 `codex-clipboard-80d2c217-6fe9-444d-aeac-4e5ff568bec1.png`。
- 当前组件套件：`SourceArt/UI/PSD/gamexxk-v4/calibration-v2/`。
- UI Master 工程：`SourceArt/UI/PSD/gamexxk-v4/ui-master/`。
- PSD 输出：`outputs/UI_PSD/Candidates/GameXXK_UI_Master_V1.psd`。
- 商店页面：`07_商店交易`。

若目标图与组件套件存在细节差异，保持目标图的信息层级和构图，视觉表面优先使用套件；允许等比缩放、九宫格拉伸、裁切和轻微统一色值，不创建另一套视觉语言。

## 页面构图

- 画布固定为 1920×1080。
- 保留城镇背景，并覆盖与现有 Master 一致的暗化层。
- 左上放入真实主角头像、主角名称和身份信息，不保留空白占位。
- 左侧垂直放置背包、伙伴、图鉴、任务、路线五个真实主导航图标。商店由 NPC 交互打开，不伪造额外商店导航；五个导航均保留正常态。
- 右上资源栏显示铜钱图标和示例数值 `500`，不显示“永久金币”或“金”字。
- 主商店纸面位于画面右侧主体区域，尺寸、留白和轮廓尽量贴近目标效果图。
- 左侧商品区呈 4+3 两排，共七个商品。
- 右侧固定为所选商品的图标、名称、说明、等级、概率、可能部位和购买操作。

## 组件与资源使用

- 主纸面、资源栏、导航底座、导航状态、商品槽、详情槽、按钮和状态框优先来自现有 UI Master V2 套件。
- 铜钱统一使用 `SourceArt/UI/PSD/gamexxk-v4/calibration-v2/Content/resource_coin.png`。
- 不使用 `resource_gold.png` 元宝图标。
- 七个商品使用现有 Meta Shop V2 独立商品图标，不将商品名称或价格烘焙到图标中。
- 商品卡价格统一表现为“铜钱图标 + 数字”。
- 右侧购买按钮统一表现为“购买 + 铜钱图标 + 数字”。

## PSD 图层结构

### 全屏壳体非破坏式拆分

当前 `approved_v2_shop_shell` 不得继续作为城镇背景与全部纸张窗口共用的可见合成层。必须以用户最后保存的 `outputs/UI_PSD/Candidates/GameXXK_UI_Master_V1.psd` 为输入，在修改前创建带时间戳的 PSD 备份，并在原 PSD 中追加以下可独立移动、缩放和开关的透明图层：

1. `00_城镇背景`：无 UI 城镇底图，并匹配现有商店画面的压暗色调。
2. `01_主角身份条`：左上圆形头像底框与横向身份纸条作为一个窗口组件；头像和文字仍为其上的独立内容层。
3. `02_顶部铜钱条`：右上横向纸条；铜钱图标和数值仍为独立内容层。
4. `03_导航圆底_背包`。
5. `04_导航圆底_伙伴`。
6. `05_导航圆底_图鉴`。
7. `06_导航圆底_任务`。
8. `07_导航圆底_路线`。
9. `08_中央商店窗口`：只包含中央大纸面、撕边、墨线和阴影，不烘焙标题、商品、详情或按钮。
10. `99_原始合成壳体_备份`：保留原始整屏壳体，默认隐藏，不得删除。

拆分采用独立纸张蒙版，不直接对两张背景做逐像素相减。现有无 UI 城镇底图与合成壳体几何一致但色值不同，必须先做整体色调匹配；纸张蒙版应保留撕边、墨线、投影和半透明抗锯齿，且不得携带窗口外的屋顶、地面或植被像素。

除 PSD 图层外，同时导出八个窗口组件透明 PNG、一个城镇背景不透明 PNG 和一份放置清单。窗口 PNG 使用紧边透明画布；放置清单记录原始 1920×1080 坐标、尺寸、PSD 图层名和资源来源。城镇背景固定输出为 1920×1080。此阶段只生成 PSD/源美术资产，不写入 `RuntimeAssets`，不导入 UE。

若自动蒙版在纸张撕边产生脏边，必须暂停批量写回，改用局部人工修边；不得用模糊扩大蒙版掩盖问题。用户已调整的文字、图标、位置和状态图层不得被重新生成或覆盖。

`07_商店交易` 至少包含以下可独立开关的语义组：

1. `10_Background`：城镇背景与暗化层。
2. `20_GlobalShell`：左上身份区、左侧五导航、右上铜钱栏。
3. `30_ShopPaper`：商店主纸面与标题区域。
4. `40_ProductGrid`：七个商品槽、图标、名称和价格。
5. `50_ProductDetail`：所选商品的图标、说明、概率和部位。
6. `60_PurchaseAction`：购买按钮、铜钱图标和价格。
7. `70_State_Default`：默认可购买状态。
8. `71_State_Selected`：商品选中态。
9. `72_State_InsufficientFunds`：铜钱不足状态与原因。
10. `73_State_Confirmation`：二次确认状态。
11. `74_State_Result`：购买成功或失败结果状态。

文字必须保留为可编辑文字图层；可复用 PNG 不得烘焙运行时文字。商品图标、铜钱图标和选中装饰必须保持独立图片图层。

## 状态表现

- 默认预览展示第一件商品处于选中状态，与目标效果图一致。
- 选中态必须同时影响商品槽和右侧详情，不能只加文字颜色。
- 铜钱不足时购买按钮使用套件禁用态，并在按钮附近显示明确原因。
- 二次确认在同一商店布局内出现，不跳转到另一套通用弹窗风格。
- 购买结果在同一商店布局内出现，保留主框架、导航、身份区和铜钱栏。

- 更新后的可编辑 UI Master PSD。
- 拆分前 PSD 时间戳备份。

- `07_商店交易` 默认选中态预览 PNG。
- 金币不足、二次确认、购买结果三张状态预览 PNG。
- 一份组件来源与使用方式清单，标明直接复用、缩放、九宫格或裁切。

交付后等待用户确认。用户确认前不得：

- 导出或替换 UE RuntimeAssets；
- 修改 `UGameXXKMetaShopWidget`；
- 调整商店运行时代码或交互探针；
- 声称游戏内还原完成。

## 后续迁移边界

PSD 获得用户确认后另行制定 UE 迁移计划。迁移时保持现有商店数据和购买事务接口，只替换视觉装配与状态呈现；旧商店继续不可见，路线商人保持隔离。
