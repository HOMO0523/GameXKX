# GameXXK UI 母版与公共组件设计规范

日期：2026-08-04  
状态：待用户书面复核  
视觉基准：用户批准的城镇主角/背包效果图，以及当前局内终版角色、怪物 Idle 图

## 1. 目标

建立一份与 NWUEBall 最新 PSD 工作流一致的 GameXXK UI 母版：先在一张超大分层 PSD 中并排展示公共组件、十二个主要界面和五个关键交互状态，输出 Contact Sheet 供整体审阅；公共组件通过后，所有界面只使用这套组件继续制作，最终再导出无文字运行时切图并接入 UE。

当前 `GameXXK_HeroBackpack_V1.psd` 仅保留为被否决的布局验证稿。它不能成为正式组件来源，也不能直接进入 UE。

## 2. 母版拓扑

- 逻辑单页：`1920 × 1080`，72 DPI。
- 页面间距：横向、纵向均为 `120 px`。
- 主 PSD：`10080 × 4680`。
- 排列：5 列 × 4 行，共 20 个槽位；使用 18 个顶层页组，保留 2 个空槽供后续扩展。
- 术语：生成器当前只保证顶层 page group，不宣称 Photoshop 原生 Artboard 或 Smart Object 实例。
- 每个页面组必须能单独导出 `1920 × 1080` 预览。
- 所有页面同时生成一张 Contact Sheet。

## 3. 制作顺序与审批门槛

### 阶段 A：公共组件与灰度页面

1. 完成 `00_公共组件` 的所有组件族及交互状态。
2. 其余 17 个页组只完成灰度布局和真实内容占位，不做最终彩色绘制。
3. 生成公共组件页预览、17 个灰度页面预览和 Contact Sheet。
4. 用户逐项确认组件与整体信息层级。

### 阶段 B：正式页面

1. 只使用已批准组件完成十二个主要界面。
2. 再完成五个关键状态页。
3. 每页可独立批准、拒绝或延后；不能用结构验证替代视觉批准。

### 阶段 C：运行时切图与 UE

1. 仅导出已批准、无动态文字的组件和页面切片。
2. 标签、数值、描述、卡牌名、角色名继续由 PSD 可编辑文字层和 UE `TextBlock` 承担。
3. 用户明确批准具体页面后，才能进入 UE 导入、WBP/原生 UMG 组合和 PIE 验收。

## 4. 公共组件页

`00_公共组件` 分为六个套件。每个套件在同一页并排展示所有状态、尺寸和九宫格安全区域。

### 4.1 宣纸面板

- 大、中、小三种不规则撕边宣纸面板。
- 墨线应有轻微粗细变化和断笔，不使用规整双圆角描边。
- 支持无遮罩、30% 暗幕和 50% 暗幕背景。
- 面板边缘不得烘焙标题或正文。

### 4.2 页签与按钮

页签状态：普通、悬停、按下、选中、禁用。  
按钮状态：普通、悬停、按下、主要、危险、禁用。

按钮统一规则：

- 禁止使用红、蓝、绿等大面积彩色填充区分语义。
- 普通按钮使用浅宣纸底和细手绘墨线。
- 主要按钮仍使用宣纸底，以加粗墨框、淡墨刷痕或局部反白强调。
- 危险按钮仍使用宣纸底，仅允许文字旁或角落出现小型朱砂印记；不得铺满红底。
- 悬停使用轻微暖纸提亮和墨线加深。
- 按下使用 `2–4 px` 内缩、纸张压暗和局部墨晕。
- 禁用使用低对比灰墨，不改变按钮几何形状。
- 所有文字必须独立可编辑，不能烘焙进按钮切图。

### 4.3 城镇 HUD 与圆形入口

- 左上角色头像、等级、经验、战力信息条。
- 右上铜钱、玉石、元宝资源条。
- 左侧圆形入口：主角/背包、伙伴、图鉴、任务、地图/路线。
- 每个入口提供普通、悬停、选中、提醒和锁定状态。
- 图标必须通过轮廓和内部主体区分功能；不得只换文字或颜色。
- 圆形入口使用宣纸圆片和毛笔墨线，不使用塑料感浮雕或高饱和渐变。

### 4.4 槽位与卡片

- 装备槽、物品槽：空、悬停、选中、锁定、禁用。
- 角色卡、怪物卡、战斗卡保持同尺寸基准；六类卡底通过低饱和纸色和局部纹样区分，不使用纯白统一底。
- 卡牌顶部保留可编辑名称区；人物或怪物半身像从当前局内终版 Idle 图裁切。
- 选中态使用墨线、纸边和轻微光晕，不改变原图比例。

### 4.5 数值与状态

- 生命、经验、资源、任务进度、战斗状态条。
- 铜钱、玉石、元宝及数量排版。
- 提醒红点、数量徽记、锁定、完成、选中标记。
- 状态色只允许作为小面积信息编码，不允许成为大按钮底色。

### 4.6 弹层与提示

- 物品详情、角色详情、怪物详情、卡牌详情。
- 确认框、轻提示、错误提示、教学提示。
- 关闭、返回、分页箭头和滚动条。

## 5. 视觉语言

### 5.1 基础色

- 宣纸：`#E8D7B3`，允许在 `#D8C39A–#F0E3C6` 内产生纹理变化。
- 主墨：`#2B2822`。
- 次墨：`#5D5548`。
- 朱砂：`#A14F36`，只用于印记、提醒和极小面积语义点。
- 玉色：`#6B907C`，只用于资源、进度或状态图标的小面积编码。
- 金色：`#B78C43`，只用于货币与稀有度点缀。

### 5.2 形状

- 大面板优先使用自然撕边和不对称纸张轮廓。
- 小控件允许近矩形，但边线必须有手绘变化。
- 取消当前候选稿中的统一圆角双描边控件。
- 保持紧凑布局，尽量露出 3D 城镇；背包等主要页面不得完全遮住背景。

### 5.3 文字

- 中文标题、页签与正文优先使用楷体/手写感字体方向。
- 候选阶段可使用本机 `STKaiti`，但必须记录字体文件与哈希；正式可移植包晋升前必须固定可合法分发的字体文件。
- 所有动态文本必须保持独立 Type Layer。

## 6. 角色、怪物与图标来源

- 主角 UI 形象固定来源：`SourceAssets/AnimationProcessing/Production/character_00_hero_idle/frames/frame_0000.png`。
- 对应运行时图集：`/Game/GameXXK/BattleAnimations/Atlases/T_character_00_hero_idle_atlas`。
- 伙伴和怪物同样使用当前局内终版 Idle 动画首帧，不使用早期头像或旧卡面生成图。
- 禁止使用 `SourceAssets/PartyDeck/card-portraits/generated` 作为新 PSD 的人物来源。

### 6.1 等比缩放规则

- 位置与缩放以完整透明源画布为基准，不以非透明内容包围盒为基准。
- 缩放必须使用统一比例：`scale = min(targetWidth/sourceWidth, targetHeight/sourceHeight)`。
- 缩放后在目标框内居中，保留源图透明边距关系。
- 禁止分别设置横向和纵向缩放比例。
- 当前 Hero Idle 为 `512 × 512`，非透明内容约 `260 × 423`；不得把该内容包围盒强制拉成正方形。

## 7. 页面布局基准

### 7.1 城镇 HUD

- 左上角色状态条、右上资源条、左侧圆形入口。
- 入口采用单列竖排，不遮挡主要城镇交互区域。
- HUD 组件在背包、伙伴、图鉴、任务等城镇界面中保持同一位置和尺寸。

### 7.2 主角/背包

- 视觉构图高度贴近用户批准的图 1。
- 中央撕边宣纸面板；左侧角色和六个装备槽，右侧背包分类、物品格和详情。
- 主分类使用手绘矩形页签；背包分类选中态使用墨块或粗墨刷痕。
- `使用`、`整理`、`分解` 均使用统一宣纸按钮组件；其中 `分解` 仅增加小朱砂印记。
- 人物保持修长原比例，不得再次横向拉宽。
