# GameXXK 目标悬停结算预演设计

日期：2026-08-12

状态：用户确认，等待书面规格复审后进入实现计划

基线：`97dbd3268481c3b214bfea106f8aa23216df0486`

## 1. 目标

玩家选中一张需要单位目标的卡牌后，悬停合法目标时，在该目标血条附近显示本次出牌对该目标的**实际数值结果**。纯群攻牌无需选择单位；玩家悬停该手牌时，直接显示敌方各位置各自的实际承伤类别与数值。

本功能统一覆盖：

- 单体伤害与群体伤害；
- 多段攻击、重箭追加、流血/中毒/灼烧触发与毒爆；
- 药师药效对敌扣血；
- 对我方角色的治疗与护甲；
- 防御、护甲、破绽、标记、气势、灵动、怪物被动、伤害改向和致死中断后的真实结果。

核心体验要求：**短、准；单体只看当前目标，群体逐个看清敌方位置**。不得把卡牌完整说明或计算过程重复塞进悬停层。

## 2. 已确认交互

1. 单体结果只显示当前鼠标悬停的合法目标；纯群攻牌或真实结算含 `GroupAttack` 群体伤害包时例外，必须同时列出敌方 1P、2P、3P 中每个预演开始前实际存在且存活目标的承伤。
2. 手动单位牌只在选目标阶段显示，移开目标后立即隐藏；纯群攻牌在悬停手牌时显示，移开手牌后立即隐藏。
3. 点击出牌、取消选牌、状态刷新、演出锁定、战斗结束或界面销毁时立即清除。
4. 纯单体结果固定在当前目标血条附近；纯群攻牌或真实结算含 `GroupAttack` 群体伤害包时，在敌方区域使用一张按 1P→2P→3P 排列的 `HitTestInvisible` 临时清单。
5. 不移动或缩放现有血条、状态图标、敌方意图、角色、手牌、按钮和任何已确认布局。
6. 自动目标、全体目标、自身目标和无目标牌保持现有直接结算流程，不新增二次确认步骤；纯群攻牌的手牌 Hover 只负责预览，点击仍立即出牌。
7. 若一张手动选目标牌的实际结算包含群体伤害包，该包必须写成 `群体伤害`，不得简写成 `伤害`；每个敌方位置自己的单体、群体、毒爆、DOT、药效和联动伤害合并在该位置行内，敌方空位不生成占位行。

## 3. 文本规则

### 3.1 总体格式

- 纯单体预演最多两行；涉及多个敌方位置时，每个有效位置固定一行，最多三行，不再增加全场总计行。
- 只显示实际生效数值，不显示卡面理论值、溢出值、百分比公式或逐层计算过程。
- 同行类别用 ` · ` 分隔。
- 纯单体有两个及以上伤害类别时，第二行显示 `合计`；敌方位置行有两个及以上伤害类别时，`合计` 直接放在同一行。
- 致死时在最后追加 `· 致死`。
- 数值为零但卡牌明确属于治疗或护甲效果时，仍显示 `治疗 +0` 或 `护甲 +0`，让玩家知道目标当前没有数值收益。
- 状态层数继续由卡牌文本和现有状态图标说明，本预演不重复罗列“中毒 +N”“清除流血”等非即时数值变化。

### 3.2 示例

单体攻击：

```text
伤害 48
```

悬停纯群攻手牌时：

```text
1P 群体伤害 48 · 毒爆 18 · 合计 66 · 致死
2P 群体伤害 35
3P 群体伤害 42 · 毒爆 6 · 合计 48
```

若 2P 没有存活怪物：

```text
1P 群体伤害 48
3P 群体伤害 42
```

单体攻击并毒爆：

```text
伤害 48 · 毒爆 18
合计 66 · 致死
```

同时包含单体与群体伤害，当前悬停 2P：

```text
1P 群体伤害 10
2P 伤害 20 · 群体伤害 10 · 合计 30
3P 群体伤害 10
```

药效与毒爆：

```text
药效伤害 15 · 毒爆 11
合计 26
```

治疗与护甲：

```text
治疗 +5 · 护甲 +12
```

完全被闪避或护甲挡住：

```text
伤害 0
```

### 3.3 伤害类别

预演按真实伤害包的语义归类，不按卡名猜测：

| 真实结算来源 | 显示词 |
|---|---|
| 单体直接攻击 | `伤害` |
| 群体直接攻击 | `群体伤害` |
| 普通流血触发 | `流血` |
| 普通中毒触发 | `中毒` |
| 普通灼烧触发 | `灼烧` |
| 流血、中毒、灼烧的毒爆包 | 合并为 `毒爆` |
| 消耗药效对敌扣血 | `药效伤害` |
| 其他明确的出牌后附加扣血 | `联动伤害` |

蚀伤只增加流血、中毒、灼烧的结算值，不显示为独立伤害类别，也不计入毒爆可引爆类型。

## 4. 精确预演架构

### 4.1 采用方案

新增只读的目标结算预演入口：

1. 接收当前完整 `FGameXXKRuntimeState`、稳定 CardInstanceId，以及手动单位牌的稳定 TargetUnitId；纯群攻牌使用 `NAME_None`。
2. 复制完整 RuntimeState。
3. 在副本上调用与真实点击完全相同的 `FGameXXKCardBattleAdapter::ResolveCardPlay`；手动牌传悬停 UnitId，纯群攻牌传 `NAME_None`。
4. 从副本结算结果和结算前后目标状态生成紧凑预演模型。
5. 丢弃副本，绝不回写真实运行时。

不在 UI 里重新实现攻击、治疗、护甲或毒爆公式。这样可自动继承：

- 气势、虚弱、防御、破绽、标记和护甲；
- 灵动的确定性下一次判定；
- 怪物首次受击、厚皮等被动；
- 守护改向；
- 重箭消耗、追加攻击和追加毒爆；
- 药效快照及一次性消耗；
- 套装、药方、任务奖励、自动重放和出牌后联动；
- 当前真实随机状态，但只推进副本中的随机序列。

### 4.2 不采用的方案

- **UI 复制公式**：实现快，但一定会和共享结算器漂移。
- **只复制 CardBattleRuntime**：会漏掉完整 RuntimeState 中的遗物、路线与投影联动。
- **预先计算所有合法目标**：会制造不必要的结算开销，也违背“只看当前目标”。

## 5. 预演数据契约

### 5.1 伤害审计补全

现有 `FGameXXKCardDamageResult` 需要补足 UI 可依赖的稳定语义：

- 新增并填写 `EGameXXKCardDamageKind Kind`，用于区分单体与群体伤害；
- 在 `EGameXXKCardDamageCause` 末尾追加 `Medicine` 与 `Relic`，明确药效反向治疗和出牌后遗物附伤，不再与普通环境扣血混为一类；
- 保留真实目标，用于处理守护改向；
- 保留实际 HealthDamage，预演只展示该值；
- 毒爆继续保留流血、中毒、灼烧三个真实包，展示层只合并数字。

所有由当前出牌触发的实际扣血都必须进入同一个 `DamageResults` 审计。`震山鼓坠` 等出牌后遗物不得再直接改 HP 而不留下结果；它们改走共享伤害入口并作为 `联动伤害` 回传，数值与触发时机不变。

新增枚举值必须追加在现有序列末尾，不改变既有序列化数值。

### 5.2 治疗与护甲

- 所有由当前出牌触发的治疗尝试都写入 `FGameXXKCardHealingResult`，包括满血时 `EffectiveHealing = 0`；预演直接使用 `EffectiveHealing`，不从最终血差倒推。
- 新增与治疗结果同级的护甲审计，至少记录 SourceUnitId、TargetUnitId、RequestedArmor 与 EffectiveArmor；所有出牌护甲尝试都必须写入，包括达到 99 点上限时的 `EffectiveArmor = 0`。
- 对我方目标只汇总落到该目标的治疗和护甲，不显示其他队友的群体收益。
- `护甲 +X` 使用本次出牌实际成功赋予该目标的 `EffectiveArmor` 合计；若护甲随后被同一张牌的其他机制消耗，消耗规则仍由卡牌文本说明，不把护甲收益写成负数，也不让 UI 自己解析卡牌定义。

### 5.3 目标预演模型

预演结果至少包含：

- CardInstanceId；
- HoveredTargetUnitId；纯群攻手牌预演时允许为空；
- 一个可选的当前我方目标结果，以及按 1P→2P→3P 排序的敌方目标结果数组；
- 每个目标结果自己的最终 UnitId、Side、SlotNumber、各伤害类别、总实际伤害、实际治疗、实际护甲、致死、闪避和改向状态；
- 已经本地化的紧凑展示行；纯单体最多两行，多个敌方目标时每个位置恰好一行；
- 成功或无法预演状态。

手动悬停敌方目标且真实结算含 `GroupAttack` 群体伤害包时，当前目标的单体与群体类别合并进它自己的位置行，不额外复制一个当前目标框。没有 `GroupAttack` 的手动单位牌严格只投影当前悬停目标；即使遗物等联动同时影响其他单位，也不展开其他目标。手动悬停我方目标时同样只显示该角色的治疗与护甲；只有该次结算真实含 `GroupAttack` 时才另外出现敌方位置清单。

UI 只消费该模型，不读取卡牌定义并自行猜测结果。

## 6. 关键结算边界

### 6.1 多段与致死

- 每段都走真实结算。
- 目标死亡后，真实规则取消的后续段不计入预演。
- 每个目标的 `合计` 只汇总实际落到该目标的伤害包。
- 只要目标在副本结算后死亡，就追加 `致死`。

### 6.2 毒爆

- 先按真实规则锁定流血、中毒、灼烧层数。
- 每种存在的 DOT 生成自己的毒爆伤害包。
- 三种实际 HealthDamage 在展示层合并成一个 `毒爆` 数字。
- 扣层、蚀伤加伤、蚀骨套保层和重箭重复毒爆全部由真实副本结算决定。

### 6.3 药效

- 对我方使用时显示实际治疗。
- 对敌方使用时显示 `药效伤害`。
- 药效快照、基础治疗值和药效层数不在悬停层展开。
- 新结算过程中获得的药效是否保留，由真实快照规则决定，预演不另写特例。

### 6.4 群体与改向

- `群体伤害` 由伤害包的 GroupAttack 语义决定，而不是由卡名或目标模式判断。
- 敌方位置清单只由两种入口启用：悬停纯群攻手牌，或手动单位牌的副本结算实际产生至少一个 `GroupAttack` 伤害包。普通单体牌不会仅因遗物等联动影响多个敌人而展开清单。
- 群体伤害按敌方阵位 1P、2P、3P 分别汇总并逐行显示，不显示一个容易误解的全场总和。
- 遍历预演开始时实际存在且存活的敌方位置；开始前为空、已移除或已死亡的位置不生成行。预演中被击杀的目标仍保留自己的位置行并标记 `致死`。
- 清单启用后，同一位置受到多段群体伤害时显示该位置实际收到的群体伤害合计；该位置自己的单体伤害、毒爆、普通 DOT、药效伤害和遗物联动伤害也合并在同一行，不生成额外总计行。
- 手动选中的单体效果只加入实际承受它的目标行；我方目标的治疗与护甲不混入敌方位置清单。
- 纯群攻牌不进入单位目标模式；其 Card Hover 直接以 `NAME_None` 运行一次只读预演并生成位置行，点击行为不改变。
- 守护将伤害改向其他单位时，不在原目标上显示虚假伤害；原目标显示 `伤害 0`，并以短标记 `已改向` 表明原因。

### 6.5 零结果与错误

- 合法目标但本次数值为零：显示对应类别的 0。
- 预演失败：清除旧预览并显示一行 `无法预演`，绝不保留上一个目标的数字。
- 真实点击仍会重新验证并结算；预演结果不能代替权威提交。

## 7. UI 呈现

### 7.1 位置与生命周期

- 在现有 1920×1080 `BattleDesignStage` 上增加一个瞬时、输入穿透的预演层。
- 纯单体结果使用当前目标已有阵型锚点和 HUD 位置定位到血条附近；多个敌方目标使用敌方 HUD 区域内的固定清单锚点，按 1P→2P→3P 排列，避免三个浮框遮挡角色。
- 预演层绝不参加现有布局流，不改变任何 slot、anchor、offset 或 z-order 关系。
- 单位透明点击代理增加 Hovered/Unhovered 转发；点击行为保持不变。
- 同一个 CardInstanceId、目标和未变化状态只计算一次；鼠标每帧移动不重复结算。

### 7.2 视觉层级

- 单体/群体伤害：低饱和朱红。
- 毒爆和 DOT：低饱和墨绿。
- 药效伤害：低饱和赭色。
- 治疗：低饱和青绿。
- 护甲：低饱和蓝灰。
- `致死`：比普通数字略亮，但不闪烁、不震屏。

使用现有字体、描边与水墨 UI 语言，不增加高饱和霓虹色或大面积新面板。

## 8. 缓存与失效

手动单位牌只在 Hover 事件进入合法目标时计算；纯群攻牌在手牌 Hover 时计算。以下任一事件必须清空缓存和可见文本：

- Unhover；
- 更换选中的卡牌；
- 取消目标选择；
- 出牌成功或失败；
- `RefreshFromState` 检测到权威状态变化；
- 演出队列开始；
- 战斗 VisualSession 取消；
- 单位死亡或移除；
- Board `NativeDestruct`。

不建立跨回合或跨出牌缓存。

## 9. TDD 与验收

### 9.1 规则层 RED/GREEN

1. 预演前后的完整 RuntimeState 必须相等，包括手牌、弃牌、气力、内力、状态、药效、DOT、套装次数、任务进度和 CombatRandomState。
2. 对同一状态、卡和目标，预演模型必须与随后在独立副本上真实提交的结果一致。
3. 锁定单体、群体、多段、致死中断、护甲吸收、灵动闪避、守护改向、怪物被动、气势、破绽和标记。
4. 锁定流血/中毒/灼烧触发、蚀伤加伤、毒爆三包合并、重箭多次毒爆和蚀骨套保层。
5. 锁定药效对友治疗、对敌扣血、药效一次性快照与新药效保留。
6. 锁定治疗满血为 `+0`、护甲达到 99 为 `+0`、治疗与护甲组合。
7. 锁定 `群体伤害` 文案不能退化为 `伤害`。
8. 锁定每个有效敌方位置自己的群体、毒爆、普通 DOT、药效与联动伤害合并在同一行；预演前空位无行，预演中致死目标保留行，且没有全场总计行。
9. 锁定所有出牌关联的伤害、治疗和护甲尝试都有审计，包括遗物联动、治疗 `+0` 和护甲 `+0`。
10. 锁定纯群攻牌以 `NAME_None` 预演，点击仍立即出牌且不进入单位选择。
11. 对全部 198 卡目录项完成“手动单位目标 / 纯敌方群体 / 无本功能预览”三类穷举且无未分类 CardId；对前两类每项至少验证一个合法预演场景并成功，不允许通过跳过未知 CardId 假绿。

### 9.2 UI RED/GREEN

1. 手动单位牌只有选牌目标模式中的合法目标 Hover 才显示；纯群攻牌只有可出牌的手牌 Hover 才显示。
2. 纯单体只显示一个悬停目标且最多两行；多个敌方目标按 1P→2P→3P 每个位置一行，同位置类别合并，空位无行且没有全场总计行。
3. Unhover、取消、提交、失败、刷新、演出锁、session 取消和销毁都清空。
4. 同一目标连续 Hover 不重复结算；切换目标恰好各计算一次。
5. 原目标被守护改向时不显示虚假承伤。
6. 现有战斗布局的锚点、尺寸、offset 和 z-order 断言保持不变。
7. 纯群攻牌 Card Hover 生成有效敌方位置行，Unhover 清空；点击只结算一次且不增加确认步骤。

### 9.3 验证门禁

- 先看到精确 RED，再修改生产代码。
- 冷 UBT，禁止 Live Coding 和 Hot Reload。
- 精确 Automation：目标预演规则、药师、猎手重箭、DOT/毒爆、标记、守护与 Board UI。
- 邻接 Automation：`GameXXK.Data.CardBattle`、`GameXXK.Battle`、198 卡目录运行时组。
- 真实 PIE：至少验证单体、群体、毒爆、药效对敌、治疗、护甲、闪避、护甲全挡、改向与致死。
- PIE 中预览数字与点击后逐包血条变化必须一致；没有旧文本残留、布局跳动或明显 Hover 卡顿。

## 10. 非目标

- 不改变任何卡牌、状态、套装、遗物或怪物数值。
- 不改变卡牌目标规则或给自动全体牌新增确认步骤；纯群攻牌只增加手牌 Hover 预演。
- 不把完整卡牌说明复制到目标预览中。
- 不显示一个合并的全场总伤害；群体伤害必须显示各敌方位置的实际值。仍不显示其他单位治疗或其他单位护甲。
- 不改已确认 UI 布局、页签、角色位置、血条位置和手牌位置。

## 11. 提交边界

建议按可回滚单元实施：

1. `docs: design target hover outcome preview`
2. `test: lock target outcome preview semantics`
3. `feat: add read-only card outcome preview`
4. `test: lock target hover preview lifecycle`
5. `feat: show concise target outcome preview`
6. `test: certify target outcome preview parity`

每个提交只暂存目标文件。用户未跟踪美术、角色素材、背景、PSD 和探针脚本不得纳入。
