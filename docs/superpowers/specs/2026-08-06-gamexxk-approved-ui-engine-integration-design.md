# GameXXK 已确认 UI 引擎接入设计

## 目标

把已经逐页确认的 Master PSD 界面接入 UE 运行时，并保持所有现有交互与动态数据可用。当前批准范围仅包含：

- `01_主菜单`
- `02_城镇HUD`
- `03_主角背包`
- `13_主角背包_物品选中`
- `07_商店交易`（仅新 Meta Shop）

其他 Master 页面不导入、不改运行时布局。

## 权威来源

- 可编辑源稿：`outputs/UI_PSD/Candidates/GameXXK_UI_Master_V1.psd`
- 主菜单构图：Master `01_主菜单`
- 城镇常驻壳体：Master `02_城镇HUD`
- 背包基础态：Master `03_主角背包`
- 背包选中态：Master `13_主角背包_物品选中`
- 新商店：Master `07_商店交易`
- 商品图标：`SourceArt/UI/PSD/gamexxk-v4/calibration-v2/content-manifest.json`

## 视觉规则

### 共用城镇壳体

城镇 HUD、背包和新商店共享相同的主角身份条、五个导航按钮、短资源纸条和城镇背景。身份内容与资源数值保持动态文本；导航按钮保持真实可点击控件。

局外资源只显示元宝图标与永久货币数值。战斗/路线等局内界面继续使用铜钱，不在本次迁移中改动。

### 背包选中态

背包格子选中效果必须复用商店 `07_商店交易/40_ProductGrid/032_selected_selection_ink` 的同一张墨迹图，不再使用 `UIV4_item_slot_selected.png` 或 `T_InventorySlotStates` 作为选中框。

Master page 13 的旧 `44_SelectedInventorySlot` 保留为隐藏 legacy 内容。新的 `39_SelectedSlotInk` 放在 `40_InventorySlots` 后方；首格以商店 170 px 商品卡和 194 x 66 px 墨迹的比例缩放到 110 px 背包格，目标约为 126 x 43 px，格子外扩约 8 px、上移约 16 px。物品本体不复制，继续由 page 03 基础态提供。

`小布袋`、说明文、`分解`、`使用` 属于旧的示例占位文字，不在 PSD 成稿中显示。page 13 的 `46_SelectedItemRuntimeText` 保留为隐藏 legacy 内容；引擎中由真实选中物品与动作状态动态生成文案。

运行时使用同一张透明墨迹切图，选中时显示在格子底图后、物品图标前；详情、使用、分解、强化行为不变。

### 主菜单

主菜单背景使用确认的老虎 Boss 与主角构图。标题和四个按钮继续使用运行时文本/按钮，位置对齐 Master 页面；不把标题和按钮文字烘焙进背景。

### 新商店

仅 `UGameXXKMetaShopWidget` 可用。旧背包商店/`MerchantStockGrid` 不作为城镇商店入口，也不在新商店中创建。

七个商品卡、详情区、购买按钮和确认弹层保留真实控件。商品价格、顶部永久货币和购买按钮都使用元宝图标；装备包价格 100，伙伴包价格 500。商品选择效果与背包使用同一张墨迹贴图。

## 运行时资源策略

新增独立目录 `/Game/GameXXK/UI/MasterV2/Approved`，不覆盖用户手调的旧贴图。导入源放在 `SourceArt/UI/PSD/gamexxk-v4/ui-master/RuntimeApproved`，并用 JSON 清单记录源文件、尺寸、SHA256、目标资源名和用途。

运行时采用组件化贴图与动态 UMG：

- 主菜单：无文字背景、两种墨迹按钮底纹。
- 共用壳体：身份条、头像、短元宝条、元宝图标、五个导航图标/圆底、大纸张面板。
- 背包：装备槽、物品格、滚动条、主角立绘、标签/按钮底纹、选择墨迹。
- 新商店：商品槽、详情槽、选择墨迹、购买按钮底纹、七个既有商品图标。

所有控件坐标以 1920 x 1080 Master 页面为基准，通过 Canvas/锚点保持全屏缩放。

## 行为保持

- 主菜单 `开始游戏` 继续进入 `/Game/GameXXK/Maps/L_QingshanInn` 的既有玩家流程。
- 城镇 HUD 只在城镇显示；进入城镇时不自动打开新商店。
- 背包导航打开自由背包，格子支持滚动并保留 20 个运行时槽位。
- 点击物品刷新选中墨迹、详情与动作；不复制物品图标。
- 城镇商店入口只打开新 Meta Shop；关闭后回到城镇 HUD。
- 新商店购买继续走现有预览、二次确认、扣除永久货币和装备/伙伴生成逻辑。

## 验证策略

纯美术步骤不使用 TDD，使用 PSD 层级、导出尺寸、透明边缘、SHA256、清单和视觉复核验证。

运行时代码按 TDD：先增加会因旧资源路径/旧选择覆盖层/临时商店布局而失败的自动化契约，再最小修改 C++ 使其通过。最终必须完成：

1. 资源清单和 PNG 确定性检查。
2. 目标 Automation tests。
3. UBT 或 `scripts/ue_tdd_pipeline.py` 冷编译；禁用 Live Coding/Hot Reload。
4. UE MCP 保存导入包。
5. PIE 玩家流程截图：主菜单、城镇 HUD、背包基础态、背包首格选中态、新商店及商品选择/确认态。
