# 2D 放置界面实时数值刷新设计

## 目标

运行时数据变化后，当前可见的 2D 放置界面立即显示最新值；玩家不需要关闭、刷新或重新打开背包。刷新不得重建工作台或背包 WidgetTree，不得折叠界面、重置当前角色/页签/滚动位置，也不得中断鼠标悬停。

## 刷新策略

- 使用工作台统一维护的轻量“显示状态快照”。
- 按钮操作成功后立即执行一次差异刷新。
- 挂机进行时每秒执行一次差异刷新，与现有一秒逻辑步长对齐。
- 只刷新当前存在且可见的控件；隐藏页面不做后台更新，玩家打开时直接读取最新运行时数据。
- 只有发生变化的字段才写入控件；战斗血条继续使用现有逐帧视觉更新，不接入重复路径。

## 实时刷新范围

### 挂机条

- 普通/高级宝箱持有数量。
- 两个宝箱按钮的启用状态。
- 宝箱按钮悬停说明中的数量。
- 挂机条悬停说明中的待领取金币、经验、普通宝箱、高级宝箱。
- 普通/高级宝箱 CD，格式保持 `MM:SS`；鼠标持续悬停时也每秒更新。

### 背包与角色

- 当前普通金币。
- 当前可见角色的等级、经验文字、经验条。
- 当前生命、内力、最大生命、最大内力、攻击、防御、速度及装备影响后的结果。
- 主角和永久伙伴读取各自成长数据；任务 NPC 没有独立经验数据时不借用或显示主角经验。
- 背包物品数量、装备槽和选中物品详情在相关数据实际变化时同步更新。

### 仓库与工具

- 当前可见仓库的物品数量、占用格数、页数及翻页按钮状态。
- 工具等级、工具经验、下一级需求、选定合成等级。
- 工具格数量、确认按钮状态及与当前输入有关的说明。

## 组件边界

- `UGameXXKDesktopTrainingWorkbenchWidget` 负责采集运行时快照、判断变化、刷新挂机条/宝箱/金币/仓库/工具等外层控件。
- `UGameXXKInventoryWindowWidget` 提供不重建布局的可见内容刷新入口，负责角色属性、经验条、背包格、装备槽和选中详情。
- 时间型信息只由工作台的一秒节拍驱动；操作型变化由操作成功路径立即触发，并由下一次快照比较兜底。

## 状态与交互保证

- 差异刷新期间保持工作台布局构建次数不变。
- 保持背包展开状态、当前主角/伙伴/NPC、展开的成员列表、属性/装备/卡组页签、仓库页、工具模式、滚动位置、选中物品和悬停状态。
- 控件不存在、页面隐藏或运行时子系统暂不可用时安全跳过；下次控件创建时从真实状态初始化。

## 验证

- 自动化测试先证明：直接修改运行时经验、金币、宝箱和 CD 后，执行实时刷新即可更新现有控件，且布局构建次数与嵌入背包实例不变。
- 覆盖宝箱从 `0` 变为正数及反向变化时的按钮启用状态。
- 覆盖角色升级跨级后经验上限、文字和进度条同步变化。
- 覆盖工具经验、仓库数量和选中详情的可见页面刷新。
- PIE 实测保持鼠标悬停在挂机条上，观察 CD 连续倒计时；等待一次战斗结算，确认金币、经验和宝箱数量无需刷新背包即变化。

## 非目标

- 不新增全局运行时事件总线。
- 不改变奖励、宝箱掉落、CD、升级或战斗数值规则。
- 不通过周期性重建整个工作台解决显示问题。
