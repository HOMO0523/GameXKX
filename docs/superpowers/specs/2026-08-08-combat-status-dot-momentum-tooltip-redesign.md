# 局内状态、DoT、气势与精简 Tooltip 重构设计

Date: 2026-08-08
Status: User approved

## 1. 目标

本设计重构局内战斗状态，使流血、中毒、灼烧和蚀伤具有不同的触发节奏与构筑价值，同时补全气势、虚弱、反击、疗愈增幅、守护和蓄力的真实结算与展示。

目标包括：

- 四种 DoT 不再只是同一套回合末伤害的换名版本。
- 气势成为稳定、直观、无需常规消耗的逐段攻击加伤。
- 虚弱、反击等已有但未完整接线的状态获得可执行规则。
- 蚀骨套装围绕蚀伤和毒爆形成明确的 2/4/6 件闭环。
- 卡牌、怪物、净化和状态层数适配新的伤害节奏。
- 血条下方状态图标保留现有布局，只把 Tooltip 缩短为可快速阅读的真实规则。
- 继续使用已经完成的全局标记规则，不重复实现或削弱它。

本设计覆盖并取代：

- `docs/superpowers/specs/2026-07-17-battle-status-icon-language-design.md` 中关于 Tooltip 内容结构和旧状态语义的部分；该文档的图标美术、色彩与现有布局仍然有效。
- `Source/GameXXK/Private/GameXXKEquipmentSetCatalog.cpp` 中现有蚀骨 2/4/6 件效果描述。

本设计不改变已经确认的血条、状态栏、战斗界面、背包界面或其他 UI 布局。

## 2. 当前问题与根因

### 2.1 四种 DoT 缺少差异

当前流血、中毒、灼烧和 `DamageOverTime` 都被合并进回合结束公式，只是每层系数不同，而且不会在触发后减少。结果是：

- 触发时机相同；
- 玩法决策相同；
- 多段、出牌频率和怪物意图频率无法形成构筑差异；
- Tooltip 必须用很长的文字解释一个实际很单薄的系统。

### 2.2 部分状态只有数据或文字，没有完整行为

状态审计确认：

- `Weak` 会被怪物施加，但没有降低攻击伤害。
- `Counter` 会由豪猪和黑熊叠加，但没有触发或消耗逻辑。
- `Medicine` 只有巨蟾会叠加，且没有任何读取或消费方；它与现有 `NextHealingBonus` 重复。
- `Charge` 的真实倒计时保存在怪物状态中，`Charge` 层数从未产生，因此现有血条图标不可见。
- `Guard` 的真实结算使用守护关系，普通状态层数被规则明确拒绝，因此现有血条图标同样不可见。
- `Momentum` 只供少量条件或消费牌读取，没有用户期望的基础攻击收益。

这些状态主要在一次批量敌人目录导入中加入，但部分运行时消费者没有随目录一起完成。修复应针对权威状态来源和结算边界，而不是只改 Tooltip。

### 2.3 玩家可见术语不统一

当前不同文本路径同时使用：

- 灵动 / 敏捷；
- 破绽 / 易伤；
- 持续伤害 / 蚀伤；
- 免疫破绽 / 易伤免疫；
- 下次攻击强化 / 追击标记。

同一状态在卡牌描述、怪物意图和血条 Tooltip 中不应有多套名称。

## 4. 统一直接攻击管线

每一段直接攻击固定使用以下顺序：

1. 计算攻击倍率；剑意贯虹在这里加入消耗气势带来的倍率。
2. 加入卡牌固定伤害和攻击者当前气势层数。
3. 若攻击者具有虚弱，将这一段总请求伤害乘以 50%，向下取整；原本为正数的攻击最低保留 1 点。
4. 扣除目标防御；防御后最低保留 1 点。
5. 计算目标破绽与标记：破绽每层增加 10%，存在标记固定增加 15%，二者相加后一次计算并向下取整。
6. 由护甲吸收。
7. 扣除气血。

等价公式为：

```text
Requested = floor(Attack * AttackPercent / 100) + CardFlatDamage + MomentumStacks
AfterWeak = HasWeak ? max(1, floor(Requested * 50 / 100)) : Requested
AfterDefense = max(1, AfterWeak - EffectiveDefense)
AfterAmplification = floor(AfterDefense * (100 + 10 * VulnerabilityStacks + MarkBonusPercent) / 100)
HealthDamage = max(0, AfterAmplification - ArmorAbsorbed)
```

其中 `MarkBonusPercent` 在目标有至少 1 层标记时为 15，否则为 0。现有标记规则保持：每段有效命中消耗 1 层标记，标记层数不改变 15% 的固定增幅。

直接攻击包括单体攻击、群体攻击的每个目标、每段多段攻击和反击。DoT、自损、环境伤害不进入该管线。

## 5. 每段攻击的固定事件顺序

每一段攻击按以下顺序完成，下一段不得提前进入：

1. 在攻击前快照目标流血与反击层数。
2. 结算直接攻击。灵动闪避时，本段到此结束。
3. 若目标存活，使用攻击前的流血快照触发流血伤害并减少 1 层。
4. 若目标仍存活，施加本段附带的流血、破绽、标记等状态，并检查蚀骨套装的状态施加钩子。
5. 若目标仍存活且攻击前具有反击，消耗 1 层反击并反击攻击者。
6. 双方仍存活时才继续下一段攻击。

由此保证：

- 本段新施加的流血不会在同一段立即触发。
- 旧流血可能击杀目标并阻止反击。
- 状态施加触发的蚀骨自动毒爆可能击杀目标并阻止反击。
- 反击击杀出牌角色后，剩余攻击段停止。
- 反击不能触发新的反击链。

## 6. 状态规则

### 6.1 气势

- 每层气势使攻击者每一段直接攻击的请求伤害增加 1。
- 单体、多段和群体攻击均逐段、逐目标获得完整气势加值。
- 常规攻击不消耗气势。
- 气势不会自动衰减。
- 只有明确写明消费气势的卡牌或怪物的正面状态驱散能够移除气势。
- 不设置玩法层面的叠层上限，只做 `int32` 饱和保护。

现有每次获得 1–2 层气势的生产牌保持原数值。

### 6.2 虚弱

- 只要攻击者具有至少 1 层虚弱，其全部直接攻击伤害固定降低 50%。
- 多层虚弱代表持续回合，不叠加减伤百分比。
- 单体、多段、群体和反击都受虚弱影响。
- DoT、自损、反射和环境伤害不受虚弱影响。
- 单位所属阵营回合结束时减少 1 层。
- 保持现有 5 层上限。
- 敌我双方使用同一规则。

### 6.3 流血

- 每次受到一段未被灵动闪避的直接攻击后，使用攻击前流血层数造成等量生命伤害，然后减少 1 层。
- 护甲完全吸收直接攻击仍属于有效命中，会触发流血。
- 多段攻击逐段触发。
- 新施加的流血不触发当前这一段攻击。
- 回合结束不触发、不减少。
- 不设置玩法层面的叠层上限。

### 6.4 中毒

- 在中毒单位所属阵营回合结束时，造成等同当前层数的生命伤害，然后减少 1 层。
- 每个单位每次所属阵营回合结束只触发一次。
- 不设置玩法层面的叠层上限。

### 6.5 灼烧

- 玩家角色的一张牌完整结算后，若该出牌角色具有灼烧，则造成等同当前层数的生命伤害，然后减少 1 层。
- 怪物的一张意图完整结算后，若该意图来源怪物具有灼烧，则执行同一规则。
- 多段攻击意图只在整个意图结束后触发一次灼烧，不按攻击段数触发。
- 行动中刚获得的灼烧可以在该行动结束时触发；这允许炎墙、焰幕护体等反应式灼烧惩罚本次完整行动。
- 单位所属阵营回合结束时再减少 1 层，但回合结束本身不造成灼烧伤害。
- 被拒绝、取消或未提交的牌/意图不触发灼烧。
- 不设置玩法层面的叠层上限。

### 6.6 蚀伤

- 流血、中毒或灼烧每次实际造成伤害时，额外造成等同当前蚀伤层数的生命伤害。
- 每个流血、中毒或灼烧伤害包分别读取完整蚀伤层数。
- 蚀伤不会触发自身。
- 蚀伤不会因增幅其他 DoT 而减少。
- 单位所属阵营回合结束时减少 1 层。
- 毒爆不直接引爆或减少蚀伤。
- 不设置玩法层面的叠层上限。
- 蚀伤不由卡牌、阵法、路线牌或怪物直接施加，只由蚀骨装备套装提供。

### 6.7 DoT 共同伤害属性

流血、中毒、灼烧和蚀伤造成的生命损失：

- 跳过防御、护甲、灵动、守护和代挡；
- 不受破绽、标记、气势或虚弱影响；
- 不触发反击；
- 仍然产生带有明确原因的伤害审计结果，用于演出、遗物和模拟统计。

### 6.8 毒爆

毒爆是一个明确的战斗事件，不是普通直接攻击。

结算规则：

1. 同时快照目标流血、中毒和灼烧的当前层数。
2. 按固定顺序流血、中毒、灼烧分别产生一个伤害包；层数为 0 的类型跳过。
3. 每个伤害包造成等同该类型快照层数的生命伤害，并分别获得一次当前蚀伤层数的额外伤害。
4. 每种被引爆且层数大于 0 的状态减少 1 层。
5. 蚀伤不被直接引爆或减少。

示例：目标有流血 4、中毒 3、灼烧 2、蚀伤 2。毒爆造成：

```text
流血 4 + 中毒 3 + 灼烧 2 + 蚀伤 2 * 3 = 15
```

结算后为流血 3、中毒 2、灼烧 1、蚀伤 2。

毒爆对三个 DoT 的减少是一个原子提交。即使目标在其中一个伤害包后气血归零，本次毒爆中其余快照与层数减少仍完成；最终气血伤害按剩余气血截断。

### 6.9 疗愈增幅

- 下一次由该单位发起的治疗动作中，每个治疗目标的治疗量增加等同疗愈增幅层数的固定值。
- 一次治疗动作只读取一次层数，并在开始结算该动作时清空全部层数。
- 群体治疗的每个目标都获得完整固定加值。
- 敌我双方使用同一规则。

### 6.10 反击

- 敌人存活且受到玩家牌的一段有效直接攻击后，使用当前攻击力的 100% 反击该牌的出牌角色，然后减少 1 层。
- 护甲完全吸收仍触发反击；灵动闪避不触发。
- 多段攻击可依次触发并消耗多层反击。
- 流血、中毒、灼烧、蚀伤、毒爆、自损和其他反击不触发反击。
- 反击属于直接攻击，因此经过气势、虚弱、防御、破绽、标记、护甲、灵动、守护和代挡的正常管线。

### 6.11 守护

- 守护的权威数据继续使用 `GuardLinks`，不复制普通 `Guard` 状态层数。
- 守护图标显示在受护者血条下方，而不是守护者血条下方。
- 图标层数为当前所有有效守护关系指向该受护者的剩余次数总和。
- 一次针对受护者的单体攻击触发一条规则选中的守护关系并使总显示层数减少 1。
- 守护者或受护者倒下时，相应关系和展示立即消失。

### 6.12 蓄力

- 蓄力的权威数据继续使用怪物状态中的 `PendingChargedIntentId` 和 `ChargeRoundsRemaining`。
- 血条下方仍显示蓄力图标，但只从权威倒计时投影，不写入第二份普通状态数据。
- 图标数字等于剩余蓄力回合。
- 倒计时归零、已准备意图执行、怪物死亡或蓄力被系统取消时，图标消失。
- 普通正面状态驱散不能移除蓄力；未来若要提供“打断蓄力”，必须使用显式规则。

## 7. 叠层与存档兼容

- 流血、中毒、灼烧、蚀伤和气势不再受玩法层面的状态上限限制。
- 所有加层使用饱和整数运算，最大保留 `MAX_int32`，禁止溢出回绕。
- 其他状态继续使用各自现有上限，除本设计明确修改者外不扩大。
- 血条图标数字超过 99 时显示 `99+`；Tooltip 的“层数”显示真实整数。
- 不删除、不重排 `EGameXXKCardStatus` 的既有数值。
- `Medicine = 20` 保留为隐藏的旧存档兼容值，但新数据、卡牌和意图不能再产生它。
- 载入含 `Medicine` 的活动战斗时，每 1 层旧药材迁移为 6 层 `NextHealingBonus`，随后清除旧药材。
- `Guard` 与 `Charge` 保留为展示键，不作为可被普通 `AddCombatStatus` 写入的第二份权威数据。

## 8. 卡牌调整

### 8.1 流血牌

| 卡牌 | 新效果 |
| --- | --- |
| 封喉 | 90% 攻击，施加流血 4（原 2） |
| 残月三叠 | 70% 攻击 ×3 保持；整张牌攻击结束后总计施加流血 6（原 3） |
| 断脉矢 | 110% 攻击，施加流血 6（原 3） |

浪断及其他“目标具有流血”条件牌保持条件数值。它们先读取出牌开始时的条件快照获得奖励，再由直接命中触发既有流血。

流血的轻、中、重施加量以 4/6/8 为设计尺度；群体或多段牌通常按目标或整张牌降低一个档位，避免每一段重复施加重档流血。

| 百草毒 | 3 |

| 蛊雾迷踪 | 4，另施加标记 1 |

中毒的轻、中、重施加量以 2/3/4 为设计尺度。

### 8.3 灼烧牌

| 卡牌 | 层数或规则 |
| --- | --- |
| 灵火符 | 灼烧 3（原 2） |
| 凝焰成刃 | 灼烧 3（原 1） |
| 炎墙、焰幕护体 | 反应式灼烧 2 保持；可在本次完整行动结束时惩罚攻击者 |
| 离火印、焚脉符 | 灼烧 3 保持 |
| 星火燎原 | 群体灼烧 3 保持 |

| 焚天诀、赤焰封界 | 群体灼烧 4 保持 |

摄灵火、星火回收等明确消费灼烧的卡牌继续保留主动兑现玩法。灼烧的轻、中、重施加量以 3/4/5 为设计尺度。

### 8.4 腐骨散与毒爆

腐骨散改为：

1. 对目标施加中毒 2。
2. 对目标执行一次毒爆。

删除旧的中毒 5 与破绽 1，不直接施加蚀伤。

若穿戴蚀骨套装并满足 4 件条件，允许以下顺序：

1. 腐骨散施加中毒 2。
2. 蚀骨 2 件为该目标施加蚀伤 1。
3. 蚀骨 4 件自动毒爆一次。
4. 腐骨散自身再毒爆一次。

两次毒爆都必须执行；4 件自动毒爆仍受每名穿戴者每回合一次限制。

### 8.5 气势消费牌

#### 剑意贯虹

- 基础为 200% 攻击。
- 消耗出牌者全部气势。
- 每消耗 1 层，使本次攻击倍率额外增加 20 个百分点。
- 本次攻击仍读取消费前气势快照，获得正常的每层 +1 固定伤害。
- 完全删除旧的“每层恢复 4 内力”效果。

若消费 `N` 层，攻击倍率为 `200% + 20% * N`，再加 `N` 点气势固定伤害。

#### 刀意收束

- 保持最多消费 3 层气势。
- 每消费 1 层恢复 3 内力并抽 1 张牌。

除这两张明确写明消费的牌和怪物驱散外，气势不被攻击自动消耗。

## 9. 蚀骨套装重构

旧的“层数提高 5% / 混合 DoT 额外 80% / 回合末无消耗额外结算”全部替换。

### 9.1 两件套

`穿戴者使用一张牌时，该牌首次对一个目标施加流血、中毒或灼烧后，同时施加1层蚀伤。每张牌对每个目标最多触发一次。`

- 同一张多段牌反复给同一目标施加状态，只增加 1 层蚀伤。
- 群体牌可对每个目标各增加 1 层蚀伤。
- 标记、破绽、虚弱、蚀伤本身或其他负面状态不能触发两件套。

### 9.2 四件套

`每名穿戴者每回合首次新施加流血、中毒或灼烧，并使目标同时具有这三种状态中的至少两种时，自动毒爆一次。`

- “新施加的状态”必须是流血、中毒或灼烧。
- 目标原有状态可参与“至少两种”的判断。
- 标记、破绽、虚弱、蚀伤或其他减益的施加不能触发。
- 一次不满足条件的施加不会消耗本回合机会。
- 每名穿戴者独立记录机会；多人穿戴互不共享。

### 9.3 六件套

`每名穿戴者每回合第一次发动的毒爆不会减少目标的流血、中毒和灼烧层数。`

- 自动毒爆或卡牌显式毒爆都可以成为第一次。
- 第一次毒爆仍造成全部伤害，蚀伤也正常逐包增幅。
- 本回合后续毒爆恢复每种 DoT 减少 1 层的正常规则。
- 每名穿戴者独立记录。

蚀骨套装的每回合记录在玩家回合开始时重置，并按稳定 `UnitId` 归属到实际穿戴者。

## 12. 行动结束、回合结束与胜负

### 12.1 行动结束

- 一张玩家牌的全部攻击、附加状态、套装钩子、流血和反击队列结束后，才触发出牌角色的灼烧。
- 一个怪物意图的全部效果结束后，才触发意图来源怪物的灼烧。
- 灼烧及其蚀伤增幅属于同一行动队列。

### 12.2 所属阵营回合结束

对该阵营每个仍存活单位按稳定顺序：

1. 中毒造成层数伤害，蚀伤追加伤害，中毒 -1。
2. 灼烧只 -1，不造成回合末伤害。
3. 蚀伤 -1。
4. 虚弱 -1。
5. 流血不变化。

### 12.3 终局规则

胜负只在完整触发队列结束后判断：

- 敌方全部死亡：玩家胜利。
- 双方同时全部死亡：玩家胜利。
- 仅玩家队伍全部死亡且仍有敌人生存：玩家失败。
- 双方均有存活单位：继续战斗。

不得在直接攻击、流血、毒爆、反击或灼烧的中间步骤提前提交终局并丢弃同一队列的后续事件。

## 13. 权威状态与事件架构

### 13.1 状态来源

- 普通真实状态继续存储在 `FGameXXKCardCombatUnit::Statuses`。
- 守护只以 `GuardLinks` 为权威来源。
- 蓄力只以 `FGameXXKEnemyBattleState` 的蓄力字段为权威来源。
- UI 投影可以生成守护和蓄力的只读徽标，但不得把投影写回规则状态。

### 13.2 事件队列

规则层应建立统一、非递归的状态事件队列，至少能表达：

- 一段直接攻击完成；
- 状态施加完成；
- 玩家牌完成；
- 怪物意图完成；
- 所属阵营回合结束；
- 毒爆请求；
- 治疗动作；
- 终局检查。

每个事件需要携带足够的稳定上下文：

- 来源单位 `UnitId`；
- 目标单位 `UnitId`；
- 来源牌或怪物意图 ID；
- 是否为直接攻击、反击、DoT 或毒爆；
- 穿戴蚀骨套装的实际角色 `UnitId`；
- 本牌/本回合已触发的每目标、每穿戴者标记。

DoT、毒爆和反击不得通过无界递归调用彼此。队列必须有显式事件种类和禁止边，保证：

- 蚀伤不触发蚀伤；
- 反击不触发反击；
- 毒爆不直接引爆蚀伤；
- 灼烧的行动结束事件不会再次生成同一行动结束事件。

### 13.3 原子提交

整张牌、整个怪物意图和单次回合边界在临时运行时副本上结算：

- 所有校验和事件成功后一次提交；
- 任一步失败时保留进入动作前的手牌、费用、气血、护甲、状态、套装计数和意图；
- 不允许出现已扣费用但未结算、已减 DoT 但未伤害、或只完成毒爆一部分的状态。

### 13.4 审计结果

每个伤害结果必须能区分：

- 普通直接攻击；
- 反击；
- 流血；
- 中毒；
- 灼烧；
- 蚀伤追加；
- 毒爆来源的各 DoT 包；
- 自损或环境伤害。

审计应记录请求伤害、气势加值、虚弱减值、防御后伤害、破绽/标记增幅、护甲吸收、生命伤害、DoT 快照、蚀伤加值和消费层数，供测试、战斗演出和模拟分析复用。

## 15. TDD 与验证

### 15.1 红绿顺序

实现必须按可独立审查的规则切片进行：

1. 先写最小失败自动化测试并亲眼确认预期 RED。
2. 只实现该切片的最小生产改动。
3. 冷 UBT，禁止 Live Coding 和 Hot Reload。
4. 精确运行该切片自动化过滤器并确认 GREEN。
5. 运行相关既有测试组，确认没有回归。
6. 完成调用链与差异自审后再进入下一切片。

### 15.2 规则测试矩阵

至少覆盖：

- 气势：单段、多段、群体、剑意贯虹快照、刀意收束消费、虚弱顺序、饱和叠层。
- 虚弱：敌我对称、每段 -50%、层数不叠加百分比、回合末 -1、DoT 不受影响。
- 流血：直接命中、护甲全吸收、灵动闪避、多段逐次、新流血不触发同段、回合末不衰减。
- 中毒：所属阵营回合末伤害、蚀伤追加、伤害后 -1。
- 灼烧：玩家牌、怪物意图、多段只触发一次、行动中新施加、回合末只 -1。
- 蚀伤：三种 DoT 分别触发、不触发自身、不随触发减少、回合末 -1。
- 毒爆：单一/混合状态、固定顺序、蚀伤逐包、每种 -1、蚀伤不减、目标中途死亡、六件套免减层。
- 反击：直接命中、护甲全吸收、灵动闪避、多段多层、击杀攻击者、禁止反击链。
- 疗愈增幅：单体、群体、玩家、怪物、清空时机、旧药材迁移。
- 守护：受护者投影、多人守护总层数、链接消费、单位死亡清理。
- 蓄力：开始、递减、归零执行、存档恢复、死亡清理、普通驱散无效。
- 终局：玩家胜、玩家败、DoT/反击/灼烧导致双方同时死亡时玩家胜利。

### 15.3 数据测试

卡牌目录和怪物目录测试必须锁定第 8、10、11 节的全部数值与效果顺序。蚀骨套装测试必须覆盖：

- 两件套每牌每目标只加一次蚀伤；
- 群体每目标独立；
- 四件套只由新施加的流血/中毒/灼烧触发；
- 不满足条件不消费本回合机会；
- 多名穿戴者各自计数；
- 六件套第一次毒爆不减层；
- 腐骨散在满足条件时连续两次毒爆。

### 15.4 UI 与文本测试

- 所有可见状态名称与表中精确文案一致。
- Tooltip 只包含名称、真实层数和一句规则，不再出现“效果：”“时机：”。

## 16. 验收标准

本设计对应实现完成时：

- 四种 DoT 使用不同触发节奏，且所有消耗/衰减符合本规格。
- 气势逐段加伤，普通攻击不消耗；剑意贯虹与刀意收束是明确例外。
- 虚弱、反击、疗愈增幅、守护和蓄力都有真实行为与真实显示。
- 药材不再作为独立状态存在于新战斗。
- 蚀骨 2/4/6 件全部具有运行时效果，并通过多人穿戴与双毒爆测试。
- 所有指定卡牌、怪物和净化数值与本规格一致。
- 双方同时死亡判定玩家胜利。
- Tooltip 使用确认后的精简文案和统一术语。
- 当前 UI 布局、用户调整资产、地图、相机和 PaperZD 内容未被改动。
- 冷 UBT、精确测试、相关测试组、完整模拟和真实流程验证均有新鲜证据。

## 17. 非目标与后续工作

本规格不包含：

- 改动已经确认的当前 UI 布局；
- 新建天赋、称号或其他页面、页签；
- 按背包模板实现尚未开放的天赋与称号系统；
- 阵师卡牌在错误地形下的基础效果和正确地形强化；该项在本规格实施后继续单独设计与验证；
