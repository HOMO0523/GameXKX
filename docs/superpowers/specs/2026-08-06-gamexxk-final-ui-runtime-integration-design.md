# GameXXK 最终确认 UI 运行时接入设计

## 1. 目标与权威来源

本轮把用户已经在 Master PSD 中确认并手工校正的界面接入 UE 5.8 运行时。接入后，界面不是静态效果图，而是由真实贴图组件、动态文本和可交互 UMG 控件组成；所有按钮、页签、格子、滚动、装备、卡组、伙伴切换和关闭行为均连接现有游戏状态。

美术权威源为：

- `outputs/UI_PSD/Candidates/GameXXK_UI_Master_V1.psd`
- 当前保存基线 SHA256：`7c0ceefde6ae59ea4dbcea03a9796f5c8556beb72cf0ddec39f59a7e8918339f`
- 保存前安全备份：`outputs/UI_PSD/Candidates/Backups/GameXXK_UI_Master_V1.before-user-final-ui-20260806-152859.psd`

辅助确认资源：

- 卡牌底、锁状态和命名：`SourceArt/UI/PSD/gamexxk-v4/ui-master/ManualEditing/CardDeckKit`

- 六职业伙伴正常/未出战头像：`SourceArt/UI/PSD/gamexxk-v4/ui-master/ManualEditing/PartnerSwitchPortraits`

## 2. 接入原则

### 2.1 采用组件化 UMG，不采用静态热区

选择：继续使用现有 C++ 程序化 UMG Widget，把 PSD 拆成无文字组件贴图并替换布局与资源路径。

不采用以下方案：

- 整页截图加透明点击热区：动态数据、滚动、Tooltip、分辨率适配和输入焦点均不可维护。
- 新建一套完全独立的 Blueprint Widget：会复制现有 C++ 规则入口，使主角装备、伙伴装备和卡组状态出现双份逻辑。

### 2.2 视觉层与规则层分离

- PSD 决定纸张、墨迹、槽框、箭头、卡底、图标、坐标和视觉层级。
- C++/Subsystem 决定物品、装备实例、角色数据、卡组、货币和输入结果。
- 运行时文字不烘焙到背景。角色名称、等级、战力、货币、背包计数、卡名、费用和 Tooltip 均为动态文本。
- 选中态复用商店已确认的同一张墨迹贴图，放在格子底图后、图标前。

### 2.3 不覆盖用户手调资源

新切图进入独立源目录 `SourceArt/UI/PSD/gamexxk-v4/ui-master/RuntimeApproved`，UE 资源进入 `/Game/GameXXK/UI/MasterV2/Approved`。不覆盖角色帧、PaperZD、关卡、摄像机和手调 HD2D 平面。

## 3. 共用城镇壳体与导航

城镇 HUD、主角背包、伙伴背包、新商店、任务日志和系统菜单共享：

- 左上主角身份条与真实头像。
- 左侧五个真实导航按钮。
- 右上短资源纸条。
- 右上统一黑色墨迹圆底、粗白色 `X` 关闭按钮。
- 同一城镇背景。

导航行为：

| 控件 | 结果 |
| --- | --- |
| 背包 | 打开主角背包，其他互斥窗口关闭 |
| 伙伴 | 直接打开伙伴背包，不打开图鉴 |
| 任务 | 打开任务日志 |
| 系统/卷轴 | 打开系统菜单 |
| 地图 | 打开路线地图 |
| `X` | 关闭当前窗口并返回城镇 HUD |

图鉴本轮不做：不删除底层存档字段和既有测试夹具，但玩家导航中不创建图鉴入口，也不会因伙伴按钮误开图鉴。

新商店是唯一可用商店；旧 `MerchantStockGrid`/旧交易面板不可从城镇流程到达。进入城镇时所有大窗口默认关闭，不能自动打开商店。

货币规则：

- 局外（城镇、背包、新商店）显示元宝。
- 局内（路线、战斗、奖励）显示铜钱。
- 通关结算展示局内铜钱按既有兑换比例换算为局外元宝的关系。

## 4. 主角背包

### 4.1 页面与标签

标题显示 `主角`。顶部标签为：

- `属性`
- `装备`
- `卡组`
- `天赋`
- `称号`

本轮可用状态：

- `属性`：显示主角动态属性。
- `装备`：显示六装备槽、主角立绘、背包与物品 Tooltip。
- `卡组`：把右侧装备背包切换为卡组背包/角色卡组。
- `天赋`、`称号`：保留真实按钮和选中反馈；若当前规则系统没有数据，显示统一的 `尚未开放` 内容，不创建伪造天赋或称号数据。

### 4.2 六装备槽

稳定顺序与位置：

1. 武器
2. 头部
3. 衣甲
4. 腰带
5. 鞋
6. 饰品

读取和修改必须使用实例制装备接口：

- `GetEquipmentWarehouseSnapshot`
- `GetEquipmentLoadoutSnapshot(CharacterId, ...)`
- `EquipEquipmentInstance(CharacterId, Slot, InstanceId, ...)`
- `UnequipEquipmentSlot(CharacterId, Slot, ...)`

旧的 `EquippedWeapon/Armor/Accessory` 三槽镜像只保留兼容，不再作为新 UI 的权威读取入口。

### 4.3 背包与鼠标行为

- 每页显示 4 列 x 5 行，共 20 个格子。
- 右侧使用 `inventory_scrollbar_Button` 对应的真实滚动条。
- 左键物品：选中格子，显示同一张选中墨迹并刷新 Tooltip/动作按钮。
- 右键背包内的装备实例：立即装备到当前角色；若该槽已有装备，底层事务自动把旧装备放回仓库。
- 右键装备槽：立即卸下该槽装备并放回仓库。
- 右键非装备物品：不误用、不误分解，保持选中状态。
- 仓库已满、路线锁定或事务失败：不改变状态，并在当前窗口显示底层返回的中文原因。
- 成功装备/卸下后：六槽、背包、Tooltip、选中态和属性数值同帧刷新。

`分解` 为背包底部真实按钮：仅对允许分解的仓库装备启用，并继续走现有二次确认和装备经济事务。

## 5. 伙伴背包

### 5.1 基础结构

伙伴背包复刻主角背包的结构与操作：

- 同样的六装备槽。
- 同样的 20 格装备/道具仓库、筛选、滚动和 Tooltip。
- 同样的左键选中、右键装备、右键卸下。
- 装备目标 CharacterId 是当前选中的永久伙伴实例，而不是主角。

标题显示 `伙伴`。没有伙伴时角色区域显示空状态，装备和卡组修改不可用，但窗口、页签和关闭按钮保持可操作。

### 5.2 伙伴切换条

- 主角页不显示伙伴切换条。
- 伙伴页底部显示 3 个头像槽，左右各一个无横画的双笔墨迹 `<`/`>`。
- 永久伙伴容量固定 12 人，共 4 页，每页 3 人。
- 打开伙伴背包时自动定位到当前出战伙伴所在页；若没有出战伙伴，则定位到首个已拥有伙伴。
- 空位置保持空槽，不能生成占位角色。
- 拥有但未出战：使用 `_inactive` 灰暗头像。
- 当前唯一出战伙伴：使用正常亮色头像。
- 悬停头像显示角色名称。
- 点击已拥有伙伴：立即把它设为当前选中且唯一出战伙伴；不再提供单独的 `出战` 按钮。
- 左右箭头只翻页，不改变出战伙伴。

### 5.3 遣散/满员替换

按钮在伙伴页面显示 `遣散`，不显示 `分解`。

- 名册不足 12 人时禁用。
- 名册满 12 人但没有伙伴包产生的待入队候选时禁用，并通过悬停/状态文案说明需要待入队伙伴。
- 名册满 12 人且存在待入队候选时启用；点击后以当前选中伙伴为替换对象，走现有 `ResolvePendingPermanentCompanionReplacement` 原子事务。
- 若被替换者是当前出战伙伴，新伙伴继承唯一出战位。
- 事务拒绝时保持状态并显示底层原因，不自行吞掉装备、经验或候选人。

这样保持之前确认的“只在 12 人满员时可遣散当前伙伴”，同时不引入脱离伙伴包流程的任意删除入口。

## 6. 卡组页签

### 6.1 两个卡组视图

点击 `卡组` 后，右侧装备背包区域替换为：

- `卡组背包`：当前角色拥有的 12 张个人牌，含已解锁/未解锁状态。
- `角色卡组`：当前编入牌组；主角固定 8 张，伙伴固定 5 张。

左右切换控件使用 PSD 中的：

- `deck_switch_left_Button`
- `deck_switch_right_Button`
- `deck_view_title_Text`

左右按钮只在上述两个视图之间切换，不切换角色。角色切换仍由伙伴页底部三槽和分页箭头完成。

### 6.2 卡牌呈现

共用卡牌组件：

- `card_frame_base_PSD057`
- `card_portrait`
- `card_name_Text`
- `card_cost_Text`
- `card_state_Text`
- `card_state_selected_ink`
- `card_state_locked_overlay`
- `card_state_locked_icon`

职业色只用于信息条，不整体染色卡框：

| 类型 | 色值 |
| --- | --- |
| 主角 | `#F1E4CC` |
| 刀客 | `#B6483F` |
| 护卫 | `#254D4D` |
| 医师 | `#5A936D` |
| 猎手 | `#9A6833` |
| 术士 | `#40518D` |
| 阵师 | `#806279` |
| 任务 NPC | `#252321` |
| 路线/通用 | `#E1D3B8` |

未解锁卡保留宣纸卡框，叠加 `#4E4B45`、约 42% 的正片叠底暗层和简化水墨锁图标，不显示成纯黑矩形。

### 6.3 卡组交互

- 悬停卡牌显示现有纸片组件组合的 Tooltip。
- 左键已解锁卡：在卡组背包/角色卡组之间编入或移出，并更新选中墨迹。
- 未解锁卡可查看 Tooltip，但不能编入。
- 主角只有 8 张合法编入时才能提交。
- 伙伴只有 5 张合法编入时才能提交。
- 路线开始后的只读锁保持：可以查看，不能修改。
- 切换角色时，卡组区域立即刷新到该伙伴自己的 12 张池和 5 张编入牌。

## 8. 输入、焦点和互斥规则

- 城镇大窗口互斥：同一时间最多显示背包、伙伴、任务、商店、系统中的一个。
- `Escape` 优先关闭最上层确认框/Tooltip/窗口，不离开城镇。
- 鼠标右键只在背包装备格和装备槽上触发快速装备事务，不穿透到世界输入。
- 关闭窗口后恢复城镇输入；商店确认框开启时保持模态锁。
- 所有可点击控件都必须有 Normal/Hovered/Pressed/Disabled 状态或明确的可见反馈。

## 9. 验证与验收

### 美术资源

- 每个切图记录源层、尺寸、Alpha bounds、SHA256 和 UE 目标路径。
- 检查透明边缘、空像素、文字烘焙、重复图标和裁切。
- 对主角背包基础态、选中态、卡组态和伙伴组合态生成确定性预览。

### 运行时代码

先写失败测试，再做最小实现：

- 主角/伙伴六槽读取。
- 右键装备自动替换。
- 六槽右键卸下。
- 4 x 5 背包和右滚动条。
- 主角卡组 12/8、伙伴卡组 12/5、未解锁状态。
- 伙伴 4 页 x 3、默认出战页、点击即唯一出战。
- 满员待入队时 `遣散`/替换。
- 伙伴导航不打开图鉴。
- 所有窗口互斥与 `X`/Escape 关闭。
- 新商店唯一入口、进入城镇不自动开商店。

最后必须使用 UBT 或 `scripts/ue_tdd_pipeline.py` 冷编译，不能用 Live Coding/Hot Reload；在真实 PIE 中完成主菜单 → 城镇 → 主角背包 → 伙伴背包 → 卡组 → 新商店 → 路线 → 战斗 → 奖励的点击验证，并保存截图与探针 JSON。
