# 青山镇序章马车预览设计

**日期：** 2026-08-31
**状态：** 用户逐段确认，待实施
**默认入口：** `/Game/GameXXK/Maps/L_DesktopTrainingHUD` 展开 Workbench → `剧情`
**演出地图：** `/Game/GameXXK/Maps/Prototype/L_Qingshan_AsianVillage_Demo`

## 1. 目标与交付边界

本轮只交付一个可重复播放、可由玩家目视验收的 3D 城镇马车闭环：

```text
点击剧情按钮
→ 加载青山镇
→ 固定剧情镜头
→ 马车驶入并停车
→ 主角在车前出现
→ 停留 2 秒
→ 马车从主角后方继续驶离
→ 恢复正常镜头与城镇操作
```

该闭环是后续新手引导的前置演出，不代表完整序章结束。当前版本不启动 Guide，不显示“序章已完成”，不写剧情、任务或引导进度。马车表现经用户验收后，后续引导以独立规格从“恢复城镇操作”事件继续，不回写马车内部状态机。

## 2. 对既有设计的局部裁决

本规格只在“剧情按钮行为”和“马车开场”范围内覆盖下列旧规则：

- `2026-08-30-story-quest-button-placeholder-design.md` 中 action `654` 永久无动作的规则被替换；按钮由占位控件升级为马车预览入口。
- `2026-08-29-desktop-2d-narrative-task-drawer-design.md` 中默认剧情不进入 3D 城镇的规则，不适用于本次用户明确选择的马车预览入口。项目默认启动面仍是纯 2D `L_DesktopTrainingHUD`，普通启动和普通 Workbench 不自动加载 3D 城镇。
- `2026-08-28-generic-dialogue-tutorial-shop-design.md` 中独立马匹、主角命名、马车完成后直接推进剧情进度的规则，不适用于本切片。

本规格不恢复旧任务抽屉、旧 QuestDialog、临时 NPC 支援、命名界面或任何已退役剧情耦合。

## 3. 玩家流程

1. 玩家展开 Workbench 并点击现有 `剧情` 按钮。
2. 按钮发出语义化“请求播放马车预览”事件；Widget 自身不负责地图加载或玩法状态修改。
3. PlayerController 使用现有城镇目标地图执行绝对地图切换，并附带一次性 travel option：`GameXXKIntro=CarriagePreview`。
4. 青山镇正常创建唯一主角；马车 Rig 检测到 option 后暂时隐藏、冻结主角，并切换到自己的固定摄像机。
5. 马车从停车点的镜头左侧约 400 Unreal 单位处出现，播放“行驶到停车”动画并移动到停车点。
6. 到站时切换停车待机动画；主角被移动到 Rig 的车前出现点并立即显示。
7. 马车与主角共同停留 2 秒。
8. 马车复用行驶帧段，沿原方向继续移动，从主角视觉后方经过并驶出镜头右侧。
9. 马车到达驶离点后隐藏，Rig 恢复正常城镇镜头、主角碰撞、移动与交互输入。
10. Rig 广播一次运行时完成事件。本切片不绑定 Guide 或剧情进度处理器。

每次从桌面点击 `剧情` 都直接完整重播，不显示“是否重播”确认框。普通 `进入城镇` 不携带 travel option，因此不会播放马车。

## 4. 解耦架构

### 4.1 Workbench 入口

`StoryQuestButton` 保持现有尺寸、位置、仓库打开时的平移规则、原生命中区和按压表现。action `654` 不直接调用 `OpenLevel`，而是触发一个专用 delegate。PlayerController 负责：

- 拒绝重复地图切换请求；
- 复用现有 town-travel pending 保护；
- 构造带一次性 option 的青山镇 URL；
- 在切换失败时恢复按钮可用状态。

该路径禁止修改挂机条折叠、游历计时、宝箱、重试、编队、任务、奖励或 Narrative/Guide 存档。

### 4.2 青山镇演出 Rig

青山镇只新增一个独立、默认休眠的 `AGameXXKPrologueCarriageRig`。Rig 集中拥有：

- 固定剧情 `CameraComponent`；
- `CarriageStart`、`CarriageStop`、`CarriageExit` 场景标记；
- `HeroReveal` 车前出现标记；
- 单一世界空间 HD2D 马车显示组件；
- 马车动画播放器、位移曲线与 2 秒停留计时；
- 主角状态快照、隐藏/显示、冻结/恢复和镜头交接；
- 完成、取消和故障安全清理。

Rig 的停车标记与主角出生点对齐。2026-08-31 玩家在真实 PIE 中明确选择新的安全站位 `(16678.592, 5270.000, 1075.711)`，因此该位置同时成为 `PlayerStart` 与 Rig 根节点的新权威锚点，保留 `Yaw=0`。它覆盖最初“不得移动 PlayerStart”的保护，但只授权这一组精确校准；NPC、出口、建筑、旧相机、PaperZD/Flipbook 和其他 HD2D 平面仍禁止移动。起点继续位于停车点的镜头左侧 400 Unreal 单位，驶离点继续位于同方向 800 Unreal 单位处。

Rig 在没有 `GameXXKIntro=CarriagePreview` 时保持隐藏、无 Tick、无输入 token、无碰撞，对普通青山镇流程没有行为影响。它最多接受一次启动；同一地图实例内的重复调用必须幂等拒绝。

### 4.3 主角所有权

普通城镇出生系统仍创建唯一主角。Rig 不生成第二个 Pawn，而是在开始时记录并暂时修改：

- Actor 显隐；
- 碰撞与 Movement 状态；
- PlayerController 输入模式；
- 当前 ViewTarget；
- 交互可用状态。

停车时，现有主角移动到 `HeroReveal`，以车前位置显示。驶离结束或任何失败路径均通过同一幂等清理函数恢复正常城镇状态。

### 4.4 后续引导接缝

Rig 结束时只发送一次无存档副作用的语义事件，例如 `Tutorial.CarriagePreview.Completed`。当前没有消费者。后续引导可以订阅该事件并启动第一步 Guide；重播策略、首次引导和 Guide 存档由后续规格定义，马车 Rig 不读取 Guide 状态。

## 5. 马车资源与表现

只使用现有马车资源，不叠加独立马匹图集：

- `/Game/GameXXK/Cinematics/Prologue/Atlases/T_cinematic_carriage_run_stop_2k_atlas`
- `/Game/GameXXK/Cinematics/Prologue/Atlases/T_cinematic_carriage_post_stop_idle_2k_atlas`
- 同名 1K 资源仅作低清回退。

两套图集均为 8×8、60 帧、约 14.8515 FPS、4.04 秒，采用底部中心锚点。运行时直接消费图集，不批量替换或重导入现有贴图，也不修改源动画资产。

世界空间显示使用不受场景光照染色的透明 HD2D 平面，并保持面向固定剧情镜头。马车与主角同时显示时，通过实际镜头深度和稳定的半透明排序保证马车从主角后方经过，不用方向向量修改位置。

马车移动标记使用角色胶囊根高度，显示平面必须在每个移动样本上额外应用 `Z=-72` 接地偏移；不得在 `SetWorldLocation` 时丢失该偏移。现有马车源图朝左，而演出路径为画面左→右，因此只在 `UImage` 中以中心 Pivot 做水平镜像，不反转世界移动方向。

动画策略：

- 驶入使用完整 `run_stop` 帧序列，位移终点与最后停车帧对齐；
- 停车后切换 `post_stop_idle` 并循环；
- 驶离复用经逐帧视觉核定的行驶帧子区间并循环，到达镜头外驶离点后立即隐藏；
- 不允许在画面内播放第二次停车；
- 当前切片不增加音效、对白、取名 UI 或引导 UI。

马车图集当前是隔离的序章候选资源。用户已在本设计会话中明确选择使用该马车图集；实施仍须保留原资产并完成视觉检查，不得借机重做或覆盖源图。

## 6. 状态机与时间

Rig 使用单向、有界状态机：

```text
Dormant
→ Arriving
→ Parked
→ HeroRevealed
→ HoldTwoSeconds
→ Departing
→ Handoff
→ Finished
```

关键规则：

- `Arriving` 的目标距离默认为 400 Unreal 单位，实际移动时长与驶入图集同步；
- `HoldTwoSeconds` 固定使用 2.0 秒游戏时间；
- 暂停时位移、图集帧和停留计时同时冻结；
- `Departing` 以到达驶离点为结束条件，并设置有界超时；
- 每个完成回调必须校验当前状态，迟到回调不得推进已取消或已结束的 Rig；
- `Finished` 只广播一次，然后释放 Tick 和输入所有权。

## 7. 暂停、退出与故障安全

演出期间只持有一个有范围的城镇玩法输入锁。移动、交互、背包、编队等城镇操作暂不可用，但不安装全局鼠标钩子，不修改窗口策略，也不拦截系统级输入。

`Esc` 和现有暂停界面始终可用：

- 继续：从相同位置、相同图集帧和剩余停留时间恢复；
- 返回桌面：取消 Rig，走正常地图返回流程；
- 关闭游戏：不保存任何马车会话状态。

游戏重启后仍进入默认纯 2D 桌面，不自动加载青山镇。玩家下次主动点击 `剧情` 时从驶入开头重播。

以下任一问题必须走同一个“安全放行”路径：Rig 缺失或重复、摄像机/标记缺失、图集加载失败、主角引用缺失、超时或地图正在退出。安全放行必须尽最大可能：

1. 停止并隐藏马车；
2. 显示唯一主角；
3. 恢复主角碰撞、移动、交互和 ViewTarget；
4. 释放输入锁；
5. 写入明确错误日志；
6. 不写剧情、任务、奖励或 Guide 进度。

资源错误不得留下黑屏、固定镜头、永久输入锁或不可退出状态。取消和清理重复调用必须幂等。

## 8. 数据不变量

播放、暂停、取消、失败和正常结束前后，下列数据必须严格不变：

- 挂机运行进度、计时器、离线账本、宝箱与重试状态；
- `OrderedFormation`、伙伴与固定 NPC；
- 当前任务、剧情结果、Guide 状态和奖励；
- 背包、装备、卡组、金币和经验；
- 挂机条折叠、窗口位置、尺寸和鼠标命中策略。

本切片没有新存档字段，也不提升存档版本。travel option 和 Rig 状态只存在于当前地图运行期。

## 9. 明确非目标

本轮不实现：

- 主角取名、默认名、改名或玩家身份迁移；
- 新手引导、引导偏好、Guide 步骤或目标监听；
- 剧情对话、月白登场、任务抽屉、奖励与主线推进；
- 独立马匹图集、马与车厢复合 Actor；
- Level Sequence、3D 木车替换或新的序章地图；
- 启动或读档时自动重播、剧情完成提示或重播确认框；
- 挂机条、双窗口、Viewport、自动最小化或自动输入策略修改。

## 10. 验证与验收

### 10.1 自动化门禁

新增聚焦测试证明：

- action `654` 只发出语义化请求，不直接改变 Workbench 或运行时数据；
- 剧情请求生成正确青山镇目标和 `GameXXKIntro=CarriagePreview`；
- 普通城镇请求不带该 option；
- Rig 无 option 时保持休眠；
- 状态顺序、2 秒停留、完成只广播一次；
- 暂停冻结三类时间，继续后恢复；
- 正常结束、取消、资源失败和超时均恢复输入、主角与 ViewTarget；
- 运行时数据不变量在成功和失败路径均成立；
- 重复点击可以创建新的独立地图播放，但当前播放不接受重复启动；
- 图集路径、8×8 网格、60 帧和回退资源契约正确。

C++ 必须通过冷 UBT `GameXXKEditor Win64 Development -NoHotReload`；禁止用 Live Coding、Hot Reload 或 `--check-only` 代替编译证明。

### 10.2 玩家可见验收

从默认 `/Game/GameXXK/Maps/L_DesktopTrainingHUD` 开始，不运行鼠标自动点击脚本，由用户亲自点击 `剧情`：

1. 正确加载青山镇并进入固定镜头；
2. 马车从停车点左侧约 400 单位驶入；
3. 到站位置和停车帧无跳动；
4. 主角准确出现在车前；
5. 停留约 2 秒；
6. 马车从主角后方沿原方向驶离，并在镜头外隐藏；
7. 镜头、移动和城镇交互正常恢复；
8. 返回桌面后再次点击可以完整重播；
9. 关闭并重启游戏不会自动进入马车演出。

关键阶段截图或序列帧需检查马车尺寸、底部锚点、遮挡、停车落点、主角车前位置和驶离前后层级，复核方式由执行者按证据选择。除上述玩家明确批准的 `PlayerStart`/Rig 同步迁移到 `(16678.592, 5270.000, 1075.711)` 外，视觉验收不得再改动现有 `PlayerStart`、NPC、PaperZD/Flipbook、相机或用户手调 HD2D 平面；后续只允许调整新增 Rig 内部标记、镜头和马车显示参数。

## 11. 后续阶段入口

本规格实施并通过玩家马车验收后，下一阶段才开始讨论新手引导。后续设计以 `Tutorial.CarriagePreview.Completed` 为唯一接缝，逐步确定第一条引导、提示层、输入权限、完成条件和存档；在该设计批准前，不预装任何 Guide 行为。
