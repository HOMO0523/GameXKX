# GameXXK 历练放置、桌面迷你窗与自动战斗迁移设计

日期：2026-08-12

状态：用户已逐节确认，规格自审完成，等待用户书面复审

设计基线：`e75cbed40d6b22cb4a0a12569d407c20391b99e5`

当前生产存档版本：v15。本文描述的迁移实现必须使用后续新版本，不得在 v15 上静默改变语义。

## 1. 产品方向

GameXXK 从“3D 城镇作为主要局外入口”逐步迁移为以 2D 历练放置为核心的桌面游戏：

- 首次通关仍保留现有杀戮尖塔式路线、事件、商店、奖励和卡牌战斗；
- 玩家可在局内开启自动战斗，由 AI 代为出牌和选目标，但路线仍由玩家选择；
- 章节首次通关后解锁该章节历练，历练持续产生金币、经验和宝箱；
- 完整窗口展示 2D 历练场景，另提供 `640×180` 桌面迷你窗；
- 游戏关闭后按离线历练规则结算，不要求程序常驻；
- 3D 城镇暂不删除，先降级为兼容入口，待功能迁移完成后再决定是否移除。

本设计是总体迁移规格，但实施必须拆成独立可回滚的工作包。装备高稀有度、珠子、词缀、9 合 1，以及 Steam 登录、市场和服务器权威经济另立规格，不与首个历练版本捆绑。

## 2. 已确认的核心原则

1. 离线历练只结算已通关章节，不解锁章节，也不重放完整卡牌战斗。
2. 通关必须由玩家进入路线并完成；自动战斗只简化局内操作。
3. 在线宝箱由真实历练击杀、冷却和概率决定；离线宝箱使用期望值换算。
4. 在线与离线共享一套历练状态、宝箱队列、奖励账本和保存事务，不各自维护可重复领取的副本。
5. 游戏全局只有“普通怪物宝箱”和“首领宝箱”两种宝箱道具。
6. 宝箱内容由生成时的来源章节决定，不能把低章节宝箱带到高章节后升级奖励。
7. 宝箱生成时固定随机种子，首次开箱才展开完整奖励；反复读档不得改变结果。
8. 接受任务不自动入队，也不触发跟随；玩家必须另点“入队”才把任务 NPC 加入战斗队伍。
9. 当前版本优先保证完整单机体验。服务器、Steam 市场和交易只预留替换边界，不成为单机历练的运行依赖。
10. 不改已经确认的背包布局；新界面沿用背包的视觉模板和现有水墨 UI 语言。

## 4. 术语与容量边界

- **历练待领区**：尚未转入普通背包的金币、经验和宝箱账本。
- **历练宝箱容量**：限制尚未领取的宝箱数量，初始 20，最高 80；与普通背包格数不是同一个概念。
- **宝箱批次**：一个真实宝箱实例，记录类型、来源章节、获得顺序、随机种子和开箱状态。
- **背包显示栈**：同类宝箱在 UI 中合并显示数量，但底层批次和 FIFO 顺序不得丢失。
- **结算游标**：最近一次成功写入存档的历练计算终点。
- **上次领取时间**：仅用于 UI 显示和统计，不作为重复结算起点。
- **在线历练**：游戏运行且历练场景正在推进，以真实怪物死亡事件判定宝箱。
- **离线历练**：游戏未运行或没有推进在线历练，以时间和效率快照计算期望收益。

“最多 8 小时宝箱”不再是硬时间上限。取消固定每小时 10 箱后，实际装满时间由队伍效率和掉落系数决定；80 格约 8 小时只能作为后续平衡观察目标之一。金币和经验仍各自最多累计 7 天。

## 5. 总体架构

采用“双结算器、统一状态与账本”方案。

已比较并淘汰两种替代方案：

- **在线和离线都用期望值**：实现更简单，但玩家眼前的怪物死亡与宝箱出现脱节，削弱放置画面的反馈；
- **在线和离线都重放击杀或完整战斗**：语义更统一，但长离线成本、版本兼容和存档复杂度不成比例；
- **采用方案**：在线真实事件保留即时随机反馈，离线期望值保证结算成本有界，统一账本保证不可重复领取。

### 5.1 模块职责

| 模块 | 单一职责 |
|---|---|
| `TimeSource` | 返回当前 UTC；当前使用本机时间，未来可替换为 Steam/服务器时间 |
| `IdleState` | 保存章节、效率快照、时间游标、双冷却、离线余额、容量和宝箱 FIFO |
| `IdleEncounterScheduler` | 进程运行时按效率快照产生普通怪/精英怪死亡时间线，与 UI 帧率解耦 |
| `OnlineDropResolver` | 消费真实怪物死亡事件，执行双宝箱冷却与概率抽取 |
| `OfflineYieldCalculator` | 按时间、刷图效率和掉落配置计算期望收益，不运行完整战斗 |
| `RewardLedger` | 管理待领金币、经验、宝箱，执行领取事务 |
| `ChestResolver` | 用固定种子生成奖励，处理部分领取与剩余奖励 |
| `IdlePresentationModel` | 向完整界面和迷你窗提供相同的只读展示快照 |
| `AutoBattlePolicy` | 从合法行动中选择出牌、目标和结束回合，不选择路线 |
| `IdleRepository` | 读取、校验、迁移并原子保存历练状态；未来可替换远端实现 |

### 5.2 边界规则

- 规则模块不引用 UMG 或 Slate；UI 只能消费只读模型并发出命令。
- 动效和在线刷怪画面不是奖励权威来源；奖励只由结算器写入账本。
- 活动历练在玩家查看背包、队伍、路线或首次通关战斗时仍在后台继续；切换 UI 不暂停、不重置，也不额外加速。
- 所有时间、概率、货币和宝箱修改先作用于候选状态，校验成功后再一次提交。
- 离线结算复杂度取决于章节分段和最多 80 个宝箱事件，不随离线秒数线性增长。
- 离线余额与金币经验余量使用定点整数，不使用跨平台易漂移的浮点累计。

## 6. 历练状态契约

历练状态至少持久化：

- 当前历练章节；
- 已解锁历练章节集合；
- 当前队伍效率快照及其配置版本；
- `LastSettlementTimeUtc`；
- `LastClaimTimeUtc`；
- 自上次成功领取以来金币和经验各自已累计的有效时长，均封顶 7 天；
- 金币和经验各自的定点小数余量；
- 普通宝箱剩余冷却；
- 首领宝箱剩余冷却；
- 两类宝箱各自的离线未支付定点小数余额；
- 当前历练宝箱容量和容量天赋等级；
- 历练待领区的金币与经验；
- 按获得顺序排列的宝箱批次数组；
- 下一宝箱序列号；
- 两类在线掉落各自的稳定随机根种子与尝试序号；
- 时间回退诊断状态；
- 存档结构版本与掉落配置版本。

每个宝箱批次至少记录：

- 唯一 ChestId；
- 宝箱类型；
- 来源章节；
- 获得时间或稳定序列号；
- 所在容器：历练待领区或普通背包；
- 固定随机种子；
- LootProfileVersion；
- 是否已经展开奖励；
- 已展开后的固定奖励清单及未领取部分。

只有两种对玩家可见的宝箱类型。来源章节、种子和奖励余量是实例元数据，不得被压成一个仅有总数量的 `TMap` 后丢失。

每个新宝箱的 ChestId 与开箱种子都由“存档随机根种子、下一宝箱序列号、宝箱类型、来源章节、LootProfileVersion”确定性派生。生成宝箱时立刻递增序列号；第一次打开只消费已经保存的种子，绝不调用临时系统随机。

## 7. 在线宝箱规则

`IdleEncounterScheduler` 根据当前已保存的队伍效率、章节怪物构成和定点时间线产生普通怪或精英怪死亡事件。怪物类型由独立稳定随机流选择；相同状态和时间输入不受帧率、窗口最小化、1×/2×表现速度影响。完整界面和迷你窗只播放这条时间线的视觉表现。玩家进入路线、背包或其他页签时，时间线仍在后台运行；程序暂停、休眠或关闭期间的空档交给离线结算器，不能由在线和离线同时消费。

队伍、装备、章节或其他效率来源发生变化前，先推进并保存旧时间线到当前时刻，再用新效率建立后续时间线。首次通关路线中的临时 HP、DOT 和手牌状态不反向改变历练效率；只有已定义的局外队伍与养成快照参与计算。

### 7.1 冷却

- 普通怪物宝箱冷却：4 分钟；
- 首领宝箱冷却：6 分钟；
- 两条冷却独立运行；
- 冷却从对应宝箱上次成功掉落时开始；
- 抽取失败不重置冷却；
- 掉落成功只重置该种宝箱的冷却。

### 7.2 击杀判定

每次符合条件的普通怪或精英怪死亡时：

1. 若历练宝箱容量已满，直接跳过两种宝箱，不推进冷却或离线余额；
2. 分别检查普通宝箱与首领宝箱是否就绪；
3. 对每个已就绪类型，读取“怪物类型 × 宝箱类型”的独立掉落系数；
4. 分别执行随机抽取；
5. 失败则保持就绪，下一次符合条件的击杀继续抽取；
6. 成功则生成该类型宝箱批次并重置其冷却。

在线抽取使用“存档随机根种子 + 宝箱类型 + 独立尝试序号”导出的稳定随机流，不读取未来掉落表。每次真实尝试都会推进候选状态中的序号；成功掉箱必须先保存候选状态，保存失败则不显示掉落并回滚。普通定期保存或正常退出会持久化尚未成功的尝试序号；异常退出最多重复一个已经失败的结果，不能把同一失败重随机成成功。

同一次击杀可以同时掉落两种宝箱。普通怪与精英怪都检查两种宝箱，只是四个系数可以不同：

- 普通怪 → 普通宝箱；
- 普通怪 → 首领宝箱；
- 精英怪 → 普通宝箱；
- 精英怪 → 首领宝箱。

### 7.3 容量满

一旦待领宝箱数量达到容量：

- 两条冷却立即冻结；
- 两类离线小数余额立即冻结；
- 不继续累积隐藏宝箱或额外待补余额；
- 金币和经验继续累计，直到各自 7 天上限；
- 玩家领取腾出容量后，从腾出容量的成功保存时刻继续宝箱计时；
- 容量已满期间不补发宝箱。

## 8. 离线期望值结算

### 8.1 输入

离线结算只读取结算段开始时已经保存的：

- 来源章节；
- 队伍刷图效率快照；
- 普通怪/精英怪构成；
- 四项掉落系数；
- 双宝箱剩余冷却；
- 双宝箱离线未支付定点小数余额；
- 宝箱剩余容量；
- 金币与经验效率。

玩家切换章节、队伍、装备或其他会改变刷图效率的配置前，必须先按旧快照结算到当前时刻，再保存新快照。登录后临时换强力装备不得追溯提高此前离线收益。

### 8.2 期望进度

离线不逐个生成怪物或战斗。对每种宝箱，先由普通怪/精英怪击杀速率和对应系数得到就绪后的期望成功速率，再按以下流体过程批量推进：

1. 先消耗剩余冷却；
2. 冷却结束后，按期望成功速率增加该类型离线未支付定点小数余额；
3. 余额达到 1 时生成一个真实宝箱批次、余额减 1，并重新进入该类型冷却；
4. 使用剩余离线时间继续推进；
5. 多次分段结算必须与一次长结算得到相同整数宝箱、离线余额和冷却状态。

两种宝箱的预计生成事件按时间合并。全局容量在某一事件时刻填满时，两种离线余额都冻结在同一时刻；相同定点时间戳的事件使用固定顺序“普通宝箱 → 首领宝箱”，保证跨平台结果稳定。

### 8.3 在线与离线切换

- 切换模式前先结算到切换时刻，不允许两个结算器覆盖同一时间段；
- 离线小数余额是已经由离线时间赚得但尚不足一个宝箱的奖励信用，不是在线下一次随机抽取的概率；
- 它只在离线结算时增加，在线期间原样保留，也不改变在线掉落概率；
- 在线掉落成功只重置对应冷却，不清除此前离线赚得的小数余额；
- 在线抽取由独立尝试序列决定，不向离线余额重复增加期望值；
- 返回离线模式后，离线计算从保存的余额和当时剩余冷却继续；
- 结算游标只在候选状态保存成功后推进。

这一规则不保证一次短期在线随机结果与同样时长离线结果逐箱相同，只保证长期期望、冷却上限和奖励账本一致，且无法通过频繁上下线重复计算时间。

## 9. 时间、章节与效率快照

### 9.1 时间源

- 当前版本使用本机 UTC；
- 所有计算只依赖 `TimeSource` 接口，不直接散落调用系统时间；
- 当前时间早于结算游标时，本次收益为 0，游标保持不变；
- 等时钟追平后正常继续；
- 向前跳时，金币和经验最多计算 7 天，宝箱仍受容量限制；
- 金币和经验的 7 天额度从上次成功领取开始计算，登录、预览或分段结算不会重置额度；
- 金币和经验分别保存定点小数余量，频繁登录与一次长离线结果一致；
- 未来接服务器时只替换时间源和仓库，不重写奖励公式。

`LastSettlementTimeUtc` 是所有资源共享的时间防重游标；金币、经验另存“已使用的 7 天额度”，宝箱另存容量满时的冻结状态。共享游标推进到当前时刻不会误恢复已冻结宝箱，也不会重置金币经验额度。

若宝箱容量在一个离线结算段中途填满，宝箱冷却和离线余额冻结在填满的精确时间；金币、经验以及 `LastSettlementTimeUtc` 仍结算并推进到本段终点。这样再次登录不会补算满仓期间的宝箱，也不会重复领取金币经验。

### 9.2 章节切换

- 只能选择已经首次通关的章节历练；
- 同时只能有一个活动历练章节；
- 切换前先用旧章节与旧效率快照结算到切换时刻；
- 再以切换时刻为新章节起点；
- 已生成宝箱继续保存原来源章节；
- 多次切换不能绕过容量、金币经验上限或时间游标。

### 9.3 通关解锁

- 路线章节首次胜利后写入章节通关状态；
- 历练解锁状态由通关状态显式派生并持久化；
- 离线历练、迷你窗和自动战斗都不能单独解锁未通关章节；
- 战败不解锁历练。

## 10. 奖励领取与开箱

### 10.1 领取历练奖励

- 金币和经验从待领账本直接加入玩家状态；
- 领取金币或经验成功后，才重置对应资源的 7 天累计时长；未领取资源保持原累计上限状态；
- 宝箱按获得时间 FIFO 尝试转入普通背包；
- 转移只允许从每种类型最早的待领批次开始，不能跳过较早批次；
- 背包 UI 对同类宝箱合并显示，但内部仍保留各批次；
- 背包接收接口拒绝的宝箱继续留在历练待领区；
- 金币和经验领取不因宝箱背包不足而失败；
- 领取成功释放历练容量，并从成功保存时刻恢复宝箱计时；
- 领取失败不得释放容量、推进游标或部分改写玩家状态。

普通背包能否接收一个宝箱由背包权威规则判断，历练模块不得根据“同图标”擅自假定一定可装入。

转入背包后的权威数据仍是宝箱批次数组；现有 `Inventory` 数量只能作为两种宝箱的 UI/兼容镜像。任何领取、开箱、排序和存档迁移都先更新批次，再由批次派生镜像，禁止只减显示数量而丢失来源章节、FIFO 或随机种子。

### 10.2 开箱

同类宝箱严格 FIFO，玩家不能挑选高章节批次：

1. 取该类型最早未完成宝箱；
2. 若尚未展开奖励，用 ChestId、固定种子、来源章节和 LootProfileVersion 一次性生成完整奖励清单；
3. 在候选状态中把能接收的奖励加入背包或货币；
4. 无法接收的奖励原样保存在该宝箱中；
5. 保存成功后才提交已领取部分；
6. 只有剩余奖励为空时才删除宝箱；
7. 未清空的已开启宝箱继续占据原批次并保持 FIFO 首位；
8. 再次打开时不重新随机。

奖励条目使用固定顺序处理；背包不足不会删除条目、重排随机结果或跳到下一个宝箱。存档失败时宝箱、奖励清单和背包全部保持原状。

同一宝箱内所有奖励条目都按固定顺序尝试：某件装备无可用格时保留该条目，但后续仍可接收的堆叠材料、金币或经验可以领取。系统不会越过这个未清空宝箱去开启同类型的下一个宝箱。

## 11. 历练容量与天赋接口

- 初始历练宝箱容量：20；
- 最大容量：80；
- 独立容量天赋共 12 级；
- 每级消耗金币并增加 5 个宝箱容量；
- 不设置角色等级或章节门槛；
- 金币曲线、天赋名称、图标和完整天赋页另行讨论；
- 首个实现只需提供可靠的数据字段、升级命令和 UI 可绑定状态，不提前设计整棵天赋树。

升级事务必须先校验金币、等级和新容量，再一次保存；失败时不扣金币、不加等级。

## 12. 完整 2D 历练界面

完整窗口默认显示当前活动章节的 2D 历练场景：

- 中央：章节背景、当前队伍、普通怪/精英怪循环刷怪表现；
- 顶部：章节、金币效率、经验效率、历练持续时间；
- 右侧：普通宝箱、首领宝箱、当前数量与总容量；
- 容量满时：明确显示“宝箱已满，产出暂停”；
- 已通关章节：可切换历练；
- 未通关章节：显示“前往挑战”，进入现有路线流程；
- 登录离线结算：显示离线时长、金币、经验、两类宝箱和容量截断信息；
- 底部默认收起，仅保留一个展开按钮；
- 展开后提供“历练、队伍、背包、装备、天赋、设置”。

背包和装备继续使用当前已确认模板，不移动其既有页签、格子、按钮或角色布局。天赋入口在独立天赋规格完成前只承载容量升级所需的最小入口或未开放状态，不擅自扩展新页面。

刷怪动效仅表现结算状态，不能通过播放更快的动画增加收益。领取、章节切换和容量满使用短反馈，不连续弹出阻塞窗口。

## 13. 桌面迷你窗

### 13.1 窗口行为

- 默认尺寸 `640×180`；
- 默认在当前显示器右下角打开；
- 可拖动，记住显示器、位置和 DPI 后的有效坐标；
- 默认置顶，玩家可以关闭置顶；
- 只在窗口矩形内接收点击，窗口外不拦截桌面输入；
- 显示器移除、分辨率或 DPI 改变后，将窗口夹回最近有效工作区；
- 关闭游戏后不保留常驻进程，重新启动时按离线规则结算。

迷你窗应使用独立原生窗口承载，而不是把主窗口缩放后覆盖整块透明桌面区域。

### 13.2 内容

迷你窗只显示：

- 当前章节背景；
- 队伍刷怪循环；
- 金币与经验效率；
- 两类宝箱数量和容量；
- 领取按钮；
- 折叠/展开按钮。

点击折叠按钮后，抽屉从迷你窗上方向上展开，提供章节切换、领取、置顶开关和“返回完整界面”。迷你窗不承载首次通关路线、卡牌手牌或战斗选择。

完整界面和迷你窗必须消费同一个 `IdlePresentationModel`；不得各自重新计算时间或奖励。

## 14. 首次通关与自动战斗

### 14.1 玩家仍然控制

- 路线节点选择；
- 事件选项；
- 商店购买；
- 奖励选择；
- 章节开始、重试和退出；
- 自动战斗开关。

### 14.2 AI 接管

- 选择当前可打出的牌；
- 选择合法目标；
- 处理卡牌产生的合法选择；
- 没有更优合法行动时结束回合。

AI 每一步都通过现有权威卡牌规则和只读预演获取合法结果，不在 UI 或 AI 中复制伤害、治疗、护甲、DOT、毒爆、场地和职业公式。

### 14.3 决策规则

默认评分顺序：

1. 避免本回合可预见死亡；
2. 完成确定击杀；
3. 触发职业核心机制；
4. 获得必要防御与治疗；
5. 提高资源、过牌和后续回合收益；
6. 无合法行动时结束回合。

分数相同时按稳定 CardInstanceId、手牌顺序和目标阵位决胜，保证相同状态得到相同选择。AI 不读取玩家不可见的未来掉落或敌方隐藏随机结果。

### 14.4 开关与表现速度

- 自动战斗可以在战斗中随时开启；
- 关闭时等待当前卡牌、反应、DOT、状态和演出提交链完整结束，再交还控制；
- 不允许一半结算时切换控制权；
- 战败后停止，玩家手动选择重试或退出；
- 不自动重复刷首次通关路线；
- 自动战斗开关跨战斗记忆；
- 表现速度默认 1×，可选 2×；
- 2×只缩短表现等待，不改变规则 Tick、随机序列、卡牌结果或历练效率。

项目当前不存在“治疗粉”消耗品。新自动战斗规则、文档和测试不得再引用该退役设计。

## 15. 任务 NPC 新语义

### 15.1 玩家流程

1. 与任务 NPC 交互并接受任务；
2. 任务状态变为 Accepted；
3. NPC 仍留在原位置，不跟随，不自动进入战斗队伍；
4. 玩家另点“入队”；
5. 只有入队成功后，任务 NPC 才进入当前战斗队伍选择；
6. 玩家可以通过队伍界面将其移出，任务本身仍保持接受状态。

剧情任务状态、世界位置和战斗队伍选择是三个不同字段，不再用一个 `bFollowerJoined` 同时承担。

### 15.2 v15 兼容迁移

当前 v15 会把旧 Accepted/false follower 规范化为 follower=true；新版本必须显式结束这条语义：

- 保留 Accepted 任务状态；
- 将旧 follower 激活语义退役或规范化为 false；
- 不根据旧 follower=true 自动加入战斗队伍；
- 若存档已有明确 `PartySelection.QuestNpc`，保留该显式选择；
- 旧 NPC 位置可作为兼容数据保留，但不再驱动跟随移动；
- 重新保存后写入新的分离字段；
- 更新根 `AGENTS.md`、MVP 验收、生产文档、迁移测试和真实 PIE 脚本，不能同时保留“接受即跟随”和“另点入队”两套验收。

用户本次直接确认的新规则取代旧 follower 产品规则。实施前仍需先把当前未提交的真实 PIE/目标预演任务独立收尾，避免把两项变更混入同一提交。

## 16. 3D 城镇退场策略

## 17. 错误处理与原子性

### 17.1 保存失败

以下操作都使用“复制候选状态 → 计算 → 校验 → 原子保存 → 提交运行时”的顺序：

- 离线结算；
- 在线掉箱；
- 领取历练奖励；
- 开箱或继续领取剩余奖励；
- 切换章节；
- 升级容量；
- NPC 入队或移出。

保存失败时不得发奖、扣箱、扣金币、改变章节、释放容量或推进结算游标。

### 17.2 非法配置

- 未通关章节不能开始历练；
- 缺少章节效率、掉落系数或奖励表时，本段奖励为 0 并返回明确错误；
- 不使用默认高收益配置兜底；
- 旧版本 LootProfile 必须保留可解析路径或经过显式迁移；
- 损坏宝箱批次不得静默删除。

### 17.3 UI 与窗口错误

- 迷你窗位置无效时回到当前主显示器右下角；
- 完整界面或迷你窗重建只重建显示，不重复结算；
- UI 打开、Hover、Tick 或动画播放都不得推进结算游标；
- 领取失败后继续显示原账本，不显示已经发放的假状态。

## 18. 平衡与数据评估

不再使用“固定每小时 10 个宝箱”作为规则或硬验收。调优观察：

- 各章节普通怪/精英怪击杀速率；
- 四项掉落系数；
- 4 分钟与 6 分钟冷却的实际约束率；
- 20、40、60、80 容量的填满时间分布；
- 普通队伍、成型队伍和极端高速队伍的金币、经验、两类宝箱收益；
- 在线蒙特卡洛长期均值与离线期望值的偏差；
- 章节切换、频繁上下线和背包不足是否产生额外收益；
- 首领宝箱占比和高章节奖励价值；
- 7 天金币经验上限对回流玩家的影响。

调优优先修改配置数据，不把章节或角色特例写进结算器。20～80 容量应产生可感知差异，但不保证任何队伍恰好在 2 小时或 8 小时装满。

## 19. 测试与验收门禁

### 19.1 规则层

必须先写精确 RED，再修改生产代码，覆盖：

1. 普通宝箱 4 分钟、首领宝箱 6 分钟；
2. 同次普通怪或精英怪击杀可以独立掉落两种宝箱；

6. 容量满后双冷却和双离线余额冻结，金币经验继续累计；
7. 腾出容量后从保存成功时刻继续，不补算满仓时间；
8. 章节、队伍或装备变化先结算旧快照；
9. 章节切换前后各用自己的配置；

11. 金币经验严格限制为 7 天；

- 未来服务器权威生成掉落、ItemGuid 和来源事务；
- 装备封装交易前必须卸下珠子；
- 每个 Steam 账号滚动 24 小时最多新封装上架 4 件；
- 时间限制使用 Steam/服务器权威时间；
- 交易物在所有权确认后通过永久邮件交付；
- 客户端不得持有未来掉落表或决定市场资产；
- 当前版本不连接 Steam 市场、不要求登录服务器、不影响离线单机历练。

## 22. 非目标

- 不在本迁移中删除 3D 城镇或任何用户调整资产；
- 不让自动战斗选择路线、事件、商店或奖励；
- 不用离线历练解锁章节；
- 不运行离线完整卡牌战斗；
- 不固定每小时宝箱数量；
- 不在容量满时保存隐藏待补宝箱；
- 不增加第三种宝箱；
- 不允许开箱读档重随机；
- 不恢复治疗粉；
- 不在首版实现 Steam 市场、真实交易或服务器权威经济；
- 不提前决定完整天赋树和装备系统实现细节。

## 23. 交付成功标准

迁移完成时，玩家能够：

1. 从 2D 主界面查看当前历练章节和队伍；
2. 只对已通关章节开始历练；
3. 关闭游戏后获得正确、不可重复的金币、经验和两类宝箱；
4. 在容量满时清楚知道宝箱暂停、金币经验继续；
5. 把宝箱领入现有背包并按来源章节 FIFO 开启；
6. 在背包不足时保留未领取宝箱或开箱余量；
7. 使用桌面迷你窗置顶查看、领取和切换已通关章节；
8. 在首次通关战斗中随时开启或安全关闭自动战斗；
9. 保持路线选择权，并在首次胜利后解锁历练；
10. 接受任务后由玩家另点入队，不再发生自动跟随或自动入队；
11. 从旧存档迁移而不重复发奖、不误加 NPC、不丢失显式队伍选择；
12. 在完全离线的单机环境中完成以上全部流程。
