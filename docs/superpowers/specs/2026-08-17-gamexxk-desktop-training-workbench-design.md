# GameXXK 桌面历练工作台与局内扩展画布设计

> 状态：布局与 UX 已由用户确认；书面规格待用户复核后进入详细实施计划
> 日期：2026-08-17
> 目标平台：Windows 桌面端，基准画布 1920×1080
> 设计源坐标：沿用 UI Master 的 1672×941 参考画布
> 美术权威源：`outputs/UI_PSD/Candidates/GameXXK_UI_Master_V1.psd`

## 1. 决策摘要

本次把历练相关界面确定为一个常驻桌面工作台，而不是继续扩展 3D 城镇：

- 左侧为全高仓库；中间默认为角色背包；右侧为历练地图。
- 中间上方是挂机历练条，中间下方是五个全局功能按钮。
- 点击挑战后，中间背包区与其上方挂机条合并为一个更大的局内画布，承载路线图、手动打牌与自动战斗，避免字体和卡牌过小。
- `挑战` 与 `游历` 是两套流程：挑战负责主动解锁新关卡；游历只选择已通关关卡进行低耗挂机。
- 当前生成图只冻结排版和 UX，不是生产美术。多次整图重绘已经造成图标、纸张纹理和边缘噪点累积，禁止把生成图裁切后直接进入 PSD 或 UE。
- PSD 阶段先审计现有主 PSD；已存在的框体、按钮、页签、槽位和图标一律复用。只有主 PSD 中不存在的语义图标才单独生成或绘制，并以独立透明源文件进入组件化流程。
- 2D 历练工作台只有在界面、交互、局内战斗和存档验收全部完成后，才允许替换默认 3D 城镇入口；此前 3D 城镇继续保留为可回退基线。

## 3. 目标与非目标

### 3.1 目标

1. 建立清晰、低耗、可常驻桌面的纯 2D 历练主入口。
2. 保持现有实机背包的横向比例和信息密度，不把背包挤成竖长小窗。
3. 将仓库、角色背包、编队、天赋、工具和历练整合进一致的工作台外壳。
4. 在不切换到全屏 3D 场景的前提下，让挑战局内的卡牌、字体、敌我信息足够大且易读。
5. 让挑战、游历、关卡解锁、难度解锁、失败重试和奖励结算形成完整且可存档的状态闭环。
6. 用组件化 PSD 和独立图标源消除反复整图生成造成的噪点、拉伸和风格漂移。

### 3.2 非目标

- 本规格不决定宝箱的精确掉落概率、金币/经验数值或天赋加成公式；在数值表另行冻结前，只定义数据入口和结算顺序。
- 本规格不重做现有战斗牌组、敌方意图、地形和首领奖励规则，只改变其桌面承载方式及历练关卡编制入口。
- 本规格不立即删除 3D 城镇，也不立即改默认启动地图。
- 家园种菜/收菜、可左右移动并与 6 个 NPC 交互的 2D 城镇属于后继模块；本规格不实现它们，但工作台导航与存档边界不得阻断后续接入。历练工作台最终成为主入口后，2D 城镇传送门若保留，只作为打开历练地图的快捷入口，不再是唯一入口。
- 本规格不把任务、图鉴做成底部常驻按钮；它们以后可以放进历练页面的二级入口，也可以不做。
- 本规格不把生成概念图当作可直接切图的生产资产。

## 4. 视觉基准与 PSD 生产规则

### 4.1 概念图的正确用途

最终概念图 `exec-44e28ab2-41b3-4c65-b85a-ff4a2d189547.png` 的实际尺寸是 1671×941。它只用于确认以下内容：

- 三栏宽度关系；
- 仓库、背包、历练地图的相对位置；
- 顶部 3 敌对 3 我方挂机条；
- 底部五按钮；
- 空仓库、空背包的视觉检查；
- 历练节点保持正圆；
- `挑战`、`游历` 与当前游历关卡的层级关系。

它不承担像素、图标、材质、字体或切图权威。1671×941 与 UI Master 1672×941 的一像素差异不应通过拉伸补偿；PSD 重建时直接回到 1672×941 权威画布重新排版。

最终概念图已经由 Luna 视觉验收为布局通过，证据位于：

`Saved/Codex/luna_training_empty_inventory_final_check.md`

该结论表示布局和 UX 可进入 PSD 重建，不表示概念图本身达到生产美术质量。

### 4.2 资产复用优先级

PSD 开工前必须先对 `GameXXK_UI_Master_V1.psd`、`ui-master-spec.json`、`master-manifest.json` 和 `ShellComponents` 做语义审计。每个画面元素按以下顺序处理：

1. **直接复用**：主 PSD 已有同语义、同状态的组件，直接使用智能对象或链接组件。
2. **同族派生**：主 PSD 已有组件家族，只缺尺寸或交互状态；从母组件无损派生，禁止从整屏截图裁切。
3. **新增组件**：主 PSD 确实没有该语义时，才创建独立源资产并登记清单。

当前仓库可预期复用的家族包括按钮 normal/hover/pressed/disabled、页签、物品槽位、装备槽位、面板框体、进度条、资源条、tooltip 面板和现有导航图标。实际是否复用以 PSD 图层和 manifest 审计结果为准，不以概念图外观猜测。

### 4.3 缺失图标的单独生产规范

下列只是必须审计的语义集合，不代表全部都要新画：

- 底部导航：仓库、编队、天赋、工具、历练；
- 历练节点：已通关、当前、可挑战、锁定、精英、首领；
- 历练操作：挑战、游历、失败重试；
- 仓库/背包操作：双向转移、排序；
- 难度和章节标记；
- 局内自动战斗状态。

主 PSD 中不存在的图标必须遵守：

- 每个语义单独一张透明 PNG 源，不生成带面板的整套 UI。
- 源文件只包含图形，不含中文、数字、水印、按钮底板或随机装饰。
- 使用 1:1 安全框和统一视觉占比；圆形图标按正方形源生产，运行时禁止非等比缩放。
- 同一图标只生产一份高质量母版；hover、pressed、disabled 用 PSD 样式或统一状态层派生，不反复调用生成模型重画。
- 边缘必须具有干净 alpha，无白边、黑边、色溢和压缩噪点。
- 纸张与金属底框使用主 PSD 现有低频纹理；禁止用随机高频噪点掩盖接缝。
- 每个新增源记录语义 ID、尺寸、哈希、生成/绘制来源、裁切安全区和对应 PSD 图层路径。
- 生成资产必须先经过单图视觉复核，再进入 PSD；PSD 页面必须再经过整页复核，不能跳级。

### 4.4 禁止项

- 禁止从多次重绘后的概念图抠图。
- 禁止为了适配布局对圆形节点、圆形导航图标或人物像素图做非等比拉伸。
- 禁止将文字烘焙进按钮或面板贴图。
- 禁止把整页 UI 合并成一张背景再叠热点。
- 禁止覆盖用户已调好的角色像素图、PaperZD、关卡摆放、相机和 HD2D 平面参数。
- 禁止累计缩放：任何组件都必须从母版一次性缩放到目标尺寸。

### 4.5 TaskBarHero 同机性能参照

2026-08-17 21:56（Asia/Shanghai）对用户当前持续运行的 `TaskBarHero` 做了只读同机采样。进程已运行约 179.73 小时；三次 3 秒样本与一次 5 秒样本得到：

| 指标 | 观测值 |
|---|---:|
| Working Set | 约 513.0–513.3 MiB |
| Private Bytes | 约 1417.7–1417.8 MiB |
| CPU，整机 24 逻辑处理器 | 3 秒样本平均 2.30%，范围 2.00%–2.53% |
| CPU，折算单核 | 3 秒样本平均 55.25%，范围 47.89%–60.75% |
| GPU Engine 利用率求和 | 约 2% |
| GPU Dedicated Usage | 约 282.3 MiB |
| GPU Shared Usage | 约 12.1 MiB |
| 线程 / Handle | 192 / 1663 |

这些数字是整个 TaskBarHero 进程的长时运行快照，不是单个 UI 或素材的独占成本；GPU Engine 求和也不是帧时间。因此它作为同机参考包络，而不是用来推算单张贴图成本。

GameXXK 的低耗工作台以 Shipping 构建、同一台机器、无编辑器附加开销、静置游历 10 分钟后的 60 秒窗口验收：

- 2D 工作台期间不得把 3D 城镇关卡保留在加载状态。
- 静置游历默认 30 FPS；进入主动挑战后切到现有局内帧率策略，退出后恢复 30 FPS。
- CPU 整机平均目标不高于 3.0%，GPU Engine 求和平均目标不高于 3.0%。
- GPU Dedicated Usage 目标不高于 350 MiB。
- Working Set 目标不高于 650 MiB，Private Bytes 目标不高于 1.6 GiB。
- 挑战退出 30 秒内必须回落到上述静置区间，无持续增长的战斗贴图、Widget 或对象引用。
- 若 UE 固定运行时开销导致任一内存目标无法达到，实施结果必须同时报告“空 2D Shell、历练静置、局内战斗、3D 城镇”四组同机数据；在用户明确接受新上限前，不启用 2D 工作台替换默认入口。

## 5. 桌面工作台布局契约

### 5.1 基准结构

1920×1080 下使用三栏工作台：

| 区域 | 基准职责 | 宽度关系 |
|---|---|---|
| 左栏 | 全高仓库 | 约画布 21%，允许小范围适配 |
| 中栏 | 顶部挂机条 + 主内容 + 底部导航 | 约画布 57%，为主要阅读区 |
| 右栏 | 历练地图或工具 | 约画布 18%，可比概念图略长但不能挤压中栏 |
| 外边距/栏间距 | 安全区和视觉分隔 | 合计约画布 4%，按 DPI 等比适配 |

比例来自 1672×941 UI Master 坐标系。运行时按统一 UI Scale 等比缩放，并用锚点与安全区吸收宽高差；不分别拉伸 X/Y。

### 5.2 中栏纵向分区

中栏在普通工作台状态下分为：

1. 顶部挂机历练条；
2. 小间距；
3. 中间主内容；
4. 底部五按钮导航。

中间背包内容保持实机宽屏比例，目标约 1.76:1。背包外框、内部槽位和底部按钮必须共享同一宽度基线，不能出现底栏窄于面板或左右被挤扁。

### 5.3 响应式边界

- 1920×1080 是像素验收基准，2560×1440 必须等比清晰。
- 低于基准宽度时优先缩放整个工作台，不单独压扁左右栏。
- 中栏最小可读宽度优先级高于右栏装饰宽度；必要时减少栏间距，而不是缩小卡牌字体。
- 所有圆形节点与导航圆盘以 `min(width, height)` 计算直径并保持 1:1。
- 像素角色使用整数或接近整数的 nearest-neighbor 缩放，避免双线性模糊。

## 6. 常驻区域定义

### 6.1 左栏：仓库

- 标题统一为 `仓库`，不显示“小侠客 Lv.1”等角色身份卡。
- 顶部保留 `1 / 2 / 3 / +` 多页页签。
- 可见槽位固定 4 列；基准画面显示 4×9 空槽位。
- 底部只保留 `仓库→背包`、`背包→仓库` 和 `排序`。
- 视觉母版使用空槽位，避免把测试道具写死在 PSD；运行时显示真实仓库数据。
- 选择道具后才能执行双向转移；无选择、无空间或物品不可移动时按钮进入 disabled 状态并给出短 tooltip。

### 6.2 中栏默认页：角色背包

- Tab 键直接打开角色/背包工作台。
- 顶部角色页签只保留 `属性 / 装备 / 卡组`。
- `角色` 与 `伙伴` 合并到同一角色体系，由当前角色/编队选择切换，不再占独立底部按钮。
- 背包内部保留一个角色主体切换器：主角与已入队伙伴使用同一排头像/选择位切换，装备、属性和卡组随当前主体刷新，不再分别打开“角色窗”和“伙伴窗”。
- `天赋 / 称号` 不出现在角色页签上方；天赋进入底部 `天赋` 页面，称号不在本轮常驻导航中。
- `强化 / 洗炼 / 分解` 从背包移除，后续统一放进 `工具` 页面。
- 保留六个装备槽位。
- 背包槽位基准为 4×5，并带纵向滚动条。
- 视觉母版为空背包并可显示 `背包 0/200`；运行时容量与物品数量必须来自真实数据，不能硬编码为 0/200。
- 背包栏位上方不放五类筛选，只保留单个 `排序`。
- 金币直接显示在背包区域内。
- 设置按钮与关闭按钮分离，避免相邻误触；设置属于背包/工作台功能，不与关闭 X 共用一组。

### 6.3 右栏：历练地图或工具

- 默认显示历练地图。
- 点击 `工具` 时，右栏由历练地图替换为工具页面。
- `工具` 统一承载魔方、合成、制作，以及从背包移出的强化、洗炼、分解；本轮只冻结入口和容器归属，不在背包里保留这些按钮。
- 点击 `历练` 时，如果右栏不是历练地图则恢复历练地图；如果已经打开则保持，不重复创建窗口。
- 历练地图可以比概念图略长，以容纳难度、章节、节点、双操作按钮和当前游历状态。

### 6.4 底部全局导航

按钮顺序固定为：

1. 仓库
2. 编队
3. 天赋
4. 工具
5. 历练

交互规则：

- `仓库` 聚焦左栏，不复制一份仓库到中栏。
- `编队` 替换中栏背包页面。
- `天赋` 替换中栏背包页面。
- `工具` 替换右栏历练地图。
- `历练` 恢复或聚焦右栏历练地图。

## 7. 顶部挂机历练条

### 7.1 表现

- 宽度与中栏对齐，并能容纳左侧 3 个敌方单位和右侧 3 个我方角色。
- 敌方整体朝右，我方整体朝左；双方从边缘向中央交战。
- 六个角色采用同一缩放基线，可以比实机角色略小，但不得横向压扁。
- 显示当前游历关卡，例如 `历练 1-1`。
- 只显示 `失败重试 开/关`；挂机条不显示自动战斗开关。
- 自动战斗控制只存在于主动挑战的局内画布。

### 7.2 循环行为

游历以轻量状态机循环：

`走动 → 遭遇普通波/次级精英编制/首领编制 → 自动攻击 → 敌方依次扣血并被击杀 → 整场结算 → 继续走动`

- 挂机条固定提供 3 个敌方站位和 3 个我方站位，并按当前遭遇编制填充；空站位保持为空，不用拉伸角色填满空间。
- 普通波由公鸡、狸猫两只普通怪组成，第三敌方站位为空；两只都被击杀后做一次整场结算。
- 次级精英遭遇每次只选山羊或黄鼬其中一只作为核心，不在同一场次同时放入两只次级精英；核心配公鸡、狸猫组成三敌方编制。
- 首领遭遇使用关卡首领编制；完整编制被击杀并完成结算后才继续走动。

### 7.3 失败重试

- `失败重试 开`：角色阵亡后在当前游历关卡重新开始。
- `失败重试 关`：角色阵亡后停止当前游历，并回退到前一已通关关卡。
- 1-1 没有前一关，因此无论开关状态，失败后仍停留并重试 1-1，不产生非法关卡编号。

## 8. 历练地图、挑战与游历

### 8.1 关卡与难度

每个难度有九关：

`1-1、1-2、1-3、2-1、2-2、2-3、3-1、3-2、3-3`

难度顺序：

`普通 → 困难 → 地狱`

- 1-1 默认视为已经通关，可以直接游历。
- 未通关关卡对游历锁定，但可以按进度通过挑战解锁。
- 普通九关全部通关后解锁困难；困难九关全部通关后解锁地狱。
- 地狱九关全部挑战完成后，挑战按钮 disabled；悬停显示 `期待新内容`。

### 8.2 双按钮语义

历练地图底部固定两个主按钮：

- `挑战`：进入所选可挑战关卡的主动局内路线图，玩家可以手动打牌或在局内启用自动战斗；首次通关后解锁该关游历。
- `游历`：把所选已通关关卡设为当前挂机关卡，不进入主动路线图。

`游历` 按钮下方持续显示 `当前游历：<难度>-<关卡>`；若当前难度名称在上方已经明确，允许显示简写 `当前游历：1-1`。

### 8.3 节点状态与 tooltip

节点必须有互斥且可辨认的状态：

- 已通关；
- 当前游历；
- 当前可挑战；
- 锁定；
- 精英；
- 首领。

节点外形始终保持正圆。精英和首领悬停时显示贴近节点的羊皮纸 tooltip：

- tooltip 给出实际敌人名称和编制；
- 不显示概率、金币、经验或宝箱数值；
- tooltip 不遮挡当前节点和主要连线；
- 首次挑战 tooltip 必须描述挑战编制，不得误写为挂机奖励或已通关状态。

## 9. 主动挑战的放大局内画布

### 9.1 布局切换

玩家在历练地图选择节点并点击 `挑战` 后：

1. 中栏顶部挂机条隐藏并让出完整矩形；
2. 中栏背包/编队/天赋内容隐藏；
3. 两块区域合并成一个连续的 `ChallengeViewport`；
4. 路线图、事件、战斗、结算都在该放大画布内切换；
5. 底部全局导航仍保留在合并画布之外，保证工作台结构稳定。

因此局内不再受原背包 1.76:1 内容框的高度限制。它获得“挂机条高度 + 主内容高度”，用于放大字体、卡牌、意图、血条、手牌和 tooltip。

### 9.2 输入所有权

- 未结束的挑战流程独占中栏合并画布；不能用 `编队` 或 `天赋` 直接覆盖正在结算的战斗。
- 右栏历练地图保留当前选择和进度，但在战斗结算期间为只读，避免重复启动挑战或切换游历关卡。
- 左栏仓库保持可见，但战斗需要选牌、选目标或正在结算时禁止转移物品，避免战斗快照与库存状态冲突。
- 需要离开挑战时使用局内返回/退出入口，并沿用现有挑战退出确认和存档规则；退出完成后再恢复普通工作台输入。
- Tab 在挑战未结束时聚焦局内画布，不用背包替换它；挑战结束返回工作台后，Tab 再恢复“打开角色背包”。

### 9.3 局内内容

- 挑战进入现有杀戮尖塔式路线图。
- 路线图节点进入现有战斗屏幕。
- 手动打牌是默认可用方式。
- 自动战斗开关只出现在局内，并且只影响当前主动挑战，不污染游历挂机的自动逻辑。
- 局内 tooltip、卡牌正文和关键状态文字以 1920×1080 下正常阅读为标准，不通过缩小字体迁就旧背包框。
- 路线图与战斗共享 `ChallengeViewport`，避免在两套不同尺寸之间跳变。

## 10. 第一章敌人编制

第一章复用现有敌人池：

- 普通怪：公鸡、狸猫；
- 次级精英：山羊、黄鼬；
- 1-1：使用山羊精英作为关底首领；
- 1-2：使用黄鼬精英作为关底首领；
- 1-3：使用现有第一章首领青角羊王。

主动挑战与游历使用同一敌人编制数据源，但流程不同：

- 挑战按路线节点推进，包含手动打牌或局内自动战斗；
- 游历按轻量走动/遭遇/结算循环执行。

第一章挑战路线固定出现两个精英节点，分别为山羊精英和黄鼬精英；节点图形与 tooltip 必须明确区分。精英 tooltip 展示实际编制：

- 山羊精英：公鸡 / 山羊 / 狸猫；
- 黄鼬精英：公鸡 / 黄鼬 / 狸猫。

首领 tooltip：

- 青角羊王：山羊 / 青角羊王 / 黄鼬。

每个次级精英遭遇只采用山羊或黄鼬其中一套编制，和当前游戏“每次选择一只精英核心”的逻辑一致；编制中的三个敌方站位可以同时表现，但整场胜利后只触发一次战斗结算。

## 11. 奖励与结算边界

- 每场战斗都结算金币和经验。
- 主动挑战中的普通/精英战有概率掉落普通宝箱。
- 主动挑战中的首领战有概率掉落高级宝箱。
- 游历普通 encounter 沿用局内普通宝箱概率，掉落后进入 240 秒（4 分钟）冷却；游历精英与首领 encounter 沿用局内高级宝箱概率，掉落后进入 360 秒（6 分钟）冷却。挑战结算不使用游历冷却。
- 普通 1-1 游历是新手低成本例外：所有普通/精英/首领 encounter 的敌方基础生命按 1 点配置，只结算金币和经验，不掉落任何宝箱；该例外不改写主动挑战的通用宝箱入口。
- 宝箱掉率由统一奖励服务读取，并可受天赋树加成影响。
- 挑战首次通关还负责写入关卡解锁状态；游历只读取已解锁状态，不能反向解锁新关。
- 精确基础概率、天赋加成曲线和宝箱内容不写死在 UI 或流程代码里；在独立数值表发布前，运行时只接入可配置字段和安全默认值。
- UI tooltip 不展示尚未冻结的概率，避免形成错误承诺。

## 12. 状态与数据边界

建议把职责拆成六个可独立验证的单元：

| 单元 | 负责 | 不负责 |
|---|---|---|
| Workbench Shell | 三栏布局、面板替换、Tab 与导航焦点 | 战斗规则、掉落计算 |
| Inventory/Warehouse | 真实库存、容量、转移、排序 | 历练解锁 |
| Training Progression | 难度、关卡通关、当前游历、锁定状态 | 具体战斗演算 |
| Idle Encounter Runner | 低耗走动、单敌遭遇、失败重试、单场结算 | 路线图和手动出牌 |
| Challenge Session | 路线图、战斗、自动战斗开关、退出与结算 | 桌面挂机循环 |
| Reward Resolver | 金币、经验、普通/高级宝箱、天赋掉率修正 | UI 排版 |

关键约束：

- 挑战与游历共享关卡和敌人编制定义，不复制两套表。
- 挑战与游历拥有不同运行状态机，不能让挂机逻辑驱动局内卡牌战斗。
- `CurrentTravelStage` 必须始终指向已通关关卡；读档发现非法值时回退到该难度最早已通关关卡，最终兜底为普通 1-1。
- 首次进入新存档时普通 1-1 已通关且为当前游历关卡。
- 设计冻结时以 `CurrentSaveVersion=17` 作为前置基线；当前 opt-in 实现已占用 `v18`（`DesktopTrainingWorkbenchIntroducedSaveVersion=18`）、`v19`（奖励 seed/游历宝箱冷却）和 `v20`（离线游历账本/UTC 基线/收菜桥接）。后续字段必须从 v21 继续编号，不得复用旧历练索引的 v16/v17/v18 边界。

## 13. 错误与边界处理

- 选择锁定关卡时：`游历` disabled，tooltip 说明需先挑战通关。
- 选择非当前进度的未来关卡时：`挑战` disabled，tooltip 说明需先完成前置关卡。
- 点击已完成全部内容后的挑战：不启动会话，hover 显示 `期待新内容`。
- 库存已满时：奖励先进入现有安全结算/暂存路径；不得静默丢失，也不得由 UI 自行删除。
- 战斗中重复点击挑战或游历：输入被右栏只读状态拦截。
- PSD 缺少图标时：使用有语义的临时开发占位标识，不从概念图裁切；该占位不能进入发布构建。
- 概念图和实机尺寸冲突时：以实机背包比例、UI Master 组件和本规格的布局契约为准。

## 14. PSD 页面与图层交付结构

PSD 阶段新增或更新的页面必须保持组件可编辑，建议层级如下：

```text
DesktopTrainingWorkbench
├─ Shell
│  ├─ WarehouseColumn
│  ├─ CenterColumn
│  ├─ TrainingOrToolsColumn
│  └─ GlobalNavigation
├─ HubState
│  ├─ IdleTrainingStrip
│  ├─ CharacterBackpack
│  └─ TrainingMap
├─ ChallengeState
│  ├─ ChallengeViewport
│  ├─ RouteMap
│  ├─ BattleHUD
│  └─ Settlement
├─ Components
│  ├─ ReusedMasterComponents
│  ├─ NewSemanticIcons
│  └─ StateOverlays
├─ LiveText
└─ GuidesAndSafeAreas
```

要求：

- `HubState` 与 `ChallengeState` 用图层组切换，不做两张无法对齐的扁平整图。
- `LiveText` 保持可编辑，并与 UE 字体/字号表对应。
- 新图标放入独立智能对象；同一语义不重复嵌入多个不同副本。
- 图层命名与 manifest 的语义 ID 一致。
- 导出前同时检查空库存母版和填充真实测试数据的验证版。

## 15. 分阶段交付策略

本规格是跨美术、工作台框架、历练玩法和局内集成的总设计，不作为一个原子开发任务执行。用户书面复核后，规划阶段先建立总索引，再拆成四份可独立审阅的实施计划：

1. PSD 资产审计、缺失图标与组件化页面；
2. Workbench Shell、仓库/背包和导航接线；
3. 历练进度、游历状态机、奖励与存档；
4. ChallengeViewport、现有路线/战斗集成、性能与最终入口切换。

四份计划共同按以下工作包顺序推进；每个工作包独立验收，前一个未通过不进入后一个：

1. **资产审计与尺寸基线**：枚举 UI Master 可复用组件，建立 reuse/derive/new 清单，冻结 1672×941 与 1920×1080 坐标换算。
2. **缺失图标单图生产**：只制作审计判定为 new 的图标，逐个做 alpha、尺寸、风格和哈希验收。
3. **组件化 PSD 工作台**：重建空仓库、空背包、历练地图、挂机条、底部导航以及 ChallengeState，不使用噪点概念图切片。
4. **Workbench Shell 运行时**：实现三栏布局、Tab、五导航、中央/右侧替换和响应式约束。
5. **仓库与背包接线**：接真实物品、容量、金币、转移和排序；验证 4 列仓库与 4×5 背包。
6. **历练进度与游历循环**：实现 27 个难度关卡状态、1-1 默认通关、锁定/解锁、挂机状态机和失败重试。
7. **挑战放大画布接线**：把现有路线图和战斗接入合并后的顶部+中部画布，接入局内自动战斗与敌人 tooltip。
8. **奖励、存档与迁移**：接入金币、经验、双宝箱、游历 240/360 秒冷却、天赋掉率入口、v20 离线账本/收菜桥接和基于当前 v20 继续递增的新迁移。
9. **性能与长时稳定性**：对常驻挂机、窗口切换、战斗切换、读写档和长时间运行做 CPU/GPU/内存采样。
10. **最终入口切换**：只有全部视觉、交互、战斗、存档和性能验收通过后，才把 2D 历练工作台设为主入口并弃用默认 3D 城镇入口；保留可回退开关直到发布验收结束。

详细计划必须列出具体文件、测试、MCP/UBT 命令、存档版本和回滚点。本阶段只冻结设计，不实施 UE 代码或修改资产。

## 16. 验收标准

### 16.1 PSD 与视觉

- 页面以 UI Master 1672×941 为设计权威，并能无失真映射到 1920×1080。
- 仓库全高、4 列、无角色身份卡；背包保持约 1.76:1，4×5 可见槽位与滚动条。
- 空库存母版中仓库、背包不出现任何道具图；装备槽位保留为空。
- 顶部准确容纳 3 敌方 + 3 我方，像素角色未被压扁。
- 历练节点为正圆，状态清晰；左右栏没有因为中栏放大而被非等比压缩。
- 新增图标全部来自独立干净源，alpha 边缘通过检查；没有从概念图裁切的噪点资产。
- 文字均为活字层或运行时文字，没有烘焙进贴图。

### 16.2 工作台交互

- Tab 在非挑战状态打开角色背包。
- 仓库、编队、天赋、工具、历练五按钮的替换关系与第 6.4 节一致。
- 设置与关闭分离；背包只有排序，无五类筛选。
- 工具替换右栏；历练可以恢复右栏地图且不重复创建。
- 仓库/背包显示真实数据，空母版中的 `0/200` 不会覆盖存档。

### 16.3 历练与挑战

- 新档普通 1-1 默认通关且可游历。
- 未通关关卡无法游历；挑战通关后立即解锁。
- 普通、困难、地狱按各自九关顺序解锁；全内容完成后挑战 disabled 且显示 `期待新内容`。
- 历练地图有 `挑战`、`游历` 两按钮，并持续显示当前游历关卡。
- 挑战后顶部挂机条与中间背包区合并成单一局内画布；卡牌、字体和 tooltip 比旧中间小窗更清楚。
- 局内才出现自动战斗控制；挂机条只出现失败重试。
- 精英路线固定两节点；精英与首领 tooltip 显示正确敌人和编制。
- 挑战和游历读取同一敌人编制，但分别走主动路线与轻量挂机状态机。

### 16.4 结算、存档与性能

- 普通战、精英战和首领战均完成金币/经验结算；普通/高级宝箱走各自配置入口。
- 游历普通箱掉落后冷却 4 分钟，精英/首领高级箱掉落后冷却 6 分钟；1-1 游历任何 encounter 均不掉箱。
- 天赋掉率修正从奖励服务读取，不散落在 UI 或关卡按钮中。
- 失败重试开关行为正确；1-1 不会回退到非法关卡。
- 读档能恢复难度、通关状态、当前游历关卡、失败重试和未结束挑战的既有安全状态。
- 1920×1080 与 2560×1440 无横向压扁、节点椭圆、文字裁切或槽位错位。
- 常驻挂机相对现有 3D 城镇有明确的 CPU/GPU/内存下降证据；具体预算在实施计划的基线采样后冻结。
- 未通过最终验收前，默认 3D 城镇入口不切换。

## 17. 用户复核重点

进入详细实施计划前，只需确认本规格是否准确记录以下最终方向：

1. 当前概念图只定排版和 UX，不作为 PSD 美术素材。
2. PSD 先复用主 PSD，再逐个制作真正缺失的图标。
3. 普通工作台是左仓库、中背包、右历练、上挂机、下五按钮。
4. 主动挑战用顶部挂机区加中间背包区组成更大的局内画布。
5. 2D 历练工作台最终替换 3D 城镇，但必须放到全部验收通过后的最后一步启用。
