# 路线行商设计

## 目标

在不改变既有随机路线结构、城镇永久商店和永久金币规则的前提下，让 `Merchant` 路线节点成为可购买本局遗物和路线卡的真实局内商店。玩家可以购买、处理需要替换的路线卡、离开商店并可靠回到原路线节点图。

## 已锁定需求

- 行旅货币 `RouteTravelMoney` 与城镇永久金币 `PlayerGold` 严格分离；路线 HUD 左上角显示行旅货币。
- 行商出售路线遗物和路线卡；每件物品下方直接显示价格与购买按钮，余额不足时按钮置灰。
- 路线商店卡牌遵守品质和卡池限制：主角专属牌只来自主角池；伙伴专属牌只来自当前携带伙伴实例的 `PersonalCardIds[12]`，不得扩展为整个职业池。
- 购买卡牌时，若会令本局路线牌数超过上限，进入既有战后卡牌奖励的替换流程；若同名同品质卡牌立即合成、不会增加牌数，则直接购买，不要求替换。
- 成功购买遗物立即写入本局 `CardRun` 遗物列表、在地图和战斗右上角遗物栏实时生效；路线结算/失败/放弃清空局内遗物。
- 离开才完成该商店节点；重复点击、余额不足、已售罄和未完成的替换不得扣除行旅货币，也不得完成节点。
- 商店画面使用既定低饱和水墨 Q 版 PSD 体系。初版资产走已登记的 `DRAFT-B01-ROUTE-UI`，不覆盖不可修改的 PSD 原子、角色、Boss、状态、资源条、卡框和滚动条资产。

## 当前事实与缺口

`UGameXXKMVPRules::SelectRouteNodeById` 已能进入 `RouteMerchant`，`ResolveMerchantRouteNode` 已能在离开时完成节点；`RouteTravelMoney` 已用于路线结算。当前 `UGameXXKRouteEncounterPanelWidget` 对商店只显示“离开商队/暂不离开”，没有商品、价格、余额校验、购买、遗物授予或卡牌替换流。因此不能将现有行商视为完成。

## 方案比较

### A. 复用城镇 `UGameXXKInventoryWindowWidget`

复用现成格子和交易逻辑，但它以永久库存、永久金币和装备/物品为语义。为路线商店硬塞路线货币、卡牌和遗物会混淆两套经济，并可能让路线交易写入永久背包。此方案不采用。

### B. 独立的路线行商窗口（采用）

新增 `UGameXXKRouteMerchantWidget`，只读取和修改路线运行态。它展示卡牌与遗物商品格、Tooltip、价格、按钮、行旅货币和离开按钮；控制器只在 `RouteMerchant` 时打开它。规则层维护确定性商品与购买事务，窗口不直接改存档字段。该方案使局内/局外边界、卡牌替换与自动化测试都清晰。

### C. 将商品功能继续堆入 `UGameXXKRouteEncounterPanelWidget`

改动较少，但这个面板目前仅适合三选一事件/宝箱与营地选择；加入六个商品、购买状态和待替换状态会把通用事件逻辑与商店事务耦合。此方案不采用。

## 数据与事务边界

### 商品清单

为每个待完成的 `Merchant` 节点保存一次确定性商品快照：商品 ID、类型（`Card` 或 `Relic`）、价格、已售状态，以及卡牌品质/实例或遗物 ID。商品只在第一次打开该节点时按路线种子和节点 ID 生成，之后读回快照；读档、关闭再打开、退出 PIE 后同一存档都不重掷。

首版固定提供 3 张卡牌和 3 件遗物。卡牌池按当前队伍构造，包含公共牌、主角专属牌和当前携带永久伙伴的职业专属牌；没有永久伙伴时不生成伙伴专属牌。遗物从现有路线遗物目录中抽取，三项不重复。价格是运行时规则数据，不写入 UI 文本。

### 购买遗物

点击遗物商品后，规则层依次验证：当前屏幕是 `RouteMerchant`、待完成节点是 Merchant、商品存在且未售、行旅货币足够、遗物定义存在。通过后一次事务中扣除 `RouteTravelMoney`、把遗物加入权威遗物规则、标记商品售罄。任一步失败时运行态保持不变。

### 购买卡牌

点击卡牌商品先构造购买预览。

1. 若购买会与已有同名同品质路线卡立即合成，则先在候选状态中完成合成；牌数不增加时直接在同一事务内扣钱、写入结果、售罄。
2. 若候选结果不超过路线牌组上限，同一事务内扣钱、写入卡牌、售罄。
3. 若候选结果超过上限，不扣钱、不售罄；将“待购买商品”作为来源写入既有路线卡替换状态，展示现有卡牌替换 UI。
4. 玩家选择一张可替换路线卡后，规则层重新验证商品和货币，执行替换、扣钱、售罄并清除待购买状态。取消替换只清除预览，不改变钱、商品或路线牌组。

只有规则层可改变行旅货币、商品售罄状态、路线牌组和遗物列表；窗口只发出明确的购买/替换/离开请求并基于返回的 read model 刷新。

### 离开、存档和回滚

离开调用现有 `ResolveMerchantRouteNode`，但只有在没有待购买替换时可用。商店快照和售罄状态属于路线运行态并进入存档；失败、放弃、第三章结算与现有路线状态清理必须同时清除它们。旧存档迁移缺少商店字段时，初始化为空快照，首次进入 Merchant 再生成，绝不重写已访问节点或路线边。

## UI 与交互

- 进入 `RouteMerchant` 时打开独立全屏 HUD；关闭普通事件面板，避免两个遮罩抢点击。
- 左上角使用行旅货币图标和 `当前值`；这仍是路线货币，绝不显示或修改城镇金币。
- 中央分为“路线卡”与“行商遗物”两组，各 3 个商品格；卡格使用既有卡框、稀有度文字和完整卡牌 Tooltip；遗物格使用既有遗物 Tooltip。
- 每格紧随价格与购买按钮。余额不足、已售罄、等待替换、无效数据时按钮不可用，且 Tooltip 说明原因。
- 点击需要目标的卡牌不会在商店出现；商店卡只作展示和购买，所有可交互卡牌仍必须有悬停 Tooltip。
- 右下角“离开商队”只有没有待替换购买时可用；点击后回到同一随机路线图并标记本节点已访问。
- 初版美术只绑定清单登记的路线商人立绘、宣纸底与行旅货币图；未生成/未导入时显示现有合规纸墨框架与文字，不以空白、裸框或假按钮替代商品交互。

## 验收与测试

### 规则自动化

1. 同一路线种子和 Merchant 节点在重开、存档加载后给出相同 3 卡 + 3 遗物商品；不同节点不会共享已售状态。
2. 余额不足、商品不存在、商品已售、非 Merchant 屏幕与待替换未完成时，购买都返回失败且运行态逐字段不变。
3. 买遗物只扣行旅货币、加入本局遗物，永久金币与永久仓库不变。
4. 买卡验证三条路径：直接加入、同名同品质合成不替换、超上限进入替换后购买；取消替换不扣钱。
5. 离开后节点已访问并回路线；已购买商品、行旅货币、路线牌和遗物经存档加载保持一致；路线终止清空商店快照和局内遗物。

### Widget 与真实 PIE

1. Widget 测试验证六个商品格、价格、按钮可用/置灰、售罄态、卡牌/遗物 Tooltip 与离开按钮绑定到 read model。
2. 真实 PIE 从主菜单进入城镇、接任务、进入路线并点击 Merchant；截图必须同时显示行旅货币、至少一件卡牌、至少一件遗物、价格和购买按钮。
3. 完成一次余额足够购买、一次余额不足置灰、一次需要替换的卡牌购买和一次离开；确认回到同一张路线图而不是卡死或跳到城镇。
4. C++ 改动使用保存后的编辑器关闭/重启和 `-NoHotReload` 冷编译验证，不用 Live Coding 或 Hot Reload。

## 非目标

- 不改变城镇装备/永久物品商店、其 `PlayerGold` 或库存。
- 不改变随机路线拓扑、已调地图、镜头、PaperZD、角色、Boss 或 PSD 不可覆盖资产。
- 不在本功能中重做完整装备背包或全局美术终审；它们继续由各自的冻结计划处理。
