# 伙伴图鉴 HUD 设计

状态：已由用户确认（2026-07-16）

## 目标与边界

城镇 HUD 的“伙伴”入口改为可用的伙伴图鉴，而不是编队、养成或战斗卡牌系统。

- 图鉴分类为：侠客、仙灵、妖怪、珍兽；“全部”展示汇总。
- 右侧为真实可滚动的卡片区；左侧分类固定。
- 统一使用伙伴 PSD **第一排**卡框的尺寸与比例作为运行时卡框基准。第二排切图不参与尺寸判断。
- 不把整张 `companion_window.png` 作为互动背景，不显示其烘焙样例数值或样例角色来伪造游戏内容。
- 本单元不新增伙伴升级、星级养成、抽取、出战编队或战斗数值系统。

## 数据模型

规则层提供静态图鉴定义，每项包含稳定 ID、分类、显示名、简介和可选图标路径。运行时和完整存档新增两个集合：

- `DiscoveredCodexEntryIds`：已遇见的图鉴条目；用于计数、筛选和解锁显示。
- `ReadCodexEntryIds`：已查看条目；`Discovered - Read` 决定卡片与 HUD 入口的红点。

定义与发现记录分离：定义表可以随版本添加新条目，存档仅记录玩家的发现/已读状态。未知或已删除的存档 ID 在读取和计数时忽略，不能造成崩溃。

当前只为真实已有的游戏实体配置可发现条目。缺少实际游戏实体或美术的分类保持可筛选，并显示“尚未收录”；不得以 PSD 的示例人物冒充已存在内容。

## 解锁与存档迁移

图鉴记录“首次遇见”，不是“战斗胜利”。

1. `AcceptTownQuest` 成功时发现引路人。
2. 每次成功创建战斗时，发现当前战斗中的敌方实体。
3. 发现同一条目是幂等操作，不增加总数、不重置已读状态。
4. 图鉴字段提升保存版本并写入完整运行时存档。
5. 旧存档缺少图鉴字段时安全初始化；仅当任务已接取或已完成时补记能可靠推断的“引路人”。不猜测历史战斗遭遇。

## 城镇 HUD 交互

- 点击 HUD 的“伙伴”图标打开图鉴，取代旧的伙伴文字 `Border`。
- 再次点击、关闭按钮或 `Esc` 关闭图鉴；与角色面板互斥。
- 左侧分类标签固定。选择分类后，右侧列表回到顶部并刷新“已收录 / 总数”。
- 右侧使用 `ScrollBox` 和可拖动滚动条；鼠标滚轮同样可浏览。卡片统一为三列网格，尺寸及比例来自 PSD 第一排卡框。
- 已收录卡可选择并显示名称、分类、简介。未收录卡显示 `???? / 未遇见`，不泄露名称或简介。
- 新发现卡显示红点；首次查看后标为已读。任一未读条目存在时，HUD 的伙伴入口显示红点。
- 运行时只使用 GameXXK 自有的分层标签、空白窗框、现有 HUD 纹理和程序化文字；不依赖 `/Game/1Game`。

## 模块边界与故障处理

- `UGameXXKMVPRules` / `UGameXXKMVPSubsystem` 是图鉴状态的唯一写入方。
- `UGameXXKTownHudWidget` 只投影状态并发送明确的选择/标记已读命令；不直接篡改存档集合。
- 空分类、重复发现、无效 ID、缺失可选图标、没有可显示条目的旧存档均需提供安全的空状态，不得影响城镇 HUD 的其他按钮或地图流程。

## 测试与验收

自动化测试至少覆盖：

1. 接任务发现引路人；创建战斗发现敌方条目。
2. 同一条目重复发现不会重复计数或重新产生红点。
3. 分类筛选、全量计数、空分类和未收录卡的安全显示。
4. 查看条目会清除该卡和入口的未读红点。
5. 新存档往返保存；旧存档迁移只可靠补记引路人。
6. 城镇 HUD 能打开、关闭、筛选及滚动图鉴，不影响角色面板或世界地图按钮。

人工 / PIE 验收路径：开始游戏 → 世界地图 → 青山镇 → 接任务 / 进入战斗 → 返回城镇打开图鉴，确认对应记录、红点、筛选和滚动都可用。

## 非目标

- 不按 PSD 样图伪造不存在的伙伴卡、立绘、等级或星级数据。
- 不修改用户调过的角色、美术、PaperZD、场景或 HD2D 参数。
- 不改变已确认的“开始游戏 → 世界地图 → 点击城镇进入”流程。
