# GameXXK 数值评估、自动调优与战斗动效节奏设计

日期：2026-08-12  
状态：设计冻结，进入 TDD 与持续观测  
基线：`003c43abeda12b15f3e91c3429feb5b821196836` / `backup/full198-approved-20260812`

## 1. 目标

本轮在不改变已确认 UI 布局、卡牌规则语义和 198 张卡身份的前提下，完成两个相互独立但共享验收门禁的优化闭环：

1. 建立可信、确定、可追溯的数值评估器，能够区分职业、出生流派、NPC、套装、地形与成长档，并追踪到具体 CardId。
2. 让离线工具自动识别强弱异常、提出有边界的参数候选；生产数值仍按 TDD 逐项落地，禁止游戏运行时暗改难度。
3. 把现有一次攻击约 2.5 秒、死亡约 5 秒的串行演出压缩为类《杀戮尖塔》的清晰节奏：出牌有提交反馈，首击可读，多段快速连续，伤害轻重有层级，死亡明确但不拖沓。
4. 每轮以冷 UBT、精确 Automation、正交观测、2,400 场全矩阵和真实 PIE 复核；结果不满足门禁时继续迭代，不以报告目录名代替报告内容。

## 2. 已确认基线问题

### 2.1 数值评估

- 当前锁定矩阵为 8 个绑定 cohort × 3 节点 × 100 种子，共 2,400 场；NPC、套装、品质与强化被绑定，无法归因单一变量。
- 永久伙伴由种子随机职业和出生流派，同一 cohort 内混合六职业，职业强弱不可直接比较。
- `Skilled` 策略只给即时伤害、实际治疗与护甲主要分数。198 张牌中有 71 张没有这三种即时效果，阵师等铺垫流派会被系统性低估。
- 当前结果 2,118 胜 / 282 负 / 0 僵局，总胜率 88.25%；它证明规则能够终局，不等于平衡完成。
- 现有 CSV 缺少实际伙伴职业、主流派、出生卡、逐卡看见/打出/贡献、回合末未用资源、过量治疗和过量伤害。

### 2.2 动效节奏

- Attack/Hit 60 帧、12 fps、2 倍速，单包时长 2.5 秒；五段攻击约 12.5 秒。
- Death 以源速播放 5 秒；多段致死后还会追加完整死亡演出。
- 每个伤害包都使用固定 1.1 秒命中点、固定 12×6 全屏震动，闪避、轻击和重击没有层级。
- 成功出牌后手牌原位停留，直到整个伤害队列结束才刷新，缺少“牌已打出”的即时确认。
- 状态变化会更新固定 HUD，但没有短促脉冲；完整状态演出又不适合每层 DoT 反复全屏播放。

## 3. 方案比较与选择

### A. 可信评估器 + 离线有界调优 + 混合时间轴（采用）

- 先修策略与观测，再调数值。
- 以控制变量矩阵和同种子 A/B 归因。
- 自动工具只生成候选和证据，不拥有生产写权限。
- 动效保留现有角色 atlas、中央特写和固定布局，新增短出牌提交，并把后续多段压缩为快速节拍。

优点是结果可解释、可回滚，能保护已确认规则和美术；代价是需要先建设评估基础设施。

### B. 按当前 2,400 场胜率直接批量改卡（不采用）

速度快，但会把 AI 不会使用铺垫牌误判为牌弱，也无法区分 NPC、套装与伙伴职业的贡献。

### C. 运行时动态难度或在线自动改值（不采用）

能快速把总体胜率拉到目标，但规则对玩家不透明，破坏同种子复现和构筑学习，且难以定位回归。

## 4. 数值评估架构

### 4.1 评估策略 v2

仍只调用真实 `FGameXXKCardBattleAdapter`，不复制战斗规则。候选评分新增：

- 敌方有效伤害、击杀和终局。
- 我方有效治疗、护甲、避免我方非致死失血和死亡。
- 新抽入手牌、净气力、净内力与回合末未使用资源。
- 按目标阵营分类的正负状态价值；至少覆盖流血、中毒、灼烧、蚀伤、破绽、标记、气势、蓄力、灵动、反击、格挡和药效。
- 地形切换后，当前手牌在新地形下可获得的条件收益。
- 延迟 modifier、任务进度、自动队列与下回合收益的保守价值。

第一阶段采用确定性显式启发式，不直接上全量 2-ply，避免把 2,400 场成本乘以整手候选数。必须先通过六职业战术谜题；若仍无法处理明确的两步循环，再只对零即时收益候选增加固定宽度、固定深度的 lookahead。

评分只用于诊断 AI，不改变实际卡牌规则。相同状态、种子和目录必须得到相同决策。

### 4.2 观测 schema v3

每场新增：

- `companion_template`、`companion_role`、`companion_primary_archetype`、`companion_birth_cards`、`companion_selected_cards`。
- `terrain`、成长档与控制变量标签。
- `cards_seen_by_id`、`cards_played_by_id`、`damage_by_card_id`、`healing_by_card_id`、`armor_by_card_id`。
- `energy_unspent_at_phase_end`、`mana_unspent_at_phase_end`。
- `overkill_damage`、`overhealing`。
- 现有伤害来源、DoT 来源、状态产生/消耗、队列深度、卡手与终局字段全部保留。

“看见”定义为一个牌实例新进入手牌一次；留在手中跨动作不重复计数，离手后重新抽回可再次计数。“打出”只统计主动牌；自动重放另用既有自动结算指标统计。

### 4.3 正交矩阵

保留现有 2,400 场终局回归，不把它改成单变量实验。新增同种子控制矩阵，分别只改变：

1. 六种永久伙伴职业及其均衡出生种子。
2. 无套装和六套装。
3. 六名任务 NPC。
4. 六种地形。
5. 裸装、稀有中期、珍稀成型三个成长档。

每个切片使用相同敌人、章节、节点、路线等级和种子；输出单变量差值及 95% Wilson 区间。职业结果还按主流派拆分，禁止只看六职业总均值。

### 4.4 自动候选与写入边界

Python 调优器读取两个成功且哈希一致的 schema v3 观测，输出：

- 目标区间偏差。
- 逐卡出牌率、伤害/治疗/护甲贡献与资源浪费。
- 单变量 cohort 的胜率、回合数、剩余血量和极端种子。
- 建议改动类型、建议幅度和受影响测试，但不直接编辑 C++。

候选幅度默认限制：

- 单次攻击倍率：每轮最多 ±15 个百分点。
- 固定伤害/护甲/治疗/状态：每轮最多 ±2 或原值 ±15%，取更小绝对变化。
- 气力：每轮最多 ±1，且 0 费净资源牌必须单独复审。
- 内力：每轮最多 ±3。
- 敌方生命/攻击/防御：每一章节点每轮最多 ±10%，且不得恢复已退役的 850/540 攻击倍率。

每个候选进入生产前必须有一个同种子 A/B RED；实现后跑局部 GREEN 与邻接回归。一次迭代只改一个归因簇，不能同时改卡、套装、NPC 和敌人来追同一胜率。

## 5. 平衡目标与保护线

成长档目标继续采用当前全项目规格：

| 成长档 | 普通 | 精英 | Boss |
|---|---:|---:|---:|
| 初始/裸装 | 70%–85% | 35%–55% | 15%–35% |
| 稀有中期 | 80%–92% | 55%–70% | 35%–55% |
| 珍稀/成型 | 95%+ | 80%–95% | 60%–80% |

附加保护线：

- 所有场景必须终局，`Stalemate=0`、`MaxRounds=0`、`stranded_target_failures=0`。
- 同成长档六职业/六套装在同节点的胜率极差先收敛到 20 个百分点以内，再追求更细平衡。
- 任何职业不能在普通、精英、Boss 三类节点同时 0% 或同时 100%。
- 每个起始职业牌组至少能在战术谜题中完成一次自身循环；setup-only 牌实际出牌率不能因评分缺陷长期为 0。
- 不能以增加不可预告的首回合集火伤害来压低胜率。

## 6. 战斗动效时间轴

### 6.1 固定节奏档

| 阶段 | 时长 | 命中点 | 说明 |
|---|---:|---:|---|
| 出牌提交 | 0.18 s | — | 原手牌控件仅做 render transform：上提、轻微放大、淡出；不移动 slot |
| 首个普通伤害包 | 0.82 s | 0.30 s | 保留中央 Attack/Hit 可读特写，完整播放 atlas |
| 同次结算后续伤害包 | 0.30 s | 0.10 s | 快速连续；每个包仍独立更新血量和顺序 |
| 闪避包 | 0.45 s | 0.16 s | 显示“闪避”，无震屏 |
| 死亡 | 0.90 s | — | 完整播放死亡 atlas 后再移除 |
| 状态 HUD 脉冲 | 0.30 s | 即时 | 只脉冲受影响单位状态区，不占全屏队列 |

Atlas 播放率由 `FrameCount / (FPS × 本段时长)` 计算，让 60 帧素材在目标时长内完整播放；不得简单截掉后半帧。异步 atlas 晚到时仍从同一绝对时间轴追帧。

五段攻击的总伤害演出目标不超过 `0.82 + 4×0.30 = 2.02 s`，不含一次 0.18 秒出牌提交和必要的 0.90 秒死亡。

### 6.2 强弱反馈

根据 `HealthDamage / max(1, TargetHealthBefore)` 和致死状态解析展示档：

| 档位 | 条件 | 震屏 X/Y | 时长 | 数字峰值 |
|---|---|---:|---:|---:|
| 闪避 | `bAvoided` | 0 / 0 | 0 | 1.10 |
| 轻击 | 比例 < 10% | 3 / 1.5 | 0.12 s | 1.12 |
| 中击 | 10%–29% | 6 / 3 | 0.16 s | 1.20 |
| 重击 | 30%–59% | 9 / 4.5 | 0.20 s | 1.30 |
| 致命/60%+ | 致死或比例 ≥ 60% | 14 / 7 | 0.26 s | 1.42 |

伤害数字在命中点出现，先放大后回落并淡出；震屏使用既有全屏根节点，但只改变临时 render translation。演出结束必须严格归零。

### 6.3 出牌提交与队列

- 主动牌结算成功后立即锁交互，并对对应手牌按钮播放 0.18 秒提交；结算失败不播放。
- 有伤害队列时：提交结束后启动第一包；无伤害的治疗/状态/资源牌：提交结束后执行原 continuation 并刷新 HUD。
- 提交、伤害、死亡和 continuation 共用一个绝对时钟；取消 visual session、界面销毁或 atlas 失败都必须恢复按钮 transform/opacity，并且 continuation 至多执行一次。
- 自动重放没有独立手牌按钮，不播放提交；它产生的伤害仍进入原有有序伤害队列。
- 状态变化不为每层 DoT 插入全屏动画，避免高层流血/中毒/灼烧把战斗重新拖慢。

## 7. UI 与资产边界

- 不新增或移动页签，不改变手牌、血条、状态图标、敌方意图、角色槽位、锚点、尺寸或布局。
- 不覆盖角色 sprite、PaperZD、背景、相机或手调 HD2D 参数。
- 只修改运行时 render transform、opacity、播放率、时间轴和现有 HUD 局部强调。
- 现有 206×285 卡框、410×410 阵型角色、820×820 特写尺寸保持不变。

## 8. TDD 与验收

### 8.1 数值评估 RED/GREEN

1. 六职业代表谜题先 RED：抽牌/回气、护甲格挡、药效/药方、重箭蓄力、法术任务、阵师换场均能被策略选择。
2. schema v3 字段、逐卡计数、资源浪费、过量值和身份元数据先 RED。
3. 正交矩阵必须证明只变一个变量、同种子重复字节一致。
4. Python 解析、Wilson 区间、异常排序、候选幅度限制、两次哈希门禁先单测。
5. 每一项正式数值改动均有固定种子 A/B；不能只改断言以追现状。

### 8.2 动效 RED/GREEN

1. 纯节奏解析器锁定首击、后续、闪避、轻/中/重/致命档位和非法输入回退。
2. Board 测试锁定命中前后 HP、五段总时长、死亡顺序、晚到 atlas 追帧、每包恰好一次 impact/completion。
3. 出牌提交测试覆盖自动目标、手动目标、无伤害牌、失败结算、session 取消和 continuation 恰好一次。
4. 震屏与数字测试锁定闪避不震、强度分层、结束归零；现有布局尺寸与 slot 断言继续通过。
5. 真实 PIE 至少录制/截图：单击、多段、闪避、格挡/反击、DoT、状态获得、致死；人工确认没有闪烁、跳位、重复数字或长时间锁手。

## 9. 提交与迭代边界

1. `docs: plan balance and battle rhythm tuning`
2. `test: lock setup-aware simulation policy`

4. `feat: add orthogonal balance diagnostics`

6. `test: lock battle rhythm timing`
7. `feat: accelerate battle presentation rhythm`
8. `feat: add played-card commit feedback`
9. `test: certify tuned balance and battle rhythm`
10. `docs: publish tuned balance evidence`

每个提交前检查只包含目标文件；每个阶段推送 `main`，并在重大调值前新建可恢复标签。原始美术与生成目录继续保持未跟踪且不纳入提交。
