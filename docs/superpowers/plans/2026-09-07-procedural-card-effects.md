# 局内卡牌程序化动效与联动提示

用户要求：先Git备份，再补齐发牌/使用/奖励及职业与NPC联动动效。已将此前工作提交并推送为`aea5194cde166f844ed13dee953746c56ea45828`，远端`origin/codex/ui-visual-optimization`已核对；继续根工作区当前UI优化任务。

## 语义与视觉

- 药方：按OwnerUnitId+CardId查`HealerFormulas`，未开方绿光。周光祖/琼梅儿没有虚构的药方机制，其药效与治疗反转用实际效果提示。
- 法术任务：读取主角4牌、法师伙伴5牌、宋金宝/月白3牌的锁定组与已完成集合，未完成牌淡紫。已完成本回合的主角任务不再提示；不同所有者互不混算。
- 刀客：首张主动牌可触发冲锋时朱红；之后有收招的手牌为浅红候选。真正的收招以`LastActiveCard`为准提示结束回合；不能把未打出的牌称为已触发收招。
- 重箭：黄色，按规则读取消耗蓄力的真实角色（出牌者或最高攻击友方），并考虑NPC先给蓄力再消耗的规则。
- 护甲转伤：蓝色，只在伤害读取/消耗的真实来源有护甲时提示，不能给所有守卫牌无条件加灯。
- 地势：紫色，地势牌基础提示较轻；换地势分支、双效、免耗/减耗或山河减耗已就绪时增强。阵师回合开始自动收益在地势提示处脉冲；“阵赏”是法术任务重放奖励，不是阵师另一个积攒条。
- 呼吸使用低频、低透明度墨线和少量边缘光；可打性与机制提示分开，不能支付费用时减弱。多个联动保留理由，主要提示优先，次级颜色只作轻量标记。

## 实施

1. 读取真实PIE发牌/使用基线。现有出牌上提淡出仅0.18秒，保留其结算队列，增强弧线与墨迹收束。
2. 独立只读提示模型，以规则数据和战斗快照生成原因，不按中文牌名猜测，也不修改战斗数值。
3. 同一位置合成发牌滑入、手牌补位和悬停变换，避免两个tick互相覆盖；稳定InstanceId区分新牌，重复刷新不重播。
4. 奖励与选择牌渐次翻面，复用现有纸框和卡面；鼠标操作可提前完成展示，不改变奖励发放语义。
5. 补共享气力变化、地势触发、收招就绪等低干扰反馈。所有动画结束/取消/复用都恢复正确不透明度与变换。
6. 定向规则测试、时间插值/重入测试；MCP保存后冷UBT，不用Live Coding；默认2D地图验证职业/NPC条件和真实动效序列，恢复原档和设置。

不重做用户手调角色图集，不把展示动画写入存档，也不重新设计战斗规则。
