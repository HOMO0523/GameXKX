# GameXXK 桌面训练 HUD 角色入口与编队流程纠错计划

**目标：** 修复 `L_DesktopTrainingHUD` 中角色查看、编队写入和底部导航相互串线的问题；把主角、伙伴、NPC 三个真实头像入口固定到中栏内容区左下角，并让所有队伍变更只发生在独立编队页的显式操作中。

## 已确认问题

- `BuildCharacterRosterTabs()` 把三个入口放在参考坐标 `(424, 262)`，覆盖背包顶部页签和标题区。
- 三入口误用了通用星点页签底图，不能表达当前主角、当前伙伴和当前 NPC 的真实身份。
- `SelectBackpackCharacterForTest()` 在“查看背包角色”时调用 `SetActivePermanentCompanion()` / `SelectTownQuestNpcForParty()`，一次点击同时改变查看对象、战斗编队和游历队伍。
- 同一函数还强制把 `ActiveNav` 改成 `Formation`，造成中栏仍显示背包、底部却高亮编队。
- `BuildWorkbenchShell()` 没有独立编队页；底部编队按钮实际没有对应页面。
- 仓库、工具和历练按钮以开关方式反复关闭页面，导航高亮又按“页面是否打开”计算，因此可能同时高亮多个入口。

## 冻结交互矩阵

| 入口 | 允许改变的区域 | 不允许的副作用 |
|---|---|---|
| Tab / 打开背包 | 中栏切回角色背包 | 不改编队、不打开侧栏 |
| 主角 / 伙伴 / NPC | 角色类别和当前查看对象 | 不改永久伙伴、不改任务 NPC、不重置游历队伍 |
| 仓库 | 第一次打开并聚焦左栏，第二次关闭 | 不替换中栏；关闭时不保留假高亮 |
| 编队 | 中栏切到独立编队页 | 仅进入页面时不改队伍 |
| 天赋 | 中栏切到天赋页 | 不改队伍、不改右栏 |
| 工具 | 右栏显示工具页 | 不替换中栏 |
| 历练 | 右栏显示历练地图 | 不替换中栏、不以二次点击关闭 |
| 挑战 | 直接启动当前已解锁历练关卡并进入 Battle | 不检查青山镇任务、不隐式接任务、不先绕到城镇路线入口 |
| 编入队伍 | 当前编队候选写入对应伙伴/NPC 槽 | 不改变背包查看对象 |

## 布局与视觉

- 继续使用冻结的 `1672×941` 参考画布和统一等比缩放，不改六个结构矩形。
- 三个角色入口横排放在中栏内容矩形左下，底边不超过 `Y=777`，与 `Y=788` 开始的底部导航保留间距。
- 每个入口显示真实代表头像：主角固定主角；伙伴优先当前出战伙伴；NPC 优先当前任务支援。没有当前出战对象时显示该类别第一个合法对象，不使用猜测图标。
- 用户明确否决 `T_MasterV2_ButtonNeutral` 这类星点长条底；桌面 HUD 不再引用该底及同族 Primary/Danger、通用 `T_MasterV2_TabNormal/Selected` 代用品。
- 按钮状态只复用现有“属性 / 装备（背包） / 卡组”使用的正确资源对：未选中 `003_tab_1`、选中 `004_tab_2`；标签继续由运行时文字绘制。
- 伙伴/NPC 六人列表作为临时选择层从三个入口上方向上展开，点击成员只切换背包查看对象。
- 独立编队页展示主角固定槽、当前永久伙伴槽、当前任务 NPC 槽，以及候选列表和明确的“编入队伍”按钮。

## 验收条件

1. 三入口均位于内容区左下，且不与顶部页签、底部导航或排序按钮重叠。
2. 三入口和成员项均使用项目内真实角色 portrait，并只用 `003_tab_1` / `004_tab_2` 表达未选中/选中；本任务不生成、不替换角色美术资产。
3. 查看任意伙伴/NPC 后，`ActivePermanentCompanionInstanceId`、`ActiveTemporaryQuestNpcId` 和正在运行的 Travel 队伍保持不变。
4. 点击底部编队后，中栏存在独立 `FormationPanel`，背包页不再冒充编队页。
5. 只有显式“编入队伍”成功后，对应权威队伍槽和 Travel 投影才更新。
6. 底部五入口同时最多一个高亮，且每个入口只影响交互矩阵规定的区域。
7. 未接青山镇任务时挑战按钮仍可用，点击后直接进入 `Battle`，且任务状态保持不变。
8. 不修改或保存 `L_Main.umap`、角色 Sprite、PaperZD、放置关卡、镜头或 HD2D Plane。
