# 角色详细属性与75%边际计算

用户已批准本次在根项目的 `codex/ui-visual-optimization` 分支实现。保留工作区既有修改，不创建 worktree。

## 目标

- 在背包的“属性”页增加“详细属性”按钮，显示当前查看角色的非基础属性，并提供返回基础属性入口。
- 角色切换、装备变化和永久天赋变化后，详细数据跟随当前角色刷新。使用现有纸面、字体和滚动样式。
- 分系百分比采用已确认模型：原始加成先乘0.5，名义合计S经 `E=75S/(75+S)` 折算；固定套装来源独立计算，最后按原结算规则取整。
- 展示真实有效值。当前无战斗消费者的词缀明确显示未生效，不把理论值伪装成实际加成。条件型套装效果写明条件。
- 本次不擅自定义其余29条词缀的触发，不改变分解、工具经验或装备基础属性预算。
- 用户纠正宝石边际含义并选定范围：普通到不朽的攻击/防御保持 `1、2、4、8、16`；不朽之后升级倍率从×2均匀降到×1.25，依次为 `2、1.8125、1.625、1.4375、1.25`，逐阶向上取整后采用 `32、58、95、137、172`。生命沿用批准总表的攻防值5倍。多颗宝石正常相加。此前按颗数降权、每阶新增点数递减及×1.95到×1.75的方案均撤回。先更新总表及受影响的至宝设计配装，再修改项目品质表。

## 实现顺序

1. 先加真实属性页按钮缺失的回归检查，冷编译后确认预期失败。
2. 提取共享的分系百分比边际计算与产甲结算，保留原始存档词缀值；接入已存在的产甲消费者。
3. 建立角色详细属性读模型，合并永久天赋、当前角色装备和有效套装数据。暴击伤害显示最终倍率（基础150%加天赋），产甲显示递减后词缀与固定套装的合计。
   宝石的品质数值在统一宝石规则中计算，基础属性、换装比较与详细页共用正常累加结果；不改写旧档中的宝石类型和品质。
4. 在 `UGameXXKInventoryWindowWidget` 内添加入口、返回按钮与详细列表；尽量不改动承载主线等既有修改的外层工作台。
5. 完成计算边界、真实产甲、13名角色、按钮返回、刷新和会话恢复的定向检查；更新总表的实际实现状态。
