# 局内整体问题清单与修复顺序

## 1. 本轮范围和结论

本轮围绕桌面挂机游戏的完整主动挑战流程，交叉阅读批准设计、当前代码、实时 PIE 和现有自动化。用户要求优先重做商店、事件与**击败本关 Boss 后的整关结算**，同时梳理和修正不符合设计的局内行为。

当前范围需要先处理规则与流程缺口，再统一视觉。普通战后三选一与关底整关结算是不同的界面和事务；此前把三选一当作结算稿的设计已撤回。

本次没有修改游戏 C++、关卡或美术资产，没有运行新代码构建，也没有宣称修复完成。当前分支 `codex/ui-visual-optimization` 是用户本任务明确授权创建的分支，既有未提交修改保持。

## 2. 玩法流程基线

```text
桌面挂机 / 背包 / 角色成长 / 固定三人编队
  → 选择关卡并挑战
  → 分支路线
      普通或精英战 → 普通战后奖励 → 路线
      事件、宝匣、篝火 → 明确选择 → 路线
      商店 → 购买 / 强化 / 刷新 → 明确离开 → 路线
  → 本关 Boss 胜利
      当前：发奖并清算 → 直接回桌面
      批准目标：唯一通关凭据 + 原子发奖 → 整关结算 → 确认 → 桌面挂机
```

- 默认表面为 `/Game/GameXXK/Maps/L_DesktopTrainingHUD`，主动挑战使用已有路线图与全屏 BattleBoard。
- 队伍为主角、一名永久伙伴、一名永久 NPC；事件和结算不能替换或清空队员。
- 自动战斗只代替战斗出牌，不代选路线、事件、奖励或结算确认。
- 当前单关 Boss 不发 Boss 卡三选一；整关结算确认只完成展示/导航，不再次发奖。
- 普通金币与行旅钱分开；当前商店四强化＋四遗物使用普通金币。

更详细的设计/源码核对保存在 `Saved/Codex/RouteUI-20260906/project-flow-review.md`。

### 药品实际来源已经区分

用户在“前往篝火休息”的流程附近观察到药品增加。本次逐步计数结果：

| 步骤 | 药品数 | 其他观察 |
|---|---:|---|
| 开始挑战 / 进入战斗 | 0 | 任务未接受，仍在纯2D地图 |
| 战斗胜利，普通奖励出现 | 0 | 尚未确认奖励 |
| 领取一个遗物奖励，返回路线 | **1** | 已持有江心珠，遗物栏对象为空 |
| 进入篝火 | 1 | 测试入口将主角气血设为33/100 |
| 点击当前休息操作 | 1 | 主角恢复到63/100，没有额外发药 |
| 进入下一场战斗 | 1 | 遗物仍持有，遗物栏仍未创建 |

因此不能只改篝火按钮或奖励文案。直接问题在 `GameXXKMVPRules.cpp` 普通战/精英战奖励收尾中的遗留 `AddItem`；新回归应覆盖“战斗 → 奖励确认 → 路线 → 篝火”的链路。

### 遗物栏的具体缺口

`UGameXXKRelicBarWidget` 已有六列换行、图标、叠层数和Tooltip实现；完整玩家流程会创建它。但当前桌面启动使用按需创建，路线、事件、商店和战斗的提升分支只创建对应主界面，漏了 `EnsureRelicBarWidget()`；刷新代码只在对象已经存在时更新。

修复后还需实机检查多行遗物与自动战斗/关闭按钮的占位，不能仅让一个图标出现便认定整体完成。

## 6. 已运行的测试与盲区

当前编译产物上，通过 UE MCP 运行34项相邻检查：

- Camp 7项；
- Relic UI 2项；
- Merchant Widget 7项；
- RouteEncounter Panel 16项；
- CardRoute RewardGate/RewardChoice 2项。

结果：**32通过，2失败，0跳过；4条错误、96条警告保留在原报告。**

失败项：

1. `GameXXK.MVP.RouteEncounter.Panel.DesktopTrainingContextDelegates`
2. `GameXXK.MVP.RouteEncounter.Panel.VisibleChoicesResolveOnlyOnClick`

两项均因旧护符期望与实际33→63治疗结果冲突，不能将其伪装为全绿，也不能不核对规范就通过改断言掩盖问题。

本轮特别确认两个覆盖盲区：

- Camp自身“不发药”的测试通过，但普通战奖励收尾的发药没有被这些测试检查；
- RelicBar独立构建的两个测试通过，但桌面按需进入战斗没有创建RelicBar，集成断言缺失。

尚需补充的回归：完整节点转换、已持有/新获得/多行/消耗遗物、金币不足与库存耗尽、事件重开选项稳定、Boss各阶段终局、结算未确认时退出读档、重复确认只发一次、50/75/100%与不同viewport。此清单不是一次全项目、全角色、全存档覆盖认证。

## 7. 修复顺序与验收条件

### 第一批：已复现的行为回归

1. 为战后遗留发药和桌面遗物栏缺失补真实入口回归，先确认RED。
2. 修复奖励收尾和遗物栏按需接入，保留正常经验/金币/遗物/品质收益。
3. 核对篝火规范，清理不适用的旧测试与退役事件测试入口。
4. 冷UBT、相邻回归、真实PIE重走“战斗 → 奖励 → 篝火 → 下一场战斗”。

### 第二批：Boss整关结算功能基础

1. 对齐当前存档/奖励/成长依赖。
2. 唯一通关凭据与原子提交；保留首次通关、解锁、实际奖励和成员经验变化。
3. 专门结算页、输入隔离、单一确认返回。
4. 未确认时重启/读档恢复同一凭据，重复确认不发第二次；不出现普通三选一。

### 第三批：统一视觉

商店、环境事件/宝匣/篝火、Boss整关结算使用同一纸面和文字规范。随后统一普通奖励、卡牌、战斗信息与遗物栏的阅读层级。以实时截图做改前/改后，保持用户调好的角色、地图、镜头和桌面停靠。

功能的验收以真实玩家入口和数据变化为准；界面的验收以实际渲染、长文字、缩放和操作反馈为准，两者不能互相替代。
