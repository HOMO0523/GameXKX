# 引导接入完成度核对

本次为代码与已有实测证据核对，没有重新完整游玩或修改游戏行为。

## 结论

局外开箱与工具入门已接通；完整的新档渐进学习链尚未达到验收条件。应分别记录内容存在、自然触发、操作完成、连续体验验证，不能以某批自动化通过数代表全流程完成率。

现有总计划列出100个短段；代码另有23步手动界面操作总览，以及13门、26节学院课程。它们粒度不同、存在重叠，不能相加换算百分比。

## 本次发现的具体接入问题

1. **偏好阻断伙伴/主线短课。** `OfferPartyProgressionGuide` 要求 `Preference == NewPlayer`。新档默认 `Unset`，真实卡住的首Boss快照也为 `Unset`。偏好弹窗默认隐藏，`RefreshFromProgress` 不会主动打开；原生代码中没有调用 `PresentPrompt` 的路径。现有相关测试直接把偏好设成 `NewPlayer`，因此不能证明默认新档能自然触发。
2. **正式挑战仍受旧任务条件限制。** `HandleGuideEvent` 除了检查NewPlayer，还要求当前任务正处于 `Step.Main.XuXiake.CombatTutorial`。新主线在1-3开放，首次普通1-1无法依赖这条旧任务链。真实首Boss快照的TrackedTaskId为None。
3. **F10重置的会话去重未清理。** `OfferedPartyProgressionGuides` 在展示时添加，未找到清空调用；`ResetPresentationForNewGame` 复位首箱与旧窗口，但没有清理这个集合。同一进程先看过伙伴/主线提示再重置，存在不再自动提示的风险。本次为代码发现，尚未另跑实机复现。
4. **学习证据模型未完全统一。** 目前有完成步骤、教学箱阶段、合成自动填入/实际合成区分、学院完成与奖励记录；计划中的“已介绍/成功操作/无提示独立再用”还没有覆盖所有系统。
5. **计划含旧开场段落。** 总计划部分A段仍写装备后出发，与现行开局即游历的决定不一致，不能直接按旧文字继续施工。

## 已有证据的边界

- 六箱、固定配套资源、批开优先顺序、满包、关闭、保存恢复等有定向验证与分段实机证据。
- 伙伴/NPC里程碑早期实机验证使用过Dev进度快照；短链测试通过不等于从新档自然打到1-3的全过程验收。
- 最近修复了真实单主角Boss结算、1-2解锁、商店返回的状态/视觉问题；这是业务链修复，不代表对应教学已自动触发。
- 尚缺无Dev推进的一条完整新档：1-1 → 伙伴入队及实际用牌 → 1-2 → 主线 → 月白入队及实际用牌 → 收获进入构筑。

## 优先顺序建议

1. 先修默认触发条件、提示偏好的职责和重置去重；用真正默认新档验证，不预设NewPlayer来绕过条件。
2. 把首次正式挑战接上独立于旧主线的短课：挑战入口、节点、选牌/目标、资源、意图、结束回合、奖励、结算、下一步。
3. 补伙伴和月白第一次实际发挥作用，每次一张牌、一种机制。
4. 接首次自主构筑：任务资源→开箱→比较/选择→两件套或一次配卡→实战反馈；保留关闭与自主选择。
5. 再按实际需要派发仓库、宝石合成、离线、职业课程、高难和讨伐。
