# 《江湖行》卡牌、伙伴与 PSD 界面全套优化目标

## 1. 交付目标

在不破坏现有主线、存档兼容性、手调关卡、角色资源、镜头和 HD2D 参数的前提下，把现有可玩竖切从“固定动作的战斗原型”升级为一条可实际游玩的卡牌冒险闭环：

`主菜单 → 世界地图 → 城镇 → 接任务/管理伙伴 → 路线地图 → 事件或战斗 → 三选一卡牌奖励 → 继续路线或返回城镇`。

所有新界面只能使用已批准的 PSD 切图或由其定义的版式、颜色和纸墨语言；不以临时 CSS 风格、通用占位框或重新绘制的界面替代 PSD 资产。

## 2. 不可变玩法约束

| 项目 | 锁定规则 |
| --- | --- |
| 战斗队伍 | 最多三人：1 名主角 + 最多 1 名永久招募伙伴 + 最多 1 名本次路线的任务 NPC。`bFollowerJoined` 只保留叙事/路线门槛，绝不成为第四名战斗单位。 |
| 永久伙伴 | 随机招募后写入存档，伙伴背包上限 12；可持续升级、升星、设为当前出战伙伴。 |
| 任务 NPC | 土司首领、宋金宝、月白、周光祖、金贵、琼么儿仅在本次路线临时支援；不获得 XP、星级或永久装备。牛欢是事件 NPC，不是可招募伙伴。 |
| 敌人 | 黑熊为精英，老虎为 Boss；两者均进入现有战斗和奖励规则。 |
| 卡牌池 | 共 174 张定义：主角 12、六职业伙伴 108、任务 NPC 24、路线奖励 30；不得用卡牌 ID 分支实现效果。 |
| 牌组 | 主角从 12 张个人牌中选 8；每名永久伙伴按生成种子拥有不同的 12 张个人牌，从中选 5；任务 NPC 从固定 4 张中带 3；战斗起始牌组 18 张。 |
| 路线牌 | 胜利后三选一可加入临时路线牌；路线总牌组上限 30，满时只能替换一张临时路线牌，不能替换主角/伙伴/NPC 固有牌。 |
| 战斗交互 | 手动目标牌必须先执行非破坏性 `CardCheck`；只高亮合法稳定 UnitId；箭头从出牌者角色跟随鼠标；点击合法目标后再复核并提交。点击空处/非法目标不取消，Esc 或右键取消。 |
| 目标类型 | 完整覆盖无目标、自身、单敌、单友、其他友方、全敌、全友、全体其他友方、随机敌、最低血友方、最低血其他友方、任意存活单位。 |

## 3. 界面与美术目标

### 3.1 PSD 界面契约

- 卡牌框固定使用第一排切图 `057.png`，原尺寸 `452×516`，运行时比例 `113×129`；`060–062` 禁止使用。
- 卡框本体保持原始淡黄纸墨，**不得按阵营染色**。
- 色彩只出现在底部信息条：主角为淡黄白纸色；六个伙伴职业各用锁定职业色；任务 NPC 为黑/浅灰；路线牌保持中性纸墨。
- 右侧长列表统一使用纸色轨道和墨色滑块的可见滚动条；伙伴背包、奖励替换列表、图鉴/相关长列表均不得隐藏滚动状态。
- 新界面优先使用已导入的背包窗框、槽位、操作空白、卡框、滚动条资产；不得以纯色圆角矩形冒充已存在的 PSD 框体。

### 3.2 卡面素材

- 主角和六名任务 NPC 的卡面使用各自原画来源。
- 六职业永久伙伴使用统一职业形象制作卡面，不按随机姓名临时生造不同画风。
- 所有卡牌都显示角色/路线牌的正确拥有者，并由数据定义，而非写死单张卡名。

### 3.3 八方向角色资源

- 主角现有资源只读，不覆盖。
- 六职业伙伴与六名任务 NPC 各提供 `S / SW / W / NW / N / NE / E / SE` 八方向 Idle/Walk 资源。
- 每个对象资产隔离在 PartyDeck 路径，包含完整 South Idle 默认项；不替换任何原有关卡角色蓝图、PaperZD 资源或手调 Sprite。

## 4. 功能验收清单

### A. 卡牌战斗

1. 174 张目录可检索、按来源计数正确，所有效果由 `TargetSpec + Effect` 数据驱动。
2. 对无目标、自身、群体和自动选择目标的卡，点击立即合法结算；对手动目标牌，点击卡后进入高亮+箭头态。
3. 旧的固定动作菜单在 `bHasActiveCardBattle` 时不再作为玩家出招入口；只保留抽牌、出牌、结束回合。
4. 出牌、结束回合、敌人回合、胜利、失败、奖励/返回路线状态连续正确。
5. 路线奖励三选一在达到 30 张时显示可滚动的临时路线牌替换列表；选择、跳过和替换都不会误删固有牌。

### B. 伙伴与任务 NPC

1. 城镇内可打开“伙伴背包”，显示最多 12 个永久伙伴、职业、属性、等级、星级、个人 12 张牌及选中的 5 张出战牌。
2. 界面可设定唯一出战永久伙伴；主角可在城镇将个人 12 张牌编辑为 8 张出战牌，任务 NPC 的 3 张固定出战牌仅以锁定/只读摘要展示；非城镇或规则锁定时禁止写入。
3. 随机招募具有确定性种子和不同卡池结果；存档重载后伙伴、牌组、等级、星级、当前出战选择保持一致。
4. 任务 NPC 出现、加入、离队和路线结束清理正确；不会残留为永久伙伴。

### C. 路线、事件与奖励

1. 城镇北门/城镇入口可进入路线图；路线节点按现有可达规则推进。
2. 事件 NPC（牛欢）、任务支援 NPC、普通怪、精英黑熊、Boss 老虎使用正确角色与奖励逻辑。
3. 事件、营地、商人、宝箱、战斗、Boss 均能从节点进入场景并回到路线图；战斗胜利必须先处理奖励，再完成节点。

### D. 表现与资源

1. 卡面、伙伴背包、奖励替换和可滚动面板均可见且资源路径正确；PSD 卡框不被染色。
2. 12 套八方向角色资产可在内容浏览器中加载，每套均含 56 Sprite 和 16 Flipbook（8 方向 Idle/Walk），总 864 个隔离资源。
3. 主流程可视界面没有替代旧游戏的临时文本按钮或裸框；未触碰用户已手调的地图、镜头、主角和 PaperZD 资产。

## 5. 执行顺序与完成定义

1. 先完成数据、存档和无 UI 的自动化规则；随后接入卡牌面板、箭头与奖励替换 UI。
2. 再接入伙伴背包和城镇入口，最后接通事件/路线/战斗展示与八方向映射。
3. 每批素材导入必须有来源清单、静态契约测试和 UE 命令行导入结果。
4. 源码冻结后进行一次**冷编译**（不使用 Live Coding/Hot Reload）、聚焦自动化测试、再进行 PIE 主流程验证。
5. 只有在上述自动化和真实流程均通过、且没有覆盖用户手调资产时，才标记本目标完成。

## 6. 本轮明确排除项

- 不重做或覆盖现有主角原画、角色 Sprite、PaperZD、关卡布置、镜头和 HD2D 平面参数。
- 不将任务 NPC 纳入永久招募、升级、升星或装备系统。
- 不为“看起来完整”而伪造不可交互的 UI；每个新增入口必须有底层状态与验证。
- 不在未完成冷编译和 PIE 验证前宣称已交付。
