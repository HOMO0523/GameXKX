## 4. 内存审计（2026-08-14，磁盘级，不启动引擎）

> 方法约束（用户裁决 2026-08-14）：**禁止在编辑器里批量加载纹理做内存审计**——该做法在 16 GB 机器上两次 OOM 崩溃编辑器（页面文件太小）。后续一律用磁盘级只读扫描 + 正常引擎流程。

### 4.1 贴图类资产磁盘占用（Content/GameXXK）

| 目录 | 数量 | 磁盘占用 |
|---|---:|---:|
| BattleAnimations（战斗动画图集） | 138 | **1,061.3 MB** |
| UI（战斗/城镇界面切图） | 356 | 94.5 MB |
| Characters / Sprites / Environment / SourceArt | 41 | 22.9 MB |

### 4.2 结论

- 战斗动画图集是绝对大头：138 张 4096² BC7 无 mip 图集（每张进显存 ≈16.8 MB），全量常驻最坏 ≈2.3 GB；运行时由 `BattleAtlasCache` 256 MB 预算限制为“当前战斗所需”。
- 磁盘侧最大单文件 ~13.8 MB（图集 uasset），前 12 大全部是动画图集。
- UI 切图合计 ~95 MB 磁盘，属第二梯队。

### 4.3 优化执行方式（修订后，用户裁决 2026-08-14）

1. **图集降档采用"母本不动 + 兄弟资产"架构**：
   - 138 张 4K 母本（`T_<角色>_<动作>_atlas`）**保持不动**，作为真实原素材；
   - 生产显示走 **138 张 `_2k` 兄弟资产**（`T_<角色>_2k_<动作>_atlas`，2048² BC7，含 34 张 2K 待机翻页书+2040 精灵）；
   - 保留 2 张 `_1k` 兄弟（英雄/公鸡待机）供未来小窗放置模式使用，全量 1K 可由 `gamexxk_prepare_animation_2k.py` 随时再生成；
   - 解析层约定：单位 id 默认解析 `_2k` 兄弟；`.4K` 回母本；`.1K` 取 1K 兄弟（`ResolveUnitAssetId`，生产 id 无 token 即 2K）。
2. `r.Streaming.PoolSize` 收紧：项目当前未覆盖该值（引擎默认约 1 GB）；图集为无 mip 永不流送，收紧只影响城镇/UI 纹理。提案 `768`，待城镇视觉验收后写入 `DefaultEngine.ini`。
3. 编辑器重启时不再附加 `-DDC-ForceMemoryCache`（自动化专用参数）。
