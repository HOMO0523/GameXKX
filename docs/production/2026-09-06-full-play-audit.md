# 整体试玩与优化建议（2026-09-06）

本记录使用当前 `codex/ui-visual-optimization` 工作区与真实 UE 5.8 PIE。先前商店、事件、结算改版验收见 `2026-09-06-in-run-ui-settlement-acceptance.md`。本次追加试玩的素材与状态记录在 `Saved/Codex/FullPlayAudit-20260906/`。

## 已实际走过的路径

- 默认桌面启动、持续挂机、折叠/展开、背包展开、50%/100%查看。
- 主角/伙伴切换；实际查看守卫并装备武器，装备归属为守卫，出战仍为刀客。
- 开启普通与高级宝箱；仓库、编队、天赋、工具、历练地图各页。
- 实际购买根天赋：金币11050→8550，`Talent.Root=1`。工具页显示锁定说明；另以接口探针尝试自动放入与确认，记录了两个不同的错误提示，这不代表界面允许绕过锁定遮罩。
- 主角卡组页，真实鼠标取消一张卡变为7/8；切到守卫再返回主角，草稿回到8/8，正式牌组始终未变化。
- 配齐六件初始装备，进入普通1-2；实际点击青锋一式再选黄鼬，气血96→82。开启界面自动战斗，首场获得胜利，主角最终47/137，另外两人存活。
- 随后按真实规则逐步推进 `1→3→7→10→14→17`，经历奖励、山泉、篝火与Boss。首次通关1-2，金币+65（含17行旅钱折算）、每位成员经验+28、高级宝箱1，NPC升至2级，解锁普通1-3。截图 `stage-1-2-result.png`。
- “剧情任务”入口实际进入3D青山村马车预览，挂机条继续叠在对白上。复读当前验收入口后确认：这是2026-08-31批准的独立剧情预览，不能列作默认2D主链误入3D。记录后立即结束该PIE并返回默认2D地图，没有修改3D场景。

以上不是27关全难度胜率测试；不据单次战斗改卡牌或怪物数值。

## 优先级建议

| 优先级 | 发现 | 证据与建议 |
|---|---|---|
| P0 | 装备变化与游历队伍快照不同步 | 六件装备逐件穿上后，角色最大气血100→137，游历队伍仍是88/100。装备过程中永久气血还从100降到92，而取样中的游历气血仍88，存在旧快照回写。统一遭遇快照的属性版本与生效边界，别只强制画满血条。证据 `starter-equipment-and-challenge.json`。 |
| P0 | 波次图标与新编制不一致 | 实际序列已为普通×4、精英×2、Boss；进度条还硬编码旧的普通、普通、精英、普通、精英、普通、Boss。第3、6波错标。图标和标签应直接读取当前遭遇定义。 |
| P1 | 刷新显示需要更严谨的渲染回归 | 对象中的波次/箱数变化，Slate文字与局部实拍曾停在旧值。首轮100样本未开启深度Observe，不能直接使用其36次差异作为游戏故障计数；开启后又截到对象7/7与数字控件4/7，需要继续对照当前显示树与持有控件。最终验收应比对实际画面，不能只测UTextBlock内容。 |
| P1 | 后台时钟与动画观感混在一起 | 该编辑器场景取样约3.06次UI tick/秒；另一次9秒墙钟只推进了3个Walking逻辑步。应分别测试前台、后台和独立运行的时钟，确保挂机收益/冷却按真实时间推进，动画低频不能拖慢规则时间。 |
| P1 | 铁羽山鸡缺失攻击图集 | 当前 `/BattleAnimations/Atlases/T_enemy_05_ironfeather_1k_attack_atlas` 未加载成功，Idle正常。请求失败时旧画面可能保留，但代码仍用Attack的alpha高度换算缩放；Idle与Attack缩放约1.157/1.597，存在突然变大的明确原因。优先补齐合法回退，并按实际显示的clip决定尺寸。 |
| P1 | 动画不应继续统一硬编码60帧 | 当前普通clip都是60帧，0.28秒攻击被压成约214帧/秒的采样；实际屏幕不能展示全部。主角拳击60帧只有38个不同帧。建议按动作挑选有效姿态、保留出手与命中时机，用每段时长描述停顿，不靠重复图片维持时长。 |
| P1 | 循环首尾“相同”不等于连续 | 行走60帧只有49个不同帧；脚本将首末帧替换成参考图。58→59的像素变化约为通常相邻变化的2.62倍；主角Idle的末→首变化约为中位相邻变化的5.53倍。应选自然闭合周期、固定主体锚点，再检查尾部数帧与首部数帧，而非只比较首尾哈希。 |
| P1 | 清晰度标准不同 | 当前行走图集为Nearest/EditorIcon，战斗图集为Bilinear/BC7；部分旧伙伴图集的导入来源仍指向工程外旧路径。统一适合水墨插画的采样和alpha边缘标准，并以50/75/100%实际显示像素验证。资源证据 `atlases/runtime-assets.json`、`frame-metrics.json`。 |
| P1 | 背包选人区挤压且切人丢草稿 | 105×62的小候选按钮覆盖立绘和装备槽；真实切人丢失未应用7/8草稿。按用户已明确的文本入口、居中、每页6张大卡方案实施；同次背包会话按角色保留草稿，点击应用才提交。 |
| P1 | 纸底与文字层级不统一 | 背包底边被裁直，其他纸底角更粗。代码部分已是Box，但参考尺寸和嵌入缩放不同；需要统一切片与呈现基准。天赋/历练等页面还有浅底黄白标题、提示贴边、按钮“升级”竖向换行的问题。 |
| P2 | 剧情预览的入口文案与HUD避让 | 现有“剧情任务”进入已批准的独立3D马车预览，不是主链路由错误。实拍挂机条叠在对白上；建议把入口明确标成剧情预览，并另行确认预览期间的HUD避让规则。证据 `story-screen.png`。 |
| P2 | 100%缩放后的整组垂直适配 | 当前保存位置下从较小HUD切到100%，1920×1020桌面实拍中导航和侧栏底部超出屏幕；50/75%完整可见。建议缩放完成后按整组展开范围重新夹取屏幕边界。此项与纸底自身的裁剪不同，本轮没有改拖动与停靠坐标。 |
| P2 | 操作准备与限制反馈较晚 | 工具已有锁定说明，建议补充直接定位“百工开物”天赋的入口；接口探针返回的锁定/空输入错误不计作可见按钮的交互故障。关卡节点应直接显示等级及准备信息，减少靠Tooltip猜测。 |
| P2 | 战斗信息仍挤在人物图上 | 名字/资源条压住立绘，顶部敌意图小字与图片重叠，普通战后奖励叠在战斗内容上。建议按稳定信息带整理，保留本轮已完成的独立Boss整关结算。 |

## 动画方案起点（待视觉试排）

- 行走以8～12个连续关键姿态试排；待机4～8个；攻击6～10个，明确蓄力、命中、收势。具体帧数以动作可读性决定，不机械统一。
- 在相同1K图集预算下，较少格子可以提高单帧有效像素；保留cell间距和透明边缘，不直接压缩原图。
- 使用稳定脚底/身体锚点与统一的角色尺寸参考，允许不同物种有合理体型差异。缩放依据实际加载资产，不依据一个未加载成功的预期动作。
- 对比前台/后台刷新与动作播放，避免将编辑器后台限帧误认为所有问题都来自素材。

## 背包要求已实施并验收

以下5项已完成，真实鼠标验证卡组7/8草稿切人往返后保持7/8。冷UBT和最终聚焦10/10通过，详见 [背包验收](2026-09-06-backpack-picker-paper-acceptance.md)。上表的背包拥挤、底部裁剪与切人草稿问题为改版前记录；其余挂机数据、动画和整组适配建议仍待后续处理。

1. 只去掉背包纸底底部裁剪，内部物品/卡组滚动区域继续正常裁剪。
2. 主角、伙伴、NPC切换入口使用文本，居中放在角色立绘下方。
3. 伙伴/NPC选择用完整背包区域，一页6张大卡；名称在上、等级在左、立绘在右下。明确查看与出战的区别。
4. 仓库、历练地图及同类纸底按统一四角固定、边和中间延展的方式呈现，不放大成粗角。
5. 点击候选后返回对应角色背包；取消保留原查看对象，切人不改出战队伍，并改进卡组草稿的保留。

其余数据、动画和剧情建议保留为后续修复范围。本次没有覆写用户手调Sprite、PaperZD、相机或HD2D资产。相关已有自动化证据沿用有效的核心96/96；扩展旧测试失配仍见 `2026-09-06-ui-extended-regression.md`。
