# 存档加固第一阶段与 Steam 素材

## 本轮范围

- 新存档使用标准 UE GVAS 主体加原始字节校验尾部；标准 UE 读取仍可读游戏数据，项目存储层先检查完整尾部再解析。
- 档案 ID、归属槽位、提交序号、UTC 时间位于尾部，避免往旧 UObject 里添加字段而改变旧校验布局。
- IntegritySchema 0/1 仍兼容读取；新写入使用 schema 2。存档版本 v41→v42，使旧 v41 程序走未来版本拒绝路径，避免误当成损坏后回退旧备份。
- 继续使用临时写入、刷新、回读校验、Windows 替换与三份备份。
- 普通档与恢复点依据归属、档案身份及提交顺序选择。已建立明确档案身份后，不再接受无身份旧检查点覆盖主档。两个旧格式档案才用所选文件的时间做兼容比较。
- 默认保存跟随当前已读取/保存的槽位；周期检查为30秒，有变化才写，失败在后续周期重试。教学、F10临时会话及非游戏世界受写保护。
- 正常退出既有保存门保持，增加正常生命周期退出的尽力保存；不宣称断电或强杀进程时还能执行保存代码。
