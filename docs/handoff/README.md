## 给接手同事的阅读顺序

1. **[程序交接：整体框架、架构与表现逻辑](01-programmer-architecture.md)**：先理解系统边界、状态归属、一次操作如何结算和显示，再按源码导航进入模块。
2. **[玩法策划：核心循环、构筑与渐进引导](02-gameplay-design.md)**：解释玩家为何继续玩、各系统为何存在、如何逐步加入复杂度。
3. **[未完成事项与实施顺序](03-backlog-and-acceptance.md)**：完整保留本次用户列出的缺口，并给出依赖、交付物和验收方式。

程序案是整体逻辑交接，不是需求表；策划案讲玩法意图；待办表负责说明接下来做什么。三份一起构成当前交接基线。

## 状态口径

| 标记 | 含义 |
|---|---|
| 当前实现 | 本轮通过源码或近期验收记录核对到的行为，不等于本轮重新运行验证 |
| 已确认目标／待做 | 用户已经要求，但没有完成该体验的验收；即使有底层代码，也不能写成完成 |
| 建议方案 | 为便于接手提出的设计与拆分方式，需要在实施时定案 |
| 待定参数 | 不能从现有决定推出的数值、作用范围或规则，不自行填成既定事实 |

冲突处理：用户最新明确决定优先；当前规则及证据查 [current-goal-acceptance](../production/current-goal-acceptance.md)。历史文档用于追溯。本交接包归并至本日，未来变更需同步对应章节和待办状态。

## 必须先知道的变化

- 产品默认入口是纯 2D 桌面游历界面；旧 3D 城镇不是默认主线。
- 游历和局内挑战是两套运行流程。挑战期间暂停游历；普通开箱、工具教学不暂停游历。
- 新档只有主角。1-1 已算挑战通关，1-2 开局可挑战，挑战通关前不能游历 1-2。
- 首次实际战斗可能发生在 1-2；不能把初始化的 1-1 通关记录当成战斗教学完成。
- 现有升品质机制与待做的技能点升级卡牌系统必须分开解释。
- 奖励图标及领取飞行动效已获用户验收；其余引导、设置、图鉴等不能因此整体标为完成。
